## 1. 背景与问题

当前合成路线工作台同时堆叠了路线卡片、实验条件表格、字段级 Evidence、可行性指标、阻断项、验证建议和实验计划，页面纵向过长、视觉层级分散。化学结构缩略图依赖 Ketcher 隐藏 iframe 串行渲染，真机出现长期停留在“渲染中”的问题。实验计划、精读报告和 PPT 的生成入口也未形成统一的“请求 Agent—等待登记—保存本地”闭环。

本版本把工作台收敛为三个从上到下的横版组件，以结构图和原文截图为主要视觉内容，以文字为辅助；同时补齐化合物双源确认、人工核验门禁、路线人工创建与锁定、产物生成按钮状态机，以及核磁和绘图登记信息。

## 2. 产品目标

1. 用户进入合成路线工作台后，优先看到完整路线结构图，并能通过点击路线中的反应步骤联动查看细节和证据。
2. 单步信息以“反应物 → 条件与注意事项 → 产物”的横向反应式表达，化合物结构、名称和 CAS 号同步展示。
3. 用户必须以原文/SI 截图核对 AI 提取结果；完成本轮全部人工审核后，才允许 Agent 批量更新未确定内容。
4. 实验计划、精读报告和 PPT 采用一致的两次点击请求与生成后本地保存逻辑。
5. 用户可以直接新建路线和逐步录入条件；Agent 只能直接修改未锁定的路线版本。
6. 核磁与绘图登记面板补齐实验追溯所需的最小元数据。

## 3. 非目标

- 本版本不自动执行实验，也不把 Agent 推断写成已确认事实。
- 本版本不接入需要未授权账号或许可的数据源。
- 本版本不实现完整的内嵌可视化结构编辑器；仅修复现有 Ketcher 渲染链路，并为后续编辑器预留接口。
- 本版本不建设复杂的路线自动布局引擎。路线视图采用可预测的横向/折行布局；分子和反应结构由 Ketcher 渲染，步骤连线、选择和布局由工作台自身负责。
- 本版本不继续展示多维置信度仪表盘、伪精确成功率或大量状态徽标。

## 4. 核心设计原则

- **图优先**：结构式、反应式和原文截图占主要空间；名称、CAS、条件和说明紧邻对应图形。
- **三段式**：工作台本身是最大外框，内部仅保留三个自上而下的全宽组件。
- **选择联动**：组件一选择步骤后，组件二和组件三同步切换到同一步骤。
- **少按钮**：常驻按钮只保留新建路线、锁定/解锁、添加步骤和当前产物入口；低频功能进入“更多”菜单。
- **少状态**：只展示影响下一步操作的状态，如“未核验”“生成中”“可保存”“已锁定”。
- **证据优先**：缺失值保持未确定；来源冲突不自动覆盖；用户核验和 Agent 更新有明确先后门禁。
- **向后兼容**：旧路线、旧 NMR 数据和旧产物仍可读取；新增字段均提供兼容迁移或缺省值。

## 5. 信息架构与页面布局

页面骨架如下，三个组件均占工作台完整宽度：

```text
┌──────────────────────────── 合成路线工作台 ────────────────────────────┐
│ 路线/版本                         新建路线  添加步骤  锁定  更多         │
├──────────────────────────── ① 合成总览 ───────────────────────────────┤
│ [结构/名称/CAS] ─条件→ [中间体] ─条件→ [中间体] ─条件→ [目标产物]      │
├──────────────────────────── ② 单步合成详情 ───────────────────────────┤
│ 反应物结构/名称/CAS │ 反应箭头、条件、注意事项 │ 产物结构/名称/CAS      │
│ 难点说明（≤50字）                                      [实验计划书]   │
├──────────────────────────── ③ 事实核验 ───────────────────────────────┤
│ AI 格式化事实单元、人工审核               │ 对应原文/SI 截图与定位    │
└───────────────────────────────────────────────────────────────────────┘
```

### 5.1 工作台外框

工作台占研究设计页可用内容宽度，避免再套多层卡片。顶部仅保留一行紧凑工具栏：路线选择、版本、锁定状态、“新建路线”、“添加步骤”和“更多”。Evidence 数量、提取能力、完整度、来源层级等不作为常驻徽标展示。

### 5.2 组件一：合成总览

目的：用最大可视面积展示完整合成路线。

- 全宽横向路线画布；步骤过多时可横向滚动或按稳定规则折行。
- 每个反应物、中间体和目标产物显示 Ketcher 渲染后的二维结构图。
- 结构图下方显示化合物名称和 CAS 号；CAS 未确认时显示“CAS 待确认”，不得猜测。
- 反应箭头上方或下方只显示最关键的条件摘要，避免把完整实验段落塞进总览。
- 每个步骤具有足够大的点击区域。点击步骤后高亮当前步骤，并联动组件二、组件三。
- 当前选中步骤通过边框或底色表示，不新增重复状态卡。
- 路线为空时提供“新建路线”；路线存在但无步骤时提供“添加第一步”。
- Ketcher 不负责多步路线布局。工作台将各化合物/单步反应渲染结果组合成路线图。

### 5.3 组件二：单步合成详情

目的：用一个完整横版直接回答“这一步怎么做、难点是什么、能否生成计划”。

布局为三栏：

1. 左栏“反应物”：大尺寸结构图；每个化合物同步显示名称、CAS、用量/当量（若有）。
2. 中栏“反应条件”：合成箭头居中；清晰展示试剂/催化剂、溶剂、温度、时间、气氛、浓度、后处理和纯化。注意事项置于箭头下方，不拆成多个状态卡。
3. 右栏“产物”：大尺寸结构图；同步显示名称、CAS、理论/文献收率（若有）。

底部只保留一段“分析与决策”，中文不超过 50 个字，主要从化合物性质出发说明该步骤的核心难点。不得恢复当前多维绿/黄/红指标、Blocking Issues 列表和置信度矩阵。

同一区域提供“实验计划书”按钮，遵循第 8 节的产物按钮状态机。

### 5.4 组件三：事实核验

目的：让用户用原文图像核验 AI 结构化结果，而不是只看模型转录文本。

- 左侧为 AI 从当前步骤正文和 SI 中提取的格式化内容，按反应物、用量、试剂/催化剂、溶剂、温度、时间、气氛、后处理、纯化、收率、注意事项等事实单元组织。
- 右侧为与左侧当前事实单元对应的原文或 SI 截图概览，必须是页面/区域截图，不以重新提取的纯文本替代。
- 点击左侧事实单元时，右侧切换并定位到对应页或 bbox；截图可放大并打开原 PDF。
- 每个事实单元支持“确认”“修正”“无法确认”。修正必须保留用户值和原提取值。
- 第一次提交进入人工核验轮次。用户必须完成本轮全部事实单元的选择后，才能触发“让 Agent 更新未确定项”。
- Agent 只批量处理“无法确认、缺失、冲突或被用户修正后需重算”的内容，不覆盖已确认的用户事实。
- Agent 更新产生的新内容重新标记为“待核验”，开启下一轮；无新增待核验项时该步骤完成核验。
- 若证据没有已捕获 PDF/SI、页码或截图定位，左侧内容仍可查看，但不能被视为完成截图核验；界面只给出明确缺失原因。
- 路线级核验完成条件：所有步骤均不存在待核验事实单元。只有此时才可将路线版本锁定为已核验基线。

## 6. 功能需求

### 6.1 Ketcher 渲染修复与路线图

#### FR-KET-001 结构资源健康检查

应用启动或首次进入工作台时，应验证 Ketcher 入口、主 JS/CSS、worker/WASM、编辑器初始化与渲染协议。失败时记录明确阶段和错误，不得无限显示“渲染中”。

#### FR-KET-002 有界加载与恢复

单个结构渲染必须在限定时间内成功或失败；失败卡片显示“结构预览不可用”并支持单次重试。后台渲染队列不可因一个分子失败而阻塞后续分子。

#### FR-KET-003 路线级渲染

组件一将 Ketcher 生成的分子/反应图组合为完整路线。缓存键至少包含规范化结构、渲染尺寸和主题；结构变化后自动失效。

#### FR-KET-004 诊断与回归

新增真实浏览器级回归，覆盖：资源返回 200、Ketcher 发出 ready、SMILES 载入、PNG/SVG 输出、三个以上结构连续渲染、编辑保存回写、打包安装后离线可用。

#### 当前实现审阅得到的优先排查点

以下为待验证假设，不是已确认根因：

- 现有单测只覆盖静态路径安全，未覆盖真实浏览器渲染和打包后运行。
- 宿主在 20 秒未收到 `ready` 时仍把模块标成 ready，随后发送的 render 可能在编辑器尚未初始化时丢失。
- 隐藏 iframe 使用单队列串行生成 PNG；首次加载约 10–20 秒，单任务又可等待 30 秒，多个化合物容易造成长期“渲染中”。
- postMessage 失败只返回空结果，缺少资源、初始化、`setMolecule`、`generateImage` 等阶段错误，无法从 UI 判断故障位置。
- 需要实测打包环境中的同源路径、MIME、缓存、CSP、worker/WASM 地址和服务注册时序。

### 6.2 化合物名称、CAS 与 PubChem/CACTUS 双源确认

#### FR-CMP-001 展示字段

所有路线、单步详情和核磁登记中的化合物至少支持：展示名、CAS 号、SMILES、结构来源、结构核验状态。建议内部同时保存 InChIKey 以便跨来源比对，但默认界面不展示。

#### FR-CMP-002 双源解析顺序

对名称或 CAS 发起解析时分别查询 PubChem 与 CACTUS，并记录每个来源的查询词、返回标识、结构、时间和错误。不得因一个来源先返回就覆盖另一个来源。

#### FR-CMP-003 结构比对与状态

- 两个来源规范化后结构一致：`dual-confirmed`，可自动采用。
- 仅一个来源命中：`single-source`，可作为候选显示，但保持待人工确认。
- 两个来源均命中但结构不一致：`conflict`，并列展示，不自动覆盖。
- 均未命中：`unresolved`，允许用户后续补绘或补录。
- 用户在 Ketcher 中保存的结构：`manual`，保留双源结果作为来源记录，不用外部结果覆盖人工值。

#### FR-CMP-004 CAS 规则

CAS 必须来自可追溯来源或用户录入，并通过格式校验；名称相似不等于 CAS 已确认。盐型、溶剂化物、同位素标记物和聚合物不得与中性母体静默合并。

### 6.3 分析与决策精简

#### FR-ANA-001 输出契约

每个步骤只保留一段 50 个中文字符以内的难点说明。内容优先考虑反应物/产物稳定性、溶解性、官能团兼容性、位阻、敏感性和纯化难点。

#### FR-ANA-002 缺证据处理

无法判断时输出“缺少足够的结构或条件信息，需先核验”，不生成多维置信度、成功概率或冗长建议。

### 6.4 实验计划模板与产物

#### FR-PLAN-001 模板管理

“模板管理”新增第三类“实验计划模板”，与阅读笔记模板、PPT 模板并列。模板支持新建、编辑、复制、归档和版本快照。

模板至少包含：模板名称、适用场景、章节顺序、必填字段、风险与安全段要求、试剂表字段、操作步骤格式、表征/质控要求、备注。任务保存模板版本快照，后续修改模板不影响既有产物。

#### FR-PLAN-002 生成入口

组件二显示“实验计划书”按钮。未生成时为灰色；第一次点击只进入待发送状态并展示将发送给 Agent 的请求摘要，第二次点击才真正发送消息。

#### FR-PLAN-003 登记与保存

Agent 生成 DOCX 后必须将产物路径、routeId、stepId、模板 id/version、生成时间和状态登记到面板。登记成功后按钮亮起；再次点击执行“另存为本地”，文件格式为 `.docx`。

#### FR-PLAN-004 安全门禁

实验计划始终标记为需人工审核，不自动执行实验。路线或步骤发生影响计划的修改后，已有计划标记为“可能过期”，但不自动删除。

### 6.5 文献精读报告与 PPT 入口统一

#### FR-LIT-001 精读报告

精读报告按钮采用与实验计划书一致的状态机：灰色未生成 → 第一次点击待发送 → 第二次点击发给 Agent → 生成中 → 登记完成后亮起 → 点击另存为本地 DOCX。

#### FR-LIT-002 文献 PPT

PPT 按钮采用同一逻辑，最终另存为本地 `.pptx`。现有已登记产物直接显示为可保存，不要求重新生成。

#### FR-LIT-003 失败恢复

生成失败后按钮回到可重试状态，保留上次错误摘要和请求参数；不得误亮为可下载。

### 6.6 用户创建路线、添加步骤与锁定

#### FR-ROUTE-001 新建路线

用户可从工作台直接创建路线，至少填写路线名称和目标化合物；目标化合物可从已有实体选择或现场录入名称/CAS/SMILES。

#### FR-ROUTE-002 添加与编辑步骤

用户可在路线末尾添加步骤，并可在未锁定版本上编辑、排序或删除步骤。每一步至少支持：

- 反应物、产物；
- 试剂、催化剂；
- 溶剂；
- 用量/当量；
- 温度、时间、气氛、浓度；
- 后处理、纯化、监测；
- 收率；
- 注意事项；
- 结构、名称和 CAS；
- 来源或证据定位（可后补）。

删除已有内容属于高风险操作，必须二次确认；步骤序号和路线图随后自动更新。

#### FR-ROUTE-003 锁定模型

锁定是路线版本级属性，与 `draft/under-review/approved/rejected` 审核状态分离。

- Agent 登记和人工创建的路线默认 `locked=false`。
- Agent 只能直接修改 `locked=false` 的路线版本。
- 路线锁定后，人工和 Agent 的内容写入均被阻止；修改应复制为新的未锁定版本。
- 只有用户能锁定路线。解锁是否允许由产品确认；建议不原地解锁，而是复制新版本，以保留可追溯基线。
- 锁定前若仍有待核验事实，界面应阻止锁定并定位到组件三。

### 6.7 可视化结构修改器（延期项）

当前 Ketcher shell 已具备弹层编辑的技术雏形，但距离稳定、内嵌、接近网页在线编辑器的体验仍需完成：工具栏裁剪、结构载入/保存、撤销重做、尺寸自适应、快捷键、错误提示、来源与人工覆盖记录、打包离线回归，以及与路线锁定规则联动。

工作量评估（单开发者、含测试）：

- 仅修复现有弹层编辑与缩略图：约 3–5 个工作日。
- 做成稳定的内嵌/抽屉式可视化编辑器：约 7–12 个工作日。
- 若进一步支持整条多步路线的自由拖拽、反应箭头编辑和拓扑重排：另需约 10–15 个工作日，且应拆成独立版本。

结论：0.4.0 先修复渲染并保留“查看/编辑”入口；完整可视化修改器延期到后续版本，不作为本次发布门槛。

### 6.8 核磁登记更新

#### FR-NMR-001 化合物身份

核磁登记记录关联一个化学实体或保存快照，并显示对应的 Ketcher 结构图、化合物名称和 CAS。旧数据只有 `structurePath` 时继续可读，并提示补关联信息。

#### FR-NMR-002 氘代试剂

将现有笼统 `solvent` 字段在界面明确为“氘代试剂/氘代溶剂”，支持如 CDCl₃、DMSO-d₆ 等值；内部兼容旧 `solvent`，新增记录建议写入明确的 `deuteratedSolvent` 字段。

#### FR-NMR-003 展示优先级

登记卡片以结构图为主，名称、CAS、氘代试剂和谱核类型为辅；不增加无关状态矩阵。

### 6.9 绘图登记更新

#### FR-PLOT-001 最小登记模型

新增或扩展绘图登记记录，至少包含：课题、绘图主题、日期、产物文件引用、创建者/来源、创建时间和更新时间。

#### FR-PLOT-002 主题与日期

- 绘图主题由 Agent 登记时给出默认值，用户可直接手工修改。
- 日期默认为本地创建日期，用户可修改为实验/成图日期。
- 列表卡片优先显示“绘图主题 + 日期”，不把文件名当作唯一标题。

## 7. 建议数据模型变更

| 对象 | 新增/调整字段 | 说明 |
|---|---|---|
| `synthesisRoute` | `locked`, `lockedAt`, `lockedBy` | 独立于审核状态的版本锁 |
| `routeStep` | `difficultySummary` | 50 个中文字符以内的单段难点 |
| `stepStructure` / 化学实体 | `casNumber`, `inchiKey`, `verification` | CAS、跨源比较标识、双源核验结果与来源记录 |
| `synthesisEvidence` | `reviewRound`, `originalExtract`, `userCorrection` | 支持分轮审核和保留人工修正 |
| 新 `synthesisReviewBatch` | route/step、轮次、状态、待处理项 | 实现“全部人工核验后批量交给 Agent”门禁 |
| 新 `experimentPlanTemplate` | 模板内容与版本字段 | 与阅读笔记模板一致的不可变版本快照 |
| 产物任务 | `artifactKind`, `requestState`, `templateSnapshot`, `filePath` | 统一实验计划、精读报告、PPT 的按钮与任务状态 |
| `nmrDataset` | `entityId`, `compoundSnapshot`, `deuteratedSolvent` | 显示结构、名称、CAS 与氘代试剂；兼容旧字段 |
| 新 `plotRecord` | `projectId`, `topic`, `date`, `artifactPath`, `source` | 绘图登记最小模型 |

所有新增 schema 字段应为 optional 或带 default，并提供旧数据读取测试。

## 8. 统一产物按钮状态机

适用于实验计划书、精读报告和 PPT。

| 状态 | 外观/文案 | 点击行为 |
|---|---|---|
| `idle` | 灰色“生成…” | 第一次点击进入 `confirm-send`，不发消息 |
| `confirm-send` | 强调“再次点击发送给 Agent” | 第二次点击发送一次请求，进入 `requested` |
| `requested` / `generating` | 灰色“生成中…” | 不重复发送；可查看任务摘要 |
| `ready` | 亮色“另存为本地” | 打开保存对话框并保存对应 DOCX/PPTX |
| `stale` | 亮色带“内容已变更”提示 | 允许保存旧版，也允许重新生成 |
| `failed` | 灰色“生成失败，重试” | 第一次点击重新进入确认，保留错误摘要 |

为防误触，`confirm-send` 在用户切换页面、切换步骤或经过合理超时后回到 `idle`。同一对象、同一产物类型在 `requested/generating` 状态不得创建重复任务。

## 9. 建议接口与服务拆分

- `synth_route_create`：复用现有服务，新增前端表单。
- `synth_route_step` / `synth_route_update_step`：补齐人工添加、排序、删除和锁定校验。
- `synth_route_lock`：用户锁定当前路线版本。
- `synth_review_batch_submit`：校验本轮事实项全部完成人工选择并登记批处理。
- `synth_review_batch_apply`：Agent 回写未确定项，已确认字段受保护。
- `compound_resolve_dual`：统一 PubChem/CACTUS 查询、规范化比较和来源记录。
- `plan_templates_*`：实验计划模板列表、解析、新建、更新、复制、归档和版本快照。
- `artifact_request_*`：统一三类产物的请求、状态、登记、失败和下载；可以先以现有任务服务扩展实现。
- `nmr_create/nmr_get`：扩展化学实体快照与氘代试剂字段。
- `plot_records_*`：绘图登记 CRUD，主题和日期可编辑。

所有写接口必须在服务端执行锁定校验，不能只依赖按钮禁用。

## 10. 验收标准

### AC-UI 合成工作台

- AC-UI-01：页面只呈现三个主要全宽组件，当前分析指标矩阵和长列表不再占独立大区块。
- AC-UI-02：完整路线结构图在首屏或首屏主体区域可见；点击任一步骤后，下方两个组件在 300 ms 内同步切换。
- AC-UI-03：单步详情呈现“反应物—箭头/条件—产物”横向结构；化合物图显著大于辅助文字。
- AC-UI-04：难点说明是一段话且不超过 50 个中文字符。
- AC-UI-05：常驻按钮和状态标签符合第 4 节精简原则。

### AC-KET Ketcher

- AC-KET-01：开发环境和 Windows 安装包离线环境均能渲染交接样例的全部路线化合物。
- AC-KET-02：连续渲染至少 10 个结构时，失败项不会阻塞后续项，也不会无限“渲染中”。
- AC-KET-03：打开已有结构、修改、保存后，组件一和组件二均刷新为新图，来源记为人工。
- AC-KET-04：资源或渲染失败时能区分失败阶段，并提供可执行的重试/补绘路径。

### AC-CMP 化合物双源确认

- AC-CMP-01：每个可识别化合物显示名称、结构和 CAS；缺失值明确为待确认。
- AC-CMP-02：双源一致、单源命中、双源冲突、均未命中四种测试数据分别进入正确状态。
- AC-CMP-03：双源冲突不自动写入最终结构；人工结构不会被后续查询覆盖。

### AC-EV 事实核验

- AC-EV-01：左侧每个事实单元可定位到右侧原文/SI 截图，且能打开原 PDF。
- AC-EV-02：本轮有任一事实未处理时，Agent 批量更新入口不可提交。
- AC-EV-03：人工全部审核后可发送一次批处理；Agent 只更新未确定项，已确认项保持不变。
- AC-EV-04：Agent 新增或改写的事实重新进入待核验，审计记录包含轮次、操作者和时间。

### AC-ART 产物按钮

- AC-ART-01：实验计划、精读报告和 PPT 均必须第二次点击才向 Agent 发送请求。
- AC-ART-02：生成中不能重复提交；失败可重试；登记完成后按钮亮起。
- AC-ART-03：实验计划和精读报告保存为 DOCX，PPT 保存为 PPTX；已有产物升级后仍可直接保存。
- AC-ART-04：实验计划模板可新建、修改、复制、归档，旧任务保持原模板版本快照。

### AC-ROUTE 路线编辑与锁定

- AC-ROUTE-01：用户能在空工作台新建路线并添加完整步骤。
- AC-ROUTE-02：人工和 Agent 创建的路线默认未锁定；Agent 能直接修改未锁定版本。
- AC-ROUTE-03：锁定后所有写接口拒绝修改；复制后产生新的未锁定版本。
- AC-ROUTE-04：仍有待核验事实时不能锁定路线。

### AC-NMR/PLOT 登记

- AC-NMR-01：核磁登记卡显示 Ketcher 图、名称、CAS、谱核类型和氘代试剂。
- AC-NMR-02：旧记录可读取，缺失的新字段以待补充显示。
- AC-PLOT-01：绘图登记显示主题和日期，两者均可人工修改并持久化。

## 13. 版本与分支治理

- 已确认：`main` 只合并严格早于 `0.3.0` 的发布线，目标为 `v0.2.0-rc.3`；不包含 `v0.3.0`。

## 14. 实施默认决策

1. 锁定后的路线不原地解锁，统一复制为新的未锁定版本。
2. 当前步骤的全部事实完成审核后可触发该步骤的 Agent 更新；整条路线全部完成后才允许锁定。
3. “无法确认”计为本轮人工操作完成，但会进入 Agent 待处理项。
4. 绘图日期默认成图日期，用户可改为实验或登记日期。
