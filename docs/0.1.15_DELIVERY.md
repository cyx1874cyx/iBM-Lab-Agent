## 1. 交付内容

0.1.15 同时解决四件事：

1. 文献精读板块已存档的正文 PDF / SI PDF，点击后在外部 Microsoft Edge 的 PDF 阅读器中打开（不再无响应/只下载/停留在应用内）。
2. 存档正文与 SI 时，服务端按"短引用 + 10 字以内短介绍"生成文件名，不再沿用出版社下载名。
3. 每篇文献建立独立条目文件夹 `literature/<entryStem>/`，正文 PDF、SI PDF、精读 Markdown/DOCX、PPTX、审计文件全部保存在该条目文件夹内。
4. 全部产品版本号统一为 0.1.15，通过自动测试与 Web 冒烟，生成 NSIS 安装包。

## 6. 新文件夹结构与文件名示例

```
<工程文件夹>\literature\<entryStem>\
  <entryStem> 正文.pdf      （原 <bundleId>/<出版社下载名> 不再使用）
  <entryStem> SI.pdf
  <entryStem> 精读报告.md
  <entryStem> 精读报告.docx
  <entryStem> 文献汇报.pptx
```

`entryStem = <短引用> <10字以内短介绍>`，示例（集成测试实测路径）：

```
projects\proj-1\literature\10.1000fake.1\10.1000fake.1 正文.pdf
projects\proj-1\literature\10.1000fake.1\10.1000fake.1 SI.pdf
```

规则：
- 短引用：report.shortCitation → 第一作者 et al. 年份 → DOI → bundle id。
- 短介绍：titleZh → 论文标题；中文标点删除、英文标点与数字转空格，截取 ≤10 Unicode 字符。
- 清理 Windows 非法字符 `<>:"/\|?*`、控制字符、尾部空格与句点，总长 ≤80。
- 同一 bundle 的 `entryStem` 在首次登记时固化到数据库，正文与 SI 分批存档复用同一目录。
- 旧 `captured-literature/<bundleId>/` 数据在首次捕获时受控迁移（保留旧文件、更新 DB 路径）。
