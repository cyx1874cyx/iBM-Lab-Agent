# 核磁解析工作区

## 核磁模拟

核磁条目可以仅凭结构创建，无需上传 FID。模拟文件尚未生成时，条目内灰色模拟图标仍可点击，打开小型设置窗口；点击生成即关闭窗口，创建独立科研助手对话并调用模拟任务工具，条目显示运行状态。Mnova 文件成功登记后图标可直接打开模拟谱；错误显示在条目中。沿用核磁解析的 `.mol`、`.sdf`、`.cdx`、`.cdxml`、`.mrv`、`.cml`、`.smi`、`.smiles` 和 `.inchi` 上传格式，也可用 Ketcher 绘制。单次只处理一个完整分子；纯分子式、多个 SDF 记录、混合物及 R 基占位结构不进入预测。

结构由本地 Indigo WASM 转换，核磁模拟支持 ¹H / ¹³C。旧自动预测器已停用；科研助手先读取结构与原子环境，结合分子结构和明确注明的依据构建峰模型，再调用核磁技能生成合成 FID。没有足够依据的环境列入未建模列表，不能凭空填写。峰模型及其每个环境的依据随结果保存；未经用户明确要求，不能把实测峰当成结构预测。

可设置氘代溶剂、样品质量（mg）、溶剂体积（mL）、观测核频率（MHz）、线宽（Hz）、温度（K）及扫描次数。质量与体积计算名义浓度，频率与线宽决定洛伦兹线形；溶剂、温度和扫描次数记录条件，不伪造未建模的位移校正、灵敏度或信噪比。交换氢默认不绘制，可手动开启；D₂O / CD₃OD 中继续省略。

模型可给出单峰、二重峰、三重峰、四重峰等一阶裂分及对应 J 值，不计算强耦合和二阶效应。谱图、界面和结果 JSON 均明确标注模拟。结构图上的序号对应导出 MOL 原子序号。¹³C 原子数不代表定量实验积分。重叠峰标签按空余行排列。

每次成功生成均保存在当前课题 `nmr-simulations/synthetic-UUID/` 下，包括结构、模型和预览文件。应用使用 `nmr-analyze-simulate` 技能的 `simulate_1d.py` 生成合成复数 FID、Varian `.fid`、ZIP、元数据及回读/峰位校验；固定种子和峰模型均随文件保存。Mnova 同时导入合成 FID 与结构，模拟专用桥接先清除自动溶剂误分类，再根据本次分析返回的原子与多重峰标识建立模拟归属计划，把一致的小写字母标在结构和模拟峰上，另存为 `synthetic.mnova`。核磁条目中的“模拟谱 · Mnova”入口打开该文件，使用登记哈希校验。文档标注 SYNTHETIC；预测模型无法唯一匹配的环境和峰不强行标注，也不属于实测归属。首次 Mnova 只读启动探针超时后自动安全重试一次；最终失败可重试并保存失败历史。失败不会覆盖旧结果，原有实测核磁任务与文件不变。

验证：`tests/integration/nmr-simulation.test.mjs` 覆盖全部结构格式、两种核种、交换氢、非法输入、浓度、峰面积与归档隔离；`tests/browser/nmr-simulation.test.mjs` 使用真实预测引擎检查上传、生成、结构/谱图显示、峰表、历史和窄窗口布局。

核磁解析与科研绘图使用独立面板。工作台核磁页与文献页一样不重复显示项目路径与项目操作栏，整栏空白都属于拖拽接收区域。核磁条目展示 Ketcher 渲染的目标结构、化合物名称、可选分子式与 CAS 号，支持拖入整个 FID 目录、FID ZIP、`.mnova`、JCAMP（`.jdx/.dx/.jcamp`）及对应结构文件。

点击“新建条目”后，弹出核磁原始数据、分子结构式两个独立选择区；均可拖入对应文件或点击打开文件资源管理器，结构区还可使用 Ketcher 绘制。选择时只在弹窗中暂存，不上传、不写入条目；两项齐全后才启用“新建条目”，点击后上传、登记，等待用户开始分析。取消会丢弃本次暂存，不留下半成品条目。

直接拖入整栏也仅打开选择弹窗；拖入多组数据会提示逐组选择，避免擅自配对结构。旧版已保存的 `draft` 保留兼容，可双击继续选择缺失的输入，集齐后保存。

输入表单支持结构文件、SMILES 和本地 Ketcher 绘制。分子式仅作为身份信息，不能代替唯一的目标结构。二进制 CDX 原件保留给 Mnova；即时预览可使用 MOL/CDXML，或在 Mnova 分析回填 SMILES 后展示。名称与 CAS 号不凭空补全。

条目在信息下方显示核磁日期，并提供五个同尺寸图标入口：

| 入口 | 行为 |
| --- | --- |
| 输入结构式 | 软件内 Ketcher 结构预览；缺失时补充输入 |
| 核磁原始文件 | 校验项目归属，ZIP 解出完整 FID 后通过 Mnova 打开 |
| 标峰后核磁文件 | 校验已登记产物哈希，在 Mnova 打开 `.mnova` |
| 标峰报告 | 复用 Office 转 PDF 服务，在软件内分页预览 |
| 条目文件夹 | 在文件资源管理器中打开标峰产物所在目录；尚无产物时打开原始核磁数据目录 |

缺少输出时对应图标禁用。条目默认显示绿色“开始分析”，点击后新建独立分析对话并显示带转圈的“正在分析”；再次点击会取消该条目绑定的会话，恢复“开始分析”。终止时递增 attempt，旧任务的状态更新及完成回填会被拒绝；重新开始再次创建独立对话。输入保留，失败也可点击“开始分析”重试。后台每 1.5 秒刷新结果；草稿不计入运行中任务。

右键“删除产出文件”可分别勾选删除当前已登记的模拟 `.mnova`、真实标峰 `.mnova` 和核磁报告；真实谱和报告包含登记的历史版本。该操作保留条目和原始文件并清除对应产物引用。“删除条目及文件”则删除条目、登记的原始核磁数据和结构文件、登记产物以及可确认属于该条目的模拟任务文件；不能确认归属的辅助文件保留。删除前检查产物哈希及其他条目的文件引用，发现共享或修改则拒绝操作。正在运行的任务不可删除，旧记录若缺少可校验的产物登记则不能单独选择该产物。

所有面板任务（文献、核磁、绘图、研究设计、写作、选中文本引用等）共用课题工作目录与记忆，每次操作使用全新会话 ID，既不复用当前对话，也不复用已有空白对话。只打开工程时仍可保留当前输入。

`characterization_nmr_save/start/structure` 提供草稿保存、启动和输入结构读取。输入与产物都经当前项目目录及归属校验；启动后不允许替换输入。Mnova 通过 `desktop_artifact(action=openMnova)` 使用已登记的条目引用，客户端不直接指定系统路径。桌面端优先使用 `MNOVA_EXE`，其次检查标准安装目录和 PATH，通过 Windows Shell 的正常 open 动作打开，工作目录固定为 Mnova 安装目录。文件路径经环境参数传递到固定启动脚本，Shell 启动失败不回退到直接启动 EXE。

核磁文件上传沿用现有 25 MB 上传上限。较大的 FID 数据建议先压缩为 ZIP 后选择。FID 文件夹拖入时保留所有采集参数与子目录，不只上传单独的 `fid`。

验证：`tests/integration/nmr-workbench.test.mjs` 覆盖草稿重启保留、输入绑定、启动与完成、项目隔离、原始文件/Mnova 输出路由和报告 PDF 流；`tests/browser/nmr-workbench.test.mjs` 在真实浏览器中验证两个选择区、文件资源管理器、拖拽、Ketcher 绘制、两项齐全后确认创建、取消不登记、任务回填和四个入口；`tests/unit/nmr-files.test.mjs` 与 `mnova-open.test.mjs` 分别验证完整目录打包和 Mnova 启动参数。

桌面端本地预览使用限定的子框架请求策略：只给当前应用窗口直接嵌入的 Ketcher/PDF 查看器及已登记报告预览导航添加请求标记，查看器仅可读取各自静态资源和规定的 PDF/SI 文档，不能调用业务 RPC。开发版准备脚本与发布构建脚本共同应用该策略，保留宿主主框架的原认证规则。对应验证位于 `tests/unit/embedded-preview-policy.test.mjs`。

Mnova 启动路径修复沿用 `vendor/mnova-mcp/README.md` 中的 Windows Shell + 安装目录 + 只读启动探针方案。分析端安装包已核对与仓库 runner 内容一致；MCP 的桥接临时副本放在系统临时目录中的项目哈希子目录，工程数据和产物不迁移。文件打开入口也必须使用同一启动方式，不能直接 `spawn(MestReNova.exe)`。启动探针超时只能记为启动未通过，不能据此判断许可状态。

桌面分析工具层直接注册五个 `mnova_*` 专用工具，按每次调用的工程绑定注入 workspace/output/runtime 路径，通过固定的 `scripts/runtime/mnova_job.py` 调用已安装的桥接实现。无需模型扫描安装目录或临时编写启动器；工作进程受科学运行时管理，终止分析会取消对应进程。Windows 正常窗口就绪最多等待 30 秒，再执行独立的 5 秒只读探针；已有可见窗口直接复用。原始核磁文件不覆盖，自动打开不修改任何授权配置。
