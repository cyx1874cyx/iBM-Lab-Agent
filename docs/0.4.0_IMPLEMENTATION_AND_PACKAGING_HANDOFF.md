## 3. 历史审阅问题与本轮变更（须在 0.4.1rc5 复核）

本节关于未挂载组件、旧样式和接口缺失的描述来自较早工作树，不是 `0.4.1rc5` 的已验证现状。先核对该版本源码与实际运行界面：已修复项保留回归，仍存在的缺口才实施；本轮四项新增要求按最新需求书执行。

### 3.1 工作台存在“定义了但没有挂载”的核心缺陷

`client/index.js` 已定义 `StepReactionLayout`，但当前返回树没有调用它。与此同时，0.4.0 CSS 覆盖又把 `.sw-cond`、`.sw04-analysis` 和 `.sw04-plan` 隐藏。因此第二组件可能只剩标题/提示，真正的横向反应式和难点、计划按钮没有显示。

正确处理方式：

1. 在第二组件中真实挂载 `StepReactionLayout`。
2. 把难点和实验计划按钮移动到同一组件内。
3. 删除或停止渲染旧条件表、旧分析区、旧计划区，而不是继续用 `display:none` 掩盖。
4. 增加界面结构测试，断言横向反应组件确实存在，且页面只有三个主要工作台组件。

### 3.2 路线总览仍是文字卡片

当前 `sw-graph` 由文字步骤卡组成，结构化状态、Evidence 数量和审核状态占据主视觉。必须改成由 Ketcher 渲染的化合物节点和反应箭头组成的路线图；文字仅保留步骤号、必要简称和最少的异常提示。

### 3.3 首次提交取消双源校验

后端已有 `synth_compound_resolve_dual` / `resolveCompoundDual`，新需求不再把它们接到首次提交链路。改为任一来源命中即采用，首选未命中或超时可回退；并行时第一个有效结果即可返回。结构与 CAS 独立回填，部分缺失不阻止路线提交。保留来源及历史状态读取，不把单源结果标为人工已审核，不覆盖人工结构。

入口检查必须覆盖用户表单、Agent 工具和远程服务，不能只换按钮文案。测试需证明慢来源、来源失败和后续不同候选均不会卡住首次提交。

### 3.4 路线写保护规则与需求不一致

`lib/synthesis.js` 的 `assertWritable` 同时检查 `locked` 和 `status === draft`。需求要求锁定与审核状态独立：只要 `locked=false`，用户和 Agent 就能修改；`locked=true` 才禁止所有原位修改。

修改后必须保留以下边界：

- 锁定版本任何写接口都在服务端拒绝，不能只禁用按钮。
- 已人工确认的事实不能被 Agent 批量更新覆盖。
- 需要继续修改锁定版本时，只能复制成新的未锁定版本。

### 3.5 模板、产物和登记功能只完成了局部后端

- 实验计划模板已有模型、服务和远程接口，但模板管理 UI 尚未接入。
- 实验计划按钮仍是直接生成内部草案，不是两次点击向 Agent 请求 DOCX。
- 精读报告/PPT 只有“已有文件后打开”的逻辑，没有未生成时的请求状态机。
- NMR 有只读卡片，没有完整登记/编辑流程。
- 绘图登记尚无模型、服务、远程接口或页面。

7. 输出修复前后指标与失败样例：正确页 ≥95%、正确段落 ≥90%，负例不得假精确命中；缓存切换 P95 ≤500 ms，未缓存 300 ms 内加载反馈。

退出条件：AC-EV-05–06 通过，真实样例截图和测量结果随交接保存；没有真实数据时如实列为待验收，不能只用模拟测试宣称达标。

### WP4：完成事实核验和 Agent 批量更新闭环

任务：

1. 将 AI 提取结果拆成事实单元，至少覆盖反应物、产物、试剂/催化剂、溶剂、温度、时间、气氛、浓度、后处理、纯化、监测、收率和注意事项。
2. 每项提供“确认”“修正”“无法确认”；修正必须同时保留原始提取值和用户修正值。
3. 未完成全部选择前，不允许提交给 Agent。
4. 全部完成后出现唯一的“交给 Agent 更新未确定项”动作。
5. Agent 只能更新“无法确认/未确定”的事实，不能覆盖已确认或人工修正值。
6. Agent 回写的新事实进入下一审核轮次，不得自动视为已确认。
7. 路线锁定前检查所有步骤的当前审核轮次已经完成。

建议远程接口：

- `synth_review_batch_submit`
- `synth_review_batch_apply`
- `synth_review_batch_get`

退出条件：从首次截图审核到 Agent 回写再到第二轮审核可完整走通，并有集成测试证明确认字段不可覆盖。

### WP5：人工创建路线和完整步骤编辑

任务：

- 空工作台提供“新建路线”，而不是只提示去对话中登记。
- 使用页面表单或抽屉，不再用连续 `window.prompt`。
- 步骤字段至少包括：反应物、产物、试剂、催化剂、溶剂、用量/当量、温度、时间、气氛、浓度、后处理、纯化、监测、收率、注意事项和来源位置。
- 支持添加、编辑、删除、排序步骤。
- 人工创建和 Agent 登记的新路线默认 `locked=false`。
- 用户和 Agent 修改均调用相同的服务端锁定校验。
- 锁定后编辑入口变为“复制为新版本”，原版本保持可追溯。

退出条件：完全不借助对话也能新建一条两步路线、编辑全部条件、调整顺序并锁定；锁定后所有原位写操作均失败。

### WP6：实验计划模板和统一产物按钮

任务：

1. 模板管理新增第三个“实验计划模板”页签，接入现有 `experiment_plan_templates_*` 接口。
2. 支持新建、编辑、复制、归档和不可变版本快照。
3. 实验计划书、精读报告、PPT 共用一个状态机和一致的按钮交互：
   - `idle`：灰色；第一次点击只进入确认态，不发送请求。
   - `confirm-send`：第二次点击才向 Agent 发送一次请求。
   - `requested/generating`：不可重复提交，可显示简短进度。
   - `ready`：按钮亮起；点击调用系统“另存为”。
   - `stale`：旧文件仍可保存，同时可明确请求重新生成。
   - `failed`：显示短错误并允许重试。
4. 实验计划和精读报告输出 DOCX；PPT 输出 PPTX。
5. 产物完成后登记到对应课题面板，并保存模板版本快照和文件路径。
6. 第一次点击不得产生远程调用；第二次点击只能产生一次请求。为此编写交互测试。

优先扩展现有任务/产物服务，避免再建互不兼容的三套状态机。

退出条件：三类按钮都可从灰色开始，经两次点击生成，完成后亮起并另存；刷新页面后状态不丢失。

### WP7：NMR 与绘图任务提交闭环

任务：

- NMR 登记表单可选择/创建化合物，填写名称、CAS、SMILES、核种和氘代试剂。
- 核磁列表只常驻日期、结构式、名称、核磁图按钮和报告按钮；CAS、氘代试剂、谱核移入详情。旧记录仍可读，新字段缺失显示待补充。
- 新增绘图登记 CRUD，主题默认可从文件/任务推导但允许手工修改。
- 日期默认本地创建日期，允许修改为实验或成图日期。
- 表征页面同时提供 NMR 和绘图提交入口；绘图条目只常驻主题、日期、绘图文件按钮，不把文件名当作唯一标题。

- NMR 提交表单收集真实谱数据引用、化合物信息、核种、氘代试剂和分析目标；绘图提交表单收集数据/Origin 项目、主题、日期、绘图要求和输出格式，以 Origin 可编辑项目为必需交付，其他后端只作辅助。必填项按 FR-NMR-004 / FR-PLOT-003 执行。
- 选择文件后先完成上传/有效引用登记，再一次明确提交给服务端；不能仅保存记录或向聊天框填入未发送的文字。
- 复用现有任务服务并接通实际 Agent 分发，持久化 taskId、输入快照、状态、错误和重试历史；网络重发与双击幂等。
- 任务进度与科学审核状态分离；NMR 保留原始 FID/已审核积分保护。刷新恢复、失败保留输入、重试能继续执行。
- 核磁任务完成时自动回填同一条目的日期、结构式、名称、Mnova 谱图文档（优先 .mnova）和 .docx 报告；绘图任务完成时回填同一条目的主题、日期、Origin 项目（.opju/.opj）。按 taskId 幂等更新，不要求用户再次登记，重复完成回调不得新增条目。缺任一必需产物不得标完成。
- 核磁图按钮指定 Mnova 打开谱图文档，报告按钮指定 Microsoft Word 打开 DOCX，绘图文件按钮指定 Origin 打开项目；静态预览、下载或跳回聊天不能替代软件打开。按钮按各自产物独立就绪，重生成指向最新产物。
- 为未安装执行后端、文件上传失败、分发失败、回填失败提供可操作提示。

退出条件：AC-NMR-03、AC-PLOT-02、AC-REG-01–02 通过；至少分别跑通一个真实核磁和绘图任务的提交、处理、条目回填；实机确认核磁图在 Mnova、报告在 Word、绘图项目在 Origin 中打开的是正确文件，另测失败重试和刷新恢复。新旧记录显示及主题/日期编辑仍须通过。没有真实 Mnova/Origin 环境时记录待验收，不得仅凭 CRUD 测试宣称提交闭环已完成。

### WP7A：指定软件的桌面文件打开

- 复用或扩展桌面原生桥，接收产物 ID 与允许的软件类型，在服务端核验课题归属、产物类型及文件引用，不接收任意拼接命令。

## 7. Windows 打包指导

### 7.1 打包前提

- Windows 10/11 x64。
- Node.js `24.16.0` 或与发布清单一致的 Node 24。
- Corepack/pnpm 可用。
- Rust stable、MSVC C++ Build Tools、Tauri/NSIS 构建依赖可用。
- 发布签名需要 GitHub Secrets 或本地合法的代码签名证书；无证书只能生成内部验收候选包。
- 先完整阅读 `desktop/docs/packaging-pitfalls.md` 和 `desktop/docs/release-checklist.md`。

### 7.2 版本一致性

当前基线是用户确认的 `0.4.1rc5`；下一版本号未指定，不自动推定 rc6。机器版本字段的具体格式（如 SemVer 的 `0.4.1-rc.5`）须核对实际发布记录后使用，不把显示写法直接当作已验证的包版本。需要保持以下位置一致：

1. `package.json`
2. `desktop/package.json`
3. `desktop/src-tauri/Cargo.toml`
4. `desktop/src-tauri/tauri.conf.json`
5. `desktop/src-tauri/Cargo.lock` 中 `ibm-lab-desktop`
6. `desktop/docs/release-manifest.json` 的 `ibmLabAgent`

修改 `Cargo.toml` 后通过 Cargo 命令刷新锁文件，不要随意手改依赖锁。版本更新后检查旧候选号是否意外残留：

```powershell
rg -n '0\.4\.0-rc\.3|0\.3\.2-rc\.1' package.json desktop/package.json desktop/src-tauri/Cargo.toml desktop/src-tauri/Cargo.lock desktop/src-tauri/tauri.conf.json desktop/docs/release-manifest.json
```

发布清单中的 DSH、Node、Python、Origin MCP、Mnova MCP 和 MCP SDK 版本也必须与实际打包内容一致。

### 7.3 安装依赖并跑源码门禁

```powershell
Set-Location 'C:\Users\admin\Desktop\iBM-Agent\iBM-Agent-inCodeX'
npm ci --omit=peer --legacy-peer-deps

Push-Location 'runtime\launcher'
corepack pnpm install --frozen-lockfile --prod
Pop-Location

Push-Location 'desktop'

Pop-Location

npm run check:preset-exports

```

任何一项失败都不得继续打正式安装包。修复源码后应重跑相关测试，最终再跑一次全量。

### 7.4 准备自包含 Python 和桌面运行时

所有源码修改完成后再运行。`prepare-runtime` 会删除并重建 `resources/node`、`resources/dsh` 和 `resources/plugin`，不要并发启动两次，也不要把 `-NodeExe` 指向将被删除的资源目录。

```powershell
Push-Location 'desktop'
& pwsh -NoProfile -ExecutionPolicy Bypass -File '.\scripts\build-bundled-python.ps1' -SourceRoot '..'
if ($LASTEXITCODE -ne 0) { throw 'build-bundled-python failed' }

& pwsh -NoProfile -ExecutionPolicy Bypass -File '.\scripts\prepare-runtime.ps1' -SourceRoot '..' -NodeExe (Get-Command node).Source
if ($LASTEXITCODE -ne 0) { throw 'prepare-runtime failed' }

& pwsh -NoProfile -ExecutionPolicy Bypass -File '.\scripts\verify-package.ps1' -WebSmokeTest
if ($LASTEXITCODE -ne 0) { throw 'packaged runtime smoke test failed' }
Pop-Location
```

只要在 `prepare-runtime` 之后修改了根目录下的 `client/`、`lib/`、`src/`、`cordis.patch.yml`、`package.json`、`presets/` 或相关运行时内容，就必须重新运行 `prepare-runtime` 和 `verify-package -WebSmokeTest`。

建议为本次新增模块扩展 `verify-package.ps1`：

- 检查 Ketcher `index.html` 和其引用的所有哈希资源存在。
- 导入实验计划模板、事实审核批次、统一产物请求和绘图登记服务。
- 在 Web 冒烟中调用 `projects_list`、模型列表和一个只读合成接口。
- 明确拒绝 duplicate service、插件未注册、`Failed to fetch` 和缺生产依赖。

### 7.5 构建 NSIS 安装包

```powershell
Push-Location 'desktop'
npx tauri build
if ($LASTEXITCODE -ne 0) { throw 'tauri build failed' }
Pop-Location
```

默认按 `.github/workflows/windows-release.yml` 和 `tauri.conf.json` 构建。不要为追求速度盲目设置 `TAURI_CONFIG={"bundle":{"resources":[]}}`；如果确需用于诊断，必须证明最终 NSIS 仍包含完整 Node、DSH、插件、Python 和 Ketcher 资源，否则不能发布。

本仓库资源很多，长时间复制或 LTO 编译不等于卡死。依据日志增长、`rustc`/`makensis` 进程和目标文件变化判断；不要只因数分钟无终端输出就重启第二轮构建。

### 7.6 精确选择并验证新安装包

不要使用 `Get-ChildItem ... | Select-Object -First 1`，因为目录内已有旧候选包。按确认的版本号精确匹配：

```powershell
$releaseVersion = Read-Host '输入本次已确认且与构建产物一致的包版本号' # 不预设下一版本
$bundleDirectory = Resolve-Path 'desktop\src-tauri\target\release\bundle\nsis'
$installer = Get-ChildItem -LiteralPath $bundleDirectory -Filter '*.exe' |
  Where-Object { $_.Name -eq "iBM Lab Agent_${releaseVersion}_x64-setup.exe" }
if (@($installer).Count -ne 1) { throw "expected exactly one installer for $releaseVersion" }

Push-Location 'desktop'
& pwsh -NoProfile -ExecutionPolicy Bypass -File '.\scripts\verify-package.ps1' -InstallerPath $installer.FullName
if ($LASTEXITCODE -ne 0) { throw 'installer verification failed' }
Pop-Location

Get-FileHash -Algorithm SHA256 -LiteralPath $installer.FullName
Get-Item -LiteralPath $installer.FullName | Select-Object FullName,Length,LastWriteTime
```

当前 `verify-package.ps1 -InstallerPath` 主要检查文件存在和体积，不能代替包内内容检查。正式候选还应使用 7-Zip 列出安装包内容，确认至少包含：

- `node.exe`
- DSH 运行时
- `plugin/dsh-lab-agent/package.json`
- 新增的服务与模型文件
- `client/index.js`
- `client/assets/ketcher-standalone/index.html` 及其实际引用块
- 自包含 Python、Origin MCP、Mnova MCP 和 `bridge.qs`

### 7.7 安装版人工验收

使用干净 Windows 用户或虚拟机安装，不能只覆盖当前开发机旧安装。至少验证：

1. 首次启动能进入 DSH，第二次启动聚焦已有窗口。
2. 模型下拉可选择，不出现空列表或请求失败。
3. 课题列表正常，不出现 `client api: lab/projects_list failed: Failed to fetch`。
4. 日志没有插件未注册、重复 `labAgent` 服务、缺 `jszip/zod/fast-xml-parser/js-yaml` 等错误。
5. 合成工作台只显示三个主要组件，路线图可点选步骤。
6. Ketcher 连续渲染、失败重试和编辑保存正常，断网仍能使用。

### 7.8 签名、发布和分支约束

- 内部候选包可以先不签名，但必须明确标注“仅验收”。
- 正式 Windows 发布必须通过 `desktop/scripts/sign-windows.ps1` 和 Authenticode 验证。
- Tag 会触发 `.github/workflows/windows-release.yml`；打 Tag 前必须完成安装版验收。
- 只有得到产品负责人明确授权后才能推送正式 Tag、发布 GitHub Release 或更新 USTC/GitHub 双远程。
- 本次更新不得自动合并 `main`；应保留发布分支和可追溯提交。
- 发布资产记录文件名、字节数、SHA256、Tag、Commit、签名状态和验收日期。
