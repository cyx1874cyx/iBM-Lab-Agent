# iBM Lab Agent 0.4.0 修改计划与 Windows 打包指导

> **接手 Agent 先读**：需求已拆分为 0.4.0/0.4.1/0.4.2 三个完成书，执行入口为 `docs/0.4.x_THREE_RELEASE_AGENT_HANDOFF.md`。本文保留历史分析与技术细节；Windows 发布命令以 `desktop/scripts/build-windows-release.ps1` 和当前 `desktop/README.md` 为准，旧的逐条 npm/npx 命令不再是推荐流程。

> 面向后续接手实现、测试和打包的 Agent。本文是执行计划，不代表当前功能已经完成。
>
> 产品需求的唯一业务基线为 `docs/0.4.0_REQUIREMENTS_DRAFT.md`；本文负责把需求转换为代码任务、验收门禁和发布步骤。如两者冲突，以需求书和产品负责人的最新明确指示为准。

## 1. 交付目标

把当前“接口/模型已有一部分、界面仍是旧工作台”的状态，改造成可验收的 0.4.0：

1. 合成路线工作台只保留一个最大外框和三个自上而下的全宽组件。
2. 第一组件显示以结构图为主的完整合成路线；点击步骤联动第二、第三组件。
3. 第二组件横向显示“反应物 → 条件/注意事项 → 产物”，含 CAS、50 字以内难点和实验计划书按钮。
4. 第三组件完成“左侧结构化事实、右侧原文截图”的逐项人工核验及 Agent 批量更新门禁。
5. Ketcher 在安装版中可以离线渲染，单个坏结构不能拖死整页；化合物支持 PubChem/CACTUS 双源确认。
6. 用户可以新建路线、完整增删改排步骤；Agent 可以修改任何未锁定版本，锁定版本只能复制为新版本。
7. 实验计划书、精读报告和 PPT 使用统一的“两次点击生成、完成后另存”逻辑。
8. 模板管理增加实验计划模板；NMR 登记补齐结构/CAS/名称/氘代试剂；增加绘图主题和日期登记。
9. 完成源码测试、桌面运行时冒烟、安装包验证和干净用户环境验收。

完整内嵌、可拖拽的路线拓扑/结构编辑器不属于本次强制交付。当前 Ketcher 单结构编辑弹窗可以保留并修稳，但不要把完整路线编辑器扩展混入本次发布。

## 3. 当前实现中必须优先处理的已知问题

### 3.1 工作台存在“定义了但没有挂载”的核心缺陷

`client/index.js` 已定义 `StepReactionLayout`，但当前返回树没有调用它。与此同时，0.4.0 CSS 覆盖又把 `.sw-cond`、`.sw04-analysis` 和 `.sw04-plan` 隐藏。因此第二组件可能只剩标题/提示，真正的横向反应式和难点、计划按钮没有显示。

正确处理方式：

1. 在第二组件中真实挂载 `StepReactionLayout`。
2. 把难点和实验计划按钮移动到同一组件内。
3. 删除或停止渲染旧条件表、旧分析区、旧计划区，而不是继续用 `display:none` 掩盖。
4. 增加界面结构测试，断言横向反应组件确实存在，且页面只有三个主要工作台组件。

### 3.2 路线总览仍是文字卡片

当前 `sw-graph` 由文字步骤卡组成，结构化状态、Evidence 数量和审核状态占据主视觉。必须改成由 Ketcher 渲染的化合物节点和反应箭头组成的路线图；文字仅保留步骤号、必要简称和最少的异常提示。

### 3.3 双源解析没有接入界面

后端已有 `synth_compound_resolve_dual` 和 `resolveCompoundDual`，但工作台“解析缺结构”仍调用 PubChem-only 路径。必须改成：

- PubChem/CACTUS 结果一致：允许登记结构及来源；CAS 仍要求有可追溯来源。
- 只有一个来源成功：标记单源，必须明确展示来源。
- 两源冲突：只显示候选，禁止自动写入。
- 两源都失败：保持待确认，允许 Ketcher 人工补绘或用户录入。

### 3.4 路线写保护规则与需求不一致

`lib/synthesis.js` 的 `assertWritable` 同时检查 `locked` 和 `status === draft`。需求要求锁定与审核状态独立：只要 `locked=false`，用户和 Agent 就能修改；`locked=true` 才禁止所有原位修改。

修改后必须保留以下边界：

- 锁定版本任何写接口都在服务端拒绝，不能只禁用按钮。
- 已人工确认的事实不能被 Agent 批量更新覆盖。
- 需要继续修改锁定版本时，只能复制成新的未锁定版本。

### 3.5 模板、产物和登记功能只完成了局部后端

- 实验计划模板已有模型、服务和远程接口，但模板管理 UI 尚未接入。
- 实验计划按钮仍是直接生成内部草案，不是两次点击向 Agent 请求 DOCX。
- 精读报告/PPT 只有“已有文件后打开”的逻辑，没有未生成时的请求状态机。
- NMR 有只读卡片，没有完整登记/编辑流程。
- 绘图登记尚无模型、服务、远程接口或页面。

下面的工作包按依赖排序。每个工作包完成后先跑局部测试；不要等所有代码写完才首次验证。

目标：让后续改造有清晰的失败/通过判据。

任务：

- 将 `docs/0.4.0_REQUIREMENTS_DRAFT.md` 中 AC-UI、AC-CHEM、AC-FACT、AC-ART、AC-ROUTE、AC-REG 转成测试清单。

退出条件：新增测试能够准确暴露当前缺失项，且测试名称与需求编号对应。

主要文件：

- `scripts/ketcher-shell/src/main.tsx`
- `scripts/ketcher-shell/package.json`
- `client/assets/ketcher-standalone/`
- `client/index.js`
- `lib/ketcher-assets.js`

任务：

1. 固化 `ready`、`setMolecule`、`render`、`image`、`molecule`、`cancel` 消息协议，并校验消息来源和 `requestId`。
2. 为启动超时、单任务超时、资源加载失败提供明确错误，不让一个坏结构阻塞后续队列。
3. 缓存键至少包含规范化结构、尺寸和主题；失败结果不能永久缓存。
4. 结构卡提供独立重试；缺失/冲突时显示占位，不无限显示“渲染中”。
5. 路线总览按化合物节点和反应步骤生成路线图，结构图尽可能大；点击反应箭头/步骤区域更新选中步骤。
6. 离线安装版不得依赖 CDN。
7. 修改 Ketcher shell 后从源码重建产物，并清除目标目录中不再被新 `index.html` 引用的旧哈希块。

退出条件：开发环境和安装版均可连续渲染至少 10 个合法结构；插入一个非法 SMILES 后其余结构仍能完成；编辑保存后路线图和卡片立即刷新。

### WP3：重写三组件工作台

主要文件：`client/index.js`。该文件是 DSH 单文件注入入口，顶层不能引入未打包的 `import/export`。

组件结构必须固定为：

1. `RouteOverviewPanel`
2. `StepDetailPanel`
3. `FactReviewPanel`

具体要求：

- 根容器使用工作区可用的最大宽度，不再在内部嵌套旧式多列仪表盘。
- 总览只保留版本选择、必要的新建/复制/锁定入口和路线图；低频操作收进单一菜单或编辑入口。
- 第二组件直接挂载横向反应布局：左侧反应物、中间箭头和条件/注意事项、右侧产物。
- 每个化合物显示结构、名称、CAS、用量/当量或收率；缺失值明确标“待确认”。
- 难点说明必须在第二组件内且不超过 50 个中文字符。
- 实验计划书按钮必须在第二组件内。
- 删除旧版多维红黄绿指标、Blocking Issues、字段完整度百分比和长分析列表的用户可见渲染。
- 第三组件左侧为事实项列表/编辑，右侧始终只显示当前选中事实对应的原文截图；移动选择时截图同步变化。
- 移动端可以上下折叠，但桌面端保持三个纵向全宽主组件。

退出条件：页面肉眼只见三个主要组件；没有依靠隐藏空组件凑数；图是主体，文字和按钮退居辅助。

### WP4：完成事实核验和 Agent 批量更新闭环

任务：

1. 将 AI 提取结果拆成事实单元，至少覆盖反应物、产物、试剂/催化剂、溶剂、温度、时间、气氛、浓度、后处理、纯化、监测、收率和注意事项。
2. 每项提供“确认”“修正”“无法确认”；修正必须同时保留原始提取值和用户修正值。
3. 未完成全部选择前，不允许提交给 Agent。
4. 全部完成后出现唯一的“交给 Agent 更新未确定项”动作。
5. Agent 只能更新“无法确认/未确定”的事实，不能覆盖已确认或人工修正值。
6. Agent 回写的新事实进入下一审核轮次，不得自动视为已确认。
7. 路线锁定前检查所有步骤的当前审核轮次已经完成。

建议远程接口：

- `synth_review_batch_submit`
- `synth_review_batch_apply`
- `synth_review_batch_get`

退出条件：从首次截图审核到 Agent 回写再到第二轮审核可完整走通，并有集成测试证明确认字段不可覆盖。

### WP5：人工创建路线和完整步骤编辑

任务：

- 空工作台提供“新建路线”，而不是只提示去对话中登记。
- 使用页面表单或抽屉，不再用连续 `window.prompt`。
- 步骤字段至少包括：反应物、产物、试剂、催化剂、溶剂、用量/当量、温度、时间、气氛、浓度、后处理、纯化、监测、收率、注意事项和来源位置。
- 支持添加、编辑、删除、排序步骤。
- 人工创建和 Agent 登记的新路线默认 `locked=false`。
- 用户和 Agent 修改均调用相同的服务端锁定校验。
- 锁定后编辑入口变为“复制为新版本”，原版本保持可追溯。

退出条件：完全不借助对话也能新建一条两步路线、编辑全部条件、调整顺序并锁定；锁定后所有原位写操作均失败。

### WP6：实验计划模板和统一产物按钮

任务：

1. 模板管理新增第三个“实验计划模板”页签，接入现有 `experiment_plan_templates_*` 接口。
2. 支持新建、编辑、复制、归档和不可变版本快照。
3. 实验计划书、精读报告、PPT 共用一个状态机和一致的按钮交互：
   - `idle`：灰色；第一次点击只进入确认态，不发送请求。
   - `confirm-send`：第二次点击才向 Agent 发送一次请求。
   - `requested/generating`：不可重复提交，可显示简短进度。
   - `ready`：按钮亮起；点击调用系统“另存为”。
   - `stale`：旧文件仍可保存，同时可明确请求重新生成。
   - `failed`：显示短错误并允许重试。
4. 实验计划和精读报告输出 DOCX；PPT 输出 PPTX。
5. 产物完成后登记到对应课题面板，并保存模板版本快照和文件路径。
6. 第一次点击不得产生远程调用；第二次点击只能产生一次请求。为此编写交互测试。

优先扩展现有任务/产物服务，避免再建互不兼容的三套状态机。

退出条件：三类按钮都可从灰色开始，经两次点击生成，完成后亮起并另存；刷新页面后状态不丢失。

### WP7：NMR 与绘图登记

任务：

- NMR 登记表单可选择/创建化合物，填写名称、CAS、SMILES、核种和氘代试剂。
- 列表使用 Ketcher 图、名称、CAS、氘代试剂作为主信息；旧记录无新字段时仍可打开并显示“待补充”。
- 新增绘图登记 CRUD，主题默认可从文件/任务推导但允许手工修改。
- 日期默认本地创建日期，允许修改为实验或成图日期。
- 表征页面同时提供 NMR 和绘图登记入口，不把文件名当作唯一标题。

退出条件：新旧 NMR 记录都能显示；绘图记录可新增、编辑主题和日期、刷新后持久化。

### WP8：回归、安装版验收和文档收口

`build:client` 主要检查 `client/index.js` 仍可作为 DSH 单文件注入入口。客户端必须继续且只执行一次 `window.__ModuleLoader__.load` 注册 `dsh-lab-agent`，不得再次出现：

```text
loaded without registering "dsh-lab-agent" via __ModuleLoader__.load
```

### 6.2 本次必须新增的自动测试

- 路线未锁定且状态不是 draft 时仍可按需求修改。
- 锁定路线的步骤、结构、Evidence、Agent 回写全部被服务端拒绝。
- Evidence 三种人工决定、修正值保留、轮次推进和完整审核门禁。
- Agent 批量回写不能覆盖 confirmed/corrected 字段。
- PubChem/CACTUS 一致、单源、冲突、双失败四条路径。
- CAS 格式和来源规则；盐型/溶剂化物不能静默合并。
- 三个主要组件存在；`StepReactionLayout` 实际挂载；旧指标墙不存在。
- 产物按钮第一次点击无请求、第二次恰好一次请求、生成中不可重复、ready 执行另存。
- 实验计划模板版本快照不可变。
- NMR 旧数据兼容；绘图主题/日期可编辑并持久化。
- 所有新增远程接口通过 `cleanJson` 边界，不向客户端泄漏不可序列化对象。

### 6.3 Ketcher 专项验收

- 同时渲染 10 个不同结构，全部在限定时间内结束。
- 中间加入一个非法 SMILES，其他任务仍继续。
- 同一结构不同尺寸不会错误复用缩略图。
- 点击失败卡片可单独重试。
- 编辑保存后读取的是新结构，不使用旧缓存。
- 断网后安装版仍可打开编辑器、渲染结构。
- 路线总览和 NMR 页面使用同一稳定渲染能力。

## 7. Windows 打包指导

### 7.1 打包前提

- Windows 10/11 x64。
- Node.js `24.16.0` 或与发布清单一致的 Node 24。
- Corepack/pnpm 可用。
- Rust stable、MSVC C++ Build Tools、Tauri/NSIS 构建依赖可用。
- 发布签名需要 GitHub Secrets 或本地合法的代码签名证书；无证书只能生成内部验收候选包。
- 先完整阅读 `desktop/docs/packaging-pitfalls.md` 和 `desktop/docs/release-checklist.md`。

### 7.2 版本一致性

当前是 `0.4.0-rc.3`；下一候选通常应使用 `0.4.0-rc.4`，但最终版本以产品负责人确认为准。需要保持以下位置一致：

1. `package.json`
2. `desktop/package.json`
3. `desktop/src-tauri/Cargo.toml`
4. `desktop/src-tauri/tauri.conf.json`
5. `desktop/src-tauri/Cargo.lock` 中 `ibm-lab-desktop`
6. `desktop/docs/release-manifest.json` 的 `ibmLabAgent`

修改 `Cargo.toml` 后通过 Cargo 命令刷新锁文件，不要随意手改依赖锁。版本更新后检查旧候选号是否意外残留：

```powershell
rg -n '0\.4\.0-rc\.3|0\.3\.2-rc\.1' package.json desktop/package.json desktop/src-tauri/Cargo.toml desktop/src-tauri/Cargo.lock desktop/src-tauri/tauri.conf.json desktop/docs/release-manifest.json
```

发布清单中的 DSH、Node、Python、Origin MCP、Mnova MCP 和 MCP SDK 版本也必须与实际打包内容一致。

### 7.2.1 Windows 统一发布入口（取代旧 npm/npx 分步命令）

仓库使用 pnpm workspace，DSH 默认从根 `node_modules` 解析，旧 `runtime/launcher/node_modules` 仅作兼容回退。正式发布必须使用：

```powershell
Set-Location '<repository-root>'
pwsh -NoProfile -ExecutionPolicy Bypass -File '.\desktop\scripts\build-windows-release.ps1' -SourceRoot . -NodeExe (Get-Command node).Source
```

脚本统一执行测试、回归、预设导出检查、lint、增量资源准备、Web smoke、Tauri/NSIS 和精确安装包校验。默认拒绝脏工作树；`-AllowDirty` 只能产生不可发布诊断结果。

### 7.3 依赖与源码门禁

依赖必须按仓库锁文件预先安装，发布过程中不临时联网修改依赖。完整 DSH 不在根依赖时显式传 `-DshSource '<完整 DSH node_modules>'`。任何门禁失败均不得进入 NSIS 阶段。

### 7.4 运行时快照

`prepare-runtime.ps1` 具有独占锁，自动检测根 pnpm DSH，资源指纹未变化且快照完整时跳过删除/复制。源码 Ketcher 哈希引用会在删除旧快照前验证；需要排查缓存时使用 `-ForcePrepare`。禁止并发启动 prepare 或在生成的 resources 副本中热修源码。

### 7.5 构建 NSIS 安装包

统一脚本为每个阶段保存 stdout/stderr，并每 20 秒报告 PID、CPU、日志大小和耗时；prepare 默认上限 60 分钟，Tauri/NSIS 默认上限 120 分钟。超时只终止本轮进程树并保留日志。

正式发布禁止设置 `TAURI_CONFIG={"bundle":{"resources":[]}}`。增量加速依赖资源指纹不改动未变化快照和复用 Cargo target，不能以丢失安装资源换取速度。

### 7.6 精确选择并验证新安装包

不要使用 `Get-ChildItem ... | Select-Object -First 1`，因为目录内已有旧候选包。按确认的版本号精确匹配：

```powershell
$releaseVersion = '0.4.0-rc.4' # 示例；使用实际确认版本
$bundleDirectory = Resolve-Path 'desktop\src-tauri\target\release\bundle\nsis'
$installer = Get-ChildItem -LiteralPath $bundleDirectory -Filter '*.exe' |
  Where-Object { $_.Name -eq "iBM Lab Agent_${releaseVersion}_x64-setup.exe" }
if (@($installer).Count -ne 1) { throw "expected exactly one installer for $releaseVersion" }

Push-Location 'desktop'
& pwsh -NoProfile -ExecutionPolicy Bypass -File '.\scripts\verify-package.ps1' -InstallerPath $installer.FullName
if ($LASTEXITCODE -ne 0) { throw 'installer verification failed' }
Pop-Location

Get-FileHash -Algorithm SHA256 -LiteralPath $installer.FullName
Get-Item -LiteralPath $installer.FullName | Select-Object FullName,Length,LastWriteTime
```

当前 `verify-package.ps1 -InstallerPath` 主要检查文件存在和体积，不能代替包内内容检查。正式候选还应使用 7-Zip 列出安装包内容，确认至少包含：

- `node.exe`
- DSH 运行时
- `plugin/dsh-lab-agent/package.json`
- 新增的服务与模型文件
- `client/index.js`
- `client/assets/ketcher-standalone/index.html` 及其实际引用块
- 自包含 Python、Origin MCP、Mnova MCP 和 `bridge.qs`

### 7.7 安装版人工验收

使用干净 Windows 用户或虚拟机安装，不能只覆盖当前开发机旧安装。至少验证：

1. 首次启动能进入 DSH，第二次启动聚焦已有窗口。
2. 模型下拉可选择，不出现空列表或请求失败。
3. 课题列表正常，不出现 `client api: lab/projects_list failed: Failed to fetch`。
4. 日志没有插件未注册、重复 `labAgent` 服务、缺 `jszip/zod/fast-xml-parser/js-yaml` 等错误。
5. 合成工作台只显示三个主要组件，路线图可点选步骤。
6. Ketcher 连续渲染、失败重试和编辑保存正常，断网仍能使用。
7. CAS 及双源一致/冲突状态正确，冲突不会自动覆盖。
8. 事实核验完成前不能交给 Agent；完成后只能更新未确定项。
9. 用户可新建、完整编辑和锁定路线；锁定后不可原位修改。
10. 实验计划、精读报告、PPT 第一次点击不发送，第二次发送；完成后可另存正确格式。
11. NMR 显示结构、名称、CAS、氘代试剂；绘图主题和日期可编辑。
12. 关闭应用后端口释放，没有孤立 `node.exe`/`python.exe`。
13. `%LOCALAPPDATA%\iBM-Lab-Agent\logs` 不包含 API Key；启动失败页可以重试并查看日志。

建议特别检查：

```text
%LOCALAPPDATA%\iBM-Lab-Agent\logs\app.log
%LOCALAPPDATA%\iBM-Lab-Agent\logs\dsh.log
%LOCALAPPDATA%\iBM-Lab-Agent\logs\stderr.log
```
