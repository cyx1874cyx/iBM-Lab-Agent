# 0.4.x 三阶段版本更新：Agent 执行总交接

1. `0.4.0_COMPLETION_PLAN.md`：先完成 Ketcher、三组件、双源/CAS、截图审核和锁定基线。

## Agent 工作规则

- 源码真源为仓库根目录；`desktop/src-tauri/resources/plugin/dsh-lab-agent` 是生成快照，禁止把修复只写进快照。
- 开始每版前记录基线提交和工作树；发布构建必须来自干净提交。
- UI 存在不等于完成：必须验证远程接口、服务持久化、重启恢复和安装后行为。
- 每个需求至少具备单元/集成或浏览器测试；Ketcher、事实审核和产物状态机必须有浏览器级回归。
- 任一发布阻断失败时停止打包，不得仅凭 `node --test` 通过宣布完成。
- 每版完成后更新版本号、release manifest、变更说明、迁移说明、安装包 SHA256 和未完成项。

## Windows 推荐命令

在仓库根目录执行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\build-windows-release.ps1 `
  -SourceRoot . `
  -NodeExe (Get-Command node).Source
```

脚本默认执行源码测试、回归、导出检查、lint、增量资源准备、Web 冒烟、Tauri/NSIS 构建和安装包验证。日志位于 `desktop/.build/windows-release-<时间>/`。

常用诊断模式：

```powershell
# 只验证源码与打包资源，不生成安装包
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\build-windows-release.ps1 -SourceRoot . -SkipBuild -AllowDirty

# 只做秒级前置检查，不运行测试或复制资源
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\build-windows-release.ps1 -SourceRoot . -PreflightOnly -AllowDirty

# 明确强制重建资源快照
pwsh -NoProfile -ExecutionPolicy Bypass -File .\desktop\scripts\build-windows-release.ps1 -SourceRoot . -ForcePrepare
```

`-AllowDirty` 只允许诊断，生成报告会标记 `publishable=false`。不要同时运行多个发布脚本或单独并发运行 `prepare-runtime.ps1`。
