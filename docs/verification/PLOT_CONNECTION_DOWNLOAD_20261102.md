# Origin 连接诊断与原始数据下载

日期：2026-11-02。应用：iBM Lab。

- 绘图主界面和修改图片工具栏显示 Origin 状态。页面可见时每 5 秒检查现有 GUI 桥接，展开显示桥接版本、检查时间、响应耗时和失败原因，并支持立即检查。后台共享正在执行的检查，短时缓存结果；绘图任务期间的响应超时标为忙碌，避免直接误报断连。检查不启动或隐藏 Origin，不修改工程。
- 原始数据原来直接使用浏览器 Blob 下载，在桌面内嵌界面中不能可靠保存。绘图下载改用现有统一桌面保存接口；无桌面服务时保留浏览器下载。使用归档原始字节及原文件名，不导出转换后的 CSV 代替原始 Excel。

验收：20 项浏览器、服务及下载接口回归通过。涵盖界面断连/恢复、强制检查、共享和缓存探测、绘图忙碌，以及 CSV/Excel 文件经 HTTP 和原生保存通道的原始字节、哈希和文件名。原生保存通道使用传输桩检查，不将其视为系统保存对话框的视觉验收。

另通过实际运行时 `runPlotJob` 调用当前 Origin GUI 桥接成功，返回桥接版本 `0.1.4`、Origin 进程 ID `276`。未为断连测试关闭用户 Origin，断连与恢复场景由测试桩模拟。

构建与领域包检查通过，修改同步至开发版 Profile 和随包运行时；新后台接口需重启 iBM Lab 加载。

后续现场修复：诊断按钮移至右上角，与多面板排版同行。补齐 `plot_origin_connection` 的前端 Remote 描述符，解决 `ctx.remote.lab[method] is not a function`。此前界面测试直接替代调用函数，未覆盖实际前端描述符挂载；现浏览器用真实描述符约束调用，并检查按钮实际纵向位置一致，完成诊断、生成、编辑、保存和原始数据下载。接口扫描同时支持单引号与双引号，避免再次漏检；8 项相关回归通过。

严格依赖访问修复：诊断中直接读取 `ctx.ibmRuntime` 会因绘图记录服务未注入此可选服务而报错。与现有绘图调用保持一致，改为 `ctx.get('ibmRuntime')`，缺少运行环境时显示明确状态。回归增加禁止直接访问该属性的 Context 代理，以及运行服务缺失场景；不将运行服务改为绘图记录存储的必需依赖。
