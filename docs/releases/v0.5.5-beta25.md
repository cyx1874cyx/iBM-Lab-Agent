# v0.5.5-beta25 发布说明

## ScienceDirect 原生 PDF：保留失败证据并区分取数对象

beta24 的实机复测中，`lab_browser_download_viewer_pdf` 在 WebView2 会话里读取到 62,872 B，但文件不以 `%PDF-` 开头。自动归档正确拒绝了它；旧日志缺少请求目标和响应内容特征，无法判定这段数据来自 PDF 地址、出版社预览页还是验证页。

beta25 在同一 WebView2 会话内重新读取当前已确认的 PDF URL 时绕过缓存。`directPdfFetch` 日志现在记录脱敏后的目标 URL，`directPdfResponse` 记录 HTTP 状态、Content-Type、Content-Length 和网络错误。校验失败时，`directPdfInvalid` 还记录前 16 字节的十六进制与可打印字符，并把实际响应保存在任务暂存目录的 `.notpdf.bin` 文件。操作错误也返回这些诊断与文件路径，方便 Agent 区分问题；无效内容不会进入课题归档。

合成 Ctrl+S 仍已移除。读取失败会释放任务目标，立即提示用户在侧栏原生 PDF 查看器按 Ctrl+S；壳仍会捕获用户触发的下载并自动归档，无需回传路径。

## 验证边界

Node 单元/集成测试 759 项（757 通过、2 跳过），Windows Rust 测试 120 项（119 通过、1 忽略）。**绕过缓存能否让该 ScienceDirect PDF 自动下载，尚待安装包实机复测**。复测时检查 `directPdfFetch` 的脱敏目标、`directPdfResponse` 的状态和类型；失败时检查 `directPdfInvalid` 的前缀和 `.notpdf.bin`。只有任务状态为 `completed` 且课题文件存在，才可判定下载成功。
