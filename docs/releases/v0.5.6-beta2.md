# v0.5.6-beta2 发布说明

本版修复 beta1 文献捕获闭环中的归档冲突、关窗状态和体积上限不一致。CDP Fetch 与出版社下载事件两条已验证的正文来路保持不变。

- 捕获上限统一为 **250 MiB（262,144,000 字节）**：桌面壳、服务端校验、桥接配置及相关下载路径使用同一上限。超限返回 `too-large`。
- 条目已有同类型文件时，建任务前和最终落盘时都拒绝覆盖，返回 `already-archived`，并在捕获小球显示“已有文件”。beta2 暂不提供替换入口；旧版 `allowOverwrite` 标记也不能绕过保护。
- 同一条目、同一文件类别的并发归档串行处理；落盘采用同目录临时文件和不覆盖目标的硬链接。不同 PDF/SI 捕获分别写入 provenance 记录，不互相覆盖。
- 真正关闭文献浏览器时，壳释放内部 pending；服务端把已接管任务持久化为 `window-closed`。从未被浏览器接管的排队任务不会被误判为关窗失败。
- 手册、需求实施状态、出版社标定说明与实际行为同步。

验证：全套 Node 测试、Python 桥接测试、ESLint 和客户端产物一致性检查。Windows 安装包构建及真机浏览器验收结果见出包记录。

仍待真机确认：250 MiB 边界附近的峰值内存和耗时、各出版社的机构访问路径。逐社规则继续标为待验证。
