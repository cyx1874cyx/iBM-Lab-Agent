# v0.5.5-beta1 发布说明

发布日期：待定

## 主要更新

本版来自 0.5.4 的**真实试用复盘**：一位 Agent 用 0.5.4 完整跑了一遍「文献检索 → 精读 →
PPT 汇报」的真实任务，并交回了耗时/token 归因与七条问题。本版逐条修掉，并把「Agent 应该用
哪个运行时、怎么核对成品」从"靠猜"变成"可查询的事实源"。

---

### 1. Agent 运行时环境：优先用软件自带的，而不是宿主机的

试用现场的两条根因：① 桌面壳只导出了 `IBM_LAB_AGENT_BUNDLED_PYTHON`，没导出 node，子进程
PATH 里也只有 Python 目录 —— Agent 只能硬编码 `C:\Program Files\iBM Lab Agent\node\node.exe`；
② LibreOffice 的 user profile 落在 `%LOCALAPPDATA%\Temp`（桌面壳沙箱拒绝写）时**静默不产出
PDF**、退出码仍是 0，白耗好几轮才定位。

- **桌面壳**（`desktop/src-tauri/src/runtime/`）：子进程 PATH 现在预置捆绑 **Python 与 Node**
  两个目录；新增导出 `IBM_LAB_AGENT_BUNDLED_NODE`；`TMP`/`TEMP`/`TMPDIR` 全部指向工作区内的
  `.lab-tmp` 并预建（Python 的 `tempfile` 只在目录存在时才认 `TMPDIR`，否则静默回退 `/tmp`）。
- **统一解析器** `src/lab-runtime.js`：捆绑 → 本进程自身（DSH 就跑在壳启动的 node 上）→
  系统 PATH（需显式允许）。顺带修掉一个真实陷阱：`pythonCandidates` 的 `command` 是**数组**
  （Windows 的 `py -3.12` 是多 token 前缀），当字符串用会直接把数组当命令。
- **Agent 工具 `lab_runtime_env`** + preset 第 17 条：返回 python/node/soffice 的绝对路径、
  `argv` spawn 前缀、工作区临时目录、渲染助手与体检器的**绝对路径**，并要求"先问不要猜、
  不要硬编码安装路径、不要写相对路径（Agent 的 cwd 是课题工作区，不是插件安装目录）"。
- LibreOffice **不由本仓库捆绑**（解析链是"显式配置 → 典型安装路径 → PATH"，与应用内预览同源）；
  本版把 profile 固定到工作区，并把"退出码 0 但没产出文件"显式报错。

### 2. 核对成品：零视觉 token 的路径

试用现场最贵的开销是**逐页读图自查**（25 次 `read_image`，约 15 次可省）。

- **渲染助手** `scripts/render-deck.mjs`（+ `scripts/pptx/pdf_to_png.py`）：pptx/pdf → 逐页 PNG，
  默认再合成一张 **contact sheet**，一次读图看完整套版面；profile 固定在工作区；失败模式明确
  （不再有"静默不产出"）。
- **成品体检器** `scripts/pptx/inspect_deck.py`：一次给出每页字体三槽（`a:latin`/`a:ea`/`a:cs`）、
  最小显式字号、图片是否被拉伸、形状是否越界、占位符是否仍是提示文字、段落是否带项目符号。
  **这些都不需要读图** —— 视觉 token 只留给"版面好不好看"。
  实测 `deck6.pptx`：4 页、最小显式字号 20.0pt、error 0 / warning 0、每页
  `latin=Arial ea=微软雅黑 cs=Arial`；负例自证会失败（`--min-font-pt 30` → 11 error 退出 1）。

细节见 [`docs/AGENT_RUNTIME_ENVIRONMENT.md`](../AGENT_RUNTIME_ENVIRONMENT.md)。
