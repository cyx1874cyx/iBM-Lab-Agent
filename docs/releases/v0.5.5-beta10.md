# v0.5.5-beta10 发布说明

发布日期：2026-09-26

## 一、下载不再"抢跑"：等加载完成，而不是等第几次扫描

实测日志（beta9 运行中）：

```
13:23:37 navigation → www.science.org/doi/pdf/10.1126/science.aeg4791
13:23:38 automation: 已进入原生 PDF 预览器；可直接调用保存工具归档
13:24:37 downloadRequested → 同一个 PDF
13:24:37 error: 无法读取 WebVPN 下载文件: 系统找不到指定的文件 (os error 2)
13:24:37 downloadFinished success=false path=<unreported>
```

用户描述得很准：**预览器还在加载就触发了下载**，而且是在文献还没就绪时动手。根因是
自动化脚本用「第 2 次扫描」当触发条件（`attempts >= 2 && forceDownload(...)`），它
等价于一个约 1.5 秒的**固定延时**，与页面是否加载完毫无关系。

本版改为**事件驱动**：

- 新增 `documentLoaded()`（`readyState === 'complete'`）；
- 所有"动手"（点下载入口、强制下载、展开 SI）都必须在其为真之后；
- 未就绪（空白 / 还在 loading / 还没到 complete）只等待，并计入既有的 ~30 秒等待预算，
  超时才退回人工 —— 既不会抢跑，也不会永远卡住。

## 二、读文件按存在性重试

WebView2 报下载完成后，文件仍可能由下载进程延迟写出；原来紧接着 `fs::read` 就得到
`系统找不到指定的文件`，整次捕获失败。现在 `read_captured_file()` 按**存在性**轮询
（100ms 一次，最多 20 秒）：文件一出现就读，正常路径不引入任何额外延时。

## 三、捕获小球：队列可见、可逐条删除、下载完不消失

- **队列可视化**：小球里直接列出排队序列与每条的状态（排队中 / 进行中 / 已完成 /
  失败 / 已取消 / 已过期），正在跑的那条带 `▶`。
- **逐条删除**：每行一个 `×`，删的是**队列里的任务**（不影响正在跑的那条）。任务调度的
  真源在插件里，所以请求链路是「小球 → 壳 → Rust → 客户端 → 插件」；Rust **只接受当前
  队列快照里存在的 id**（页面是远端内容，不可信）。
- **下载完不消失**：结束后小球保留结果与队列，点一下才关闭；提示从 8 秒延长到 30 分钟，
  并且只要队列非空就继续显示。
- 数据来源：客户端每轮轮询本来就要读队列，顺手把快照交给壳（新增
  `webvpn_set_capture_queue` 命令），Rust 只做长度/条数清洗后存进会话状态。
