# v0.5.5-beta28 发布说明

发布日期：2026-09-29

## 主题：把"请求聚焦"变成"可确认的前台窗口"

β27 让原生 PDF 走 **WebView2 自带的"另存为"**（`ICoreWebView2_25` + `SaveAsUIShowing`），
保存结果由任务暂存文件的实际写入字节推进。这条路要求承载它的窗口**真的在前台**，
而之前的聚焦只做了"请求"，无法区分**已请求**与**已生效**。

本版补上：

- **`activate_capture_window`**：`show()` → `unminimize()` → `set_focus()`，
  **只在有捕获任务时**执行；Windows 拒绝后台进程抢前台时**记日志（`captureFocus`）而不判任务失败**——
  任务继续，Agent/用户从日志里看到真实情况，而不是因为一个显示问题把已布防的任务报成失败；
- **`focus_visible_browser`**：随后把焦点交给子 WebView，并**记录主窗口是否真的获得了焦点**，
  让"没生效"变得可见而不是静默；
- **侧栏由隐藏变可见时补一次焦点**：DSH 是在捕获命令返回之后才上报 tab 矩形的，
  第一次聚焦可能落在一个还没显示的子 WebView 上；但**后续的布局上报不会反复抢用户的焦点**。

## 真机验收

沿用 β27 的路线（issue beta26 的 DOI `10.1016/j.bios.2013.11.059`，文章页 `View PDF`）：

1. 调 `lab_browser_download_viewer_pdf` 后，日志应出现 `viewerNativeSave`；
2. 同时看 **`captureFocus`** 那行：应为"主窗口已处于前台，已请求文献浏览器焦点"；
   若为"系统未确认窗口位于前台"，那就是**焦点没拿到**——请把这行原文发我；
   这一版的意义正是让这种情况**可判别**，而不是继续猜；
3. 状态里 `progress.source` 为 `native-save`，字节数随任务文件增长 → 完成后 `captureCompleted`。

若仍失败，请保留 `viewerNativeSave` 与 `captureFocus` 两组日志原文。
