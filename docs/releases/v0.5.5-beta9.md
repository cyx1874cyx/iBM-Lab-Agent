# v0.5.5-beta9 发布说明

发布日期：2026-09-26

## 修掉的问题：原生 PDF 预览器里没法自动保存

beta8 之后抓取已经顺畅，用户报告的最后一步是：

> 点击 PDF 后是 PDF 的预览，但是没有了正常的上面的 bar，自动化操作没法点 bar 上的保存，
> 只能人工手动右键保存。

两件事要分开说清楚。

### 为什么预览时"没有上面那条 bar"

那条 bar 是 **WebView2 内置 PDF 查看器的工具栏**（页码、缩放、旋转、打印、保存图标），
它属于**浏览器 UI，不是网页 DOM**；而 WebView2 的原生查看器文档**不执行注入脚本**，
所以我们注入的标签页/地址栏那一层在里面根本不会渲染（这正是"bar 不见了"的原因），
自动化也没有任何 DOM 可以点击。

### 应用其实早就会自动存

`save_current_pdf` 用的是 WebView2 的 `ICoreWebView2_25::ShowSaveAsUI`，并且：

```rust
args.SetSaveAsFilePath(*path.as_ref().as_pcwstr())?;   // 直接给归档临时路径
args.SetAllowReplace(false)?;
args.SetSuppressDefaultDialog(true)?;                  // 不弹对话框
```

**它是"直接存到归档路径、不弹框"**，成功后走原有上传/归档链路 —— 用户不需要右键另存。

### 缺的是状态机这一步

进入原生 PDF 后，`on_page_load` 只做了页面位移，**没有把阶段切成 `manual`**，于是状态工具
继续返回 `wait-and-poll`，Agent 只会一直等，保存工具永远不会被调用。本版：

1. **PDF 文档加载完成即切 `manual`**，并记一条明确日志
   「已进入原生 PDF 预览器；可直接调用保存工具归档，无需右键另存」；
   状态因此返回 `nextAction=observe-or-save-pdf`，Agent 会去调
   `lab_browser_save_current_pdf`。
2. **状态文案指向保存工具**（`lib/tasks-tool.js`）：`manual` 阶段对 `kind=pdf` 明确写
   「已进入原生 PDF 预览器（查看器界面不是网页，注入的工具栏不在）：调用
   lab_browser_save_current_pdf 直接归档，无需右键另存」。
3. **PDF 端点识别放宽**：`is_pdf_document_url` 原来只认 `.pdf` 结尾，而 Science 的地址是
   `/doi/pdf/10.1126/…`、Elsevier 是 `/pdfft`、IEEE 是 `/stampPDF/getPDF.jsp`，都认不出来，
   所以 PDF 分支以前压根没触发。现在与页面脚本 `previewDownloadUrl()` 的判据对齐。
