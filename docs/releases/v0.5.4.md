### 1. Windows 捆绑 Python 3.11.9 → 3.12.10

- **动因**：`pptx-cli` 声明 `Requires-Python >=3.12`；顺带把两条线拉齐——Linux 安装器自
  0.3.x 起就是 `runtime/versions.env` 的 `PYTHON_VERSION=3.12.11`（uv 托管 CPython），
  此前 Windows 3.11 / Linux 3.12 属历史遗留。
- **改动 13 处**：`build-bundled-python.ps1` 的 `$Python='py -3.12'` 与拷贝清单
  `python311.dll`→`python312.dll`；`runtime/deps.rs` 的版本判定与 5 处用户可见文案；
  `desktop/docs/release-manifest.json`；桌面依赖面板基线文案；`src/python-env.js` 的候选
  序列（`py -3.12 → py -3 → python`）与区间提醒（`<3.12` 或 `>=3.13` 才 warn）；两个依赖锁；
  两个测试夹具；`docs/BUNDLED_PYTHON_HANDOFF.md` 新增 §9。
- **升级前尽调**（逐包查 PyPI 实际 wheel tag，不靠推断）：numpy/pandas/scipy/matplotlib/
  Pillow/lxml/cffi/PyYAML/pydantic-core/rpds-py 均有 `cp312-win_amd64`；`cryptography` 走
  `cp39-abi3`、`PyMuPDF` 走 `cp310-abi3`、`pypdfium2` 走 `py3-none-win_amd64`，abi3/纯二进制
  覆盖 3.12；`rdkit==2026.3.5`（Linux 线用）明确有 `cp312-cp312-win_amd64` 与
  `cp312-manylinux_2_28_x86_64`。**版本 pin 全部原样保留，不重新解析**，避免版本漂移扩大
  重验证面。
- **Windows 侧实测**：`py -3.12 -m pip install --dry-run -r requirements.lock` 全量解析通过
  （含 `pywin32-312-cp312-win_amd64`）；实建 dist 自检全过——`bundled python OK: 3.12.10`、
  markitdown 5 种格式、`origin-mcp 0.1.4`、`mnova-mcp 0.3.1` + `bridge.qs`；dist
  **401,951,264 B**（3.11 时 404,179,264 B，反而小 2 MB）。
- **长期成本（已登记）**：`requirements.lock` 的基准自此**有意**偏离 nature-skills 上游 CI
  （仍钉 3.11），上游每次 bump 需要手工重新推导。已写进 lock 头部注释与交接文档 §9。
- 注意：`runtime/versions.env` 整个文件进了 bundled-python 的构建指纹，因此**每次改版本号都会
  重建 dist**；pip 缓存热的机器上约 3 分钟（本次实测 173.9 s），冷缓存约 30 分钟。

### 2. PPT 模板：接入 pptx-cli，落地声明式规范 P1–P4

**架构定调：`pptx-cli` 负责「读模板 + 验输出」，我们自己的 `scripts/pptx/build_from_template.py`
负责「写内容 + 执行中文排版政策」。** 不换构建引擎，原因是核过 pptx-cli 1.3.5 源码后确认它
做不到本模板的三条硬需求：

1. 全包没有任何 `font.name=`/`font.size=`/对齐写入（只有粗体/斜体和行内 code 的 Courier New），
   `manifest` 里的 `allowed_formatting_overrides` 是死字段 —— 中文微软雅黑/英文 Arial/≥20 号
   这条政策它执行不了；
2. 纯文本路径不剥模板自带项目符号（`parse_plain_text_paragraphs` 给 `level=None`，
   `_apply_markdown_list_level` 直接 return），模板的 `a:buChar` 会原样留下；
3. 定位全程按 `placeholder_idx`，`guidance_text` 只用于容量提示 —— 提示文字优先定位是我们自己的
   实现（PowerPoint 会重排 `p:ph/@idx`）。
   另外它默认删掉未填充的非 title 占位符（`required = logical_name == "title"`），与本模板
   「留空但必须保留」的槽冲突。

#### P1 模板规范（manifest 作为唯一事实来源）

- 新增 `lib/pptx-manifest.js`：`python -m pptx_cli` 封装（`init` / `layouts` / `placeholders` /
  `theme` / `validate` / `manifest diff` / `doctor`）。JSON envelope 从 stdout 里找最后一个可解析
  对象并校验；退出码映射为 ok/validation/permission/conflict/io/internal，错误码前缀映射为
  kind + 排查建议；超时、非零退出、非 JSON、缺模块、无解释器**一律返回诊断对象，永不抛**。
  解释器走统一 resolver（显式传 venvPython，因为 Linux 线的 pptx-cli 在
  `$DSH_HOME/lab-agent/.venv`，只靠 PATH 上的 `python3` 找不到）。
- 新增 `src/ppt-slot-spec.js`：manifest → `slots.json`。**角色只按提示文字识别**；槽位到占位符
  三轮绑定（提示文字 → 结构兜底并记 `promptMismatch`=改名 → 缺失）；图注按图号区分
  （图 1/2/4 要、图 3 不要）。
- 新增 `src/pptx-xml.js`（只读扫版式/母版 XML，判断 `a:ea` 有无与 `a:buNone`/`a:buChar` 证据）、
  `src/ppt-template-guide.js`（导入时生成 `GUIDE.md`）。
- 模板导入在 `<templates>/<id>/v<版本>/` 下新增 `manifest/`（pptx-cli 产物）+ `slots.json` +
  `GUIDE.md` + `lint.json`，`parse.json` 原样保留。pptx-cli 不可用或失败时清理半成品目录、返回
  `manifestSource: "fallback"` + 原因，**导入照常成功**。

#### P2 模板体检（pptx-cli 的 `validate` 判不了的部分）

`lib/ppt-template-lint.js` + `node scripts/lint-ppt-template.mjs <id|目录> [--baseline|--write-slots|--json|--fail-on]`
（退出码 0/1/2），六类规则，每条标注构建器能否兜住（`compensated`）：

| 规则 | 严重度 | 兜得住？ |
|---|---|---|
| ① 静态层指纹/几何不一致、漂移、被删 | error | **兜不住** |
| ② 版式角色未知、槽位提示文字被改名/重复/为空、槽位键消失 | error | 部分 |
| ③ 字号低于下限 / 整条继承链无字号 | error | 兜得住 |
| ④ 静态中文缺 `a:ea`（会静默回退） | warning | 兜得住 |
| ⑤ 项目符号泄漏（mode=paragraph 的槽继承了母版 `a:buChar`） | error | 兜得住 |
| ⑥ 必填槽缺失 | error | **兜不住** |

门控语义：`ok = 不存在 compensated=false 的 error`，即 `summary.blocking` 才阻断门控，
`compensatedErrors` 只登记不阻断。新增 Agent 工具 `lab_ppt_template_lint`，
`lab_ppt_templates_get` 增加 `manifestSource`/槽位清单/`guidePath`/`lintSummary`。

#### P3 编译器（plan → 槽位填充指令）

- 新增 `lib/pptx-plan.js` + `node scripts/compile-ppt-plan.mjs --plan … --template … --out compiled.json`：
  按「layout id + 提示文字优先、idx 兜底」编译，编译期校验必填槽缺失、图片不存在、容量超限
  （CJK 1 字宽/西文 0.5 的粗估，仅 warning）。
- 构建器新增 `--compiled` 入口（与 `--plan` 互斥，校验 `kind`），编译期诊断并入符合性报告。
  **其现有排版政策行为一字未改**（字体三槽、字号下限 20、按页型开关分点、提示文字优先定位、
  静态层不动），只是多了一个输入来源。

#### P4 指导与自举

- `docs/PPT_TEMPLATE_SPEC.md`：面向用户与 Agent 的模板规范（槽位怎么命名、提示文字怎么写、
  静态层怎么放），并说明「加一个模板 = 丢一份 pptx → 生成 manifest + lint 报告 → 按报告改模板」，
  **不需要写代码**。
- `docs/PPT_TEMPLATE_PIPELINE_P14.md`：P1–P4 落地记录与已知限制。
- 导入时生成该模板的 `GUIDE.md`；`presets/lab-research/preset.patch.yml` 新增第 16 条
  「模板门控」规则。

#### 已知限制（不随本版解决）

1. 模板本身仍有 6 处待修（3 个图注槽 14pt、3 个图注槽缺「无项目符号」）与 9 处版式静态中文
   缺 `a:ea` —— 构建器兜住了，但模板没改；改模板会变更 sha256 并需重生成 manifest，交由模板
   所有者决定。
2. 真实模板与 deck 不入库（含校徽/logo，再分发未确认），端到端验证依赖开发机上的模板副本。
3. 不用 pptx-cli 的 `deck build`（见本节开头三条原因）。
4. 容量估算只是粗估，仅作 warning；`slots.json` 的手工修改暂无 schema 校验。
5. 模板版本升级沿用「同 id 不可重复导入」的既有规则，跨版本对比通过 `lint --baseline` 显式触发。
