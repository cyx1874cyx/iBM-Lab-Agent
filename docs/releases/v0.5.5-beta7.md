# v0.5.5-beta7 发布说明

发布日期：2026-09-25

## 修掉的问题：文献侧栏白屏（真正成因）

beta6 装上之后白屏依旧。这一版把成因定死了。

### 现场实测（beta6 运行中）

| 观测量 | 结果 |
| --- | --- |
| 侧栏子窗口 z 序 / `WS_VISIBLE` | 最上层 / true（没被隐藏、没被销毁、没被遮住） |
| 表面颜色数（主 WebView 作对照） | **1 种**（124 种） |
| document 是什么 | sessionStorage 里我们工具栏记录的是 `https://www.science.org/doi/10.1126/science.aeg4791`，标题是**真正的文章标题** |
| 注入的工具栏 | 已挂载（sessionStorage 有它写的 tab 状态） |
| 页面脚本 | 照常执行，定时器准点（12 秒 / 30 秒的上报都准时到） |

也就是说：**页面是真的、脚本是活的、工具栏也挂上了，但一个像素都不画。**

### 复现与定位

把应用实际注入的两段脚本（工具栏壳 + 自动扫描）在 Edge 里用**应用自己的 WebView2 profile 副本**
重放，就能稳定复现：

| 注入内容 | 结果 |
| --- | --- |
| 只有工具栏壳 | 正常（403 验证页、117 字、49 个元素、截图正常） |
| 工具栏壳 + 自动扫描（原样） | **元素数 0、截图超时** —— JS 还能 evaluate，但画不出任何一帧 |
| 工具栏壳 + 自动扫描（把 `signal()` 换成 `window.open`） | **恢复正常** |

二分结果指向唯一一句：

```js
const signal = (result) => { location.href = `ibm-webvpn://automation/${result}`; };
```

`location.href` 在 WebView2 里是一次**真实导航**。导航到一个没有注册的自定义协议会把载体
页面打进「文档还在、脚本还在跑、但首帧永远出不来」的状态——连我们注入的工具栏一起不显示，
因为首帧被阻塞。`window.open` 只触发宿主的新窗口请求，**当前文档完全不受影响**；实测它不需要
用户手势、也不会被弹窗拦截（会真的创建一个新 target，宿主一律拒绝即可）。

beta4 之所以"看起来正常"，是因为它的扫描在点击/验证处会 `clearInterval` 停掉，触发这句导航的
次数和时机不同；beta5 起改为"验证期间不停扫描"，这句导航就落在页面还在加载的窗口里，问题才
稳定暴露出来。

### 本版改动

1. **内部命令一律不再走导航**：工具栏壳新增 `notifyShell(target)`，自动扫描的 `signal(result)`
   同样改用 `window.open`；`session/ready`、`close`、`cancel-capture`、`offset-reverted`
   四个命令一并改掉（同一个隐患类）。
2. **Rust 侧统一处理**：抽出 `handle_internal_command(app, url)`，由 `on_new_window`（主路径）
   与 `on_navigation`（兜底）共同调用；非 http(s) 的其它弹窗（`about:blank` 等）仍按原逻辑拒绝。
3. 回归护栏（单测）：注入脚本里不得再出现 `location.href = 'ibm-webvpn…'`，必须走 `window.open`；
   `on_new_window` 必须处理内部命令。

beta6 的修复全部保留：工具栏立即挂载并重试、Cloudflare 验证页按验证处理、加载中/空白文档不消耗
尝试次数、页面位移只在确证顶层文档是 PDF 时打开。
