# v0.5.5-beta2 发布说明

发布日期：2026-09-25

## 主要更新

**渲染助手改用 DSH 自带的 LibreOffice —— 用户不再需要自己装 LibreOffice。**

0.5.5-beta1 把"Office 渲染依赖宿主安装 LibreOffice"写进了已知限制，并预估"要自包含得自己打进包
（+300 MB 量级）"。查证后发现 **DSH 早就把它带上了**，只是我们没接：

| 层 | 包 | 体积 |
|---|---|---|
| 预览 UI（右侧栏 document tab） | `dsh-client-ui-sidebar-documentpreview` | 14.6 MB |
| 转换服务（服务名 `officeToPdf`，带界队列 + 缓存） | `dsh-office-to-pdf` | 112 KB |
| 引擎包装（`discoverRuntime()` / `createConverter()` / CLI） | `libreoffice-kit` | 323 KB |
| 引擎本体 | `libreoffice-kit-win32-x64`（Windows，native）<br>`libreoffice-kit-wasm`（Linux，WebAssembly） | **341 MB** / **186 MB** |

它由 `dsh-web-app/cordis.patch.yml` 的两行挂载（`office-to-pdf`、`ui-sidebar-documentpreview`），
而我们的 profile 本来就包含 `dsh-web-app`；安装树里的位置是
`resources/dsh/node_modules/@deepseek-ai/…`，正是 `DSH_HARNESS_NODE_MODULES` 指向处。

### 改动

- `scripts/render-deck.mjs`：**优先**调用 kit CLI 的 `render` 子命令
  （`render --input… --output-dir… --pages… --dpi…`，内部是 LibreOffice + pdfium），
  宿主 `soffice` + PyMuPDF 降为**兜底**路径（`--no-kit` 或 `IBM_LAB_AGENT_OFFICE_KIT=off`）。
  由此我们不再需要自己解析宿主 soffice，也不再需要 PyMuPDF 做栅格化。
- 白拿两项能力：`missingFonts`（本机缺字体告警，直接命中"字体静默回退"那类问题）与
  `backend: native|wasm`（渲染后端可追溯）。
- `scripts/pptx/pdf_to_png.py`：新增 `--png-dir` 模式（kit 已经出好逐页 PNG，这一模式只负责拼
  contact sheet）。
- preset 第 17 条与 `docs/AGENT_RUNTIME_ENVIRONMENT.md` §3.3/§5 同步更新，§5 里那条
  "LibreOffice 由宿主机提供"的限制被更正。

### 实测

| 环境 | 路径 | 结果 |
|---|---|---|
| Windows | kit（**native** 后端） | 5 页 + contact sheet，**3.6 s**，无缺字体告警 |
| WSL | kit（**wasm** 后端） | 4 页 + contact sheet，**4.9 s**，报缺 `微软雅黑`/`Arial` |
| Windows | `--no-kit` 兜底（宿主 soffice + PyMuPDF） | 5 页 + contact sheet，2.7 s |

单元测试 7/7（`parseArgv` / `expandPages` / `resolveOfficeKit` 的显式关闭与真实解析）。

### 一处必须记住的渲染差异（已写进助手输出、preset 与文档）

kit 渲染会在**图片占位符**上画一行英文 `Double-click to add an image`，而同一份 deck 在宿主
LibreOffice 下不显示这行。三方核对确认 **deck 本身没有问题**：包内 `ppt/media/*` 与
`r:embed` 关系齐全、python-pptx 读到的图片几何正确、`inspect_deck.py` 的 XML 结论是 0 error，
且 contain 修复前后的 deck 表现一致。因此结论是"渲染器自带的占位提示"，并在助手输出里明确
**判断图是否插入一律以 `inspect_deck.py` 为准**，避免 Agent 据此误判"图没插进去"。

### 仍未做

- `lib/office-preview.js`（`/api/lab-artifacts` 的产物预览）仍走宿主 soffice 解析链；下一步应改用
  DSH 的 `ctx.officeToPdf` 服务（白拿它的界队列、缓存与输入上限校验），已记进 §5。
- `dsh-skill-office` 带的 Word/PPT/Excel **结构检查**尚未评估，可能替掉我们自写的一部分 PPTX 体检。
