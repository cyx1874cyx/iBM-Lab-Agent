# v0.5.5-beta8 发布说明

发布日期：2026-09-25

## 修掉的问题：状态卡在「等待自动验证」

beta7 之后白屏确实好了 —— 实测截屏里侧栏正常渲染出 Science 文章页，我们自己的工具栏
（标签页、地址栏、前进/后退）和捕获小球都在。但状态被卡住：

```
[01:12:21] webviewCreated → doi.org → www.science.org/doi/10.1126/science.aeg4791
[01:12:26] automation: 出版社页面正在验证访问；捕获有效，通过后自动继续查找入口
状态: armed / waiting-download / "正在等待页面自动验证；通过后继续查找下载入口"
nextAction: wait-and-poll （此后日志再无新行）
```

而用户看到的页面**根本不是验证页**，是一篇正常加载完的文章页。

### 根因：验证页误判（beta6 引入）

Beta6 为了识别 Cloudflare 插页，把下面这些标记也当成了"这是验证页"的判据：

```js
'script[src*="challenge-platform"]',
'script[src*="challenges.cloudflare.com"]',
'[class*="cf-chl"]', ...
```

但 **Cloudflare 会给所有受保护页面注入 `challenge-platform` 脚本**，普通文章页同样带着它。
于是文章页被判成验证页 → 扫描器每次都在验证分支 `return`、**永远不去找下载入口** →
任务卡死在 `wait-and-poll`。这与"页面看起来不是验证页、状态却说在验证"完全一致。

### 本版改动

1. **验证判定收紧为"确认是挑战"**，而不是"存在挑战脚本"：
   - 挑战插页**标题**（`请稍候…` / `Just a moment…` / `Attention Required` / `Checking your browser`）→ 验证；
   - **文章页优先**：有 `citation_doi` / `citation_title` / `dc.identifier` 元数据、或正文超过
     1200 字时，直接判定**不是**验证页；
   - 其余情况只认**可见的**验证组件（Turnstile 输入框、挑战表单/iframe，且尺寸大于 40×40），
     纯脚本存在不再算数。
2. **状态可执行化**：验证阶段返回 `nextAction=complete-verification`，文案改成
   「出版社页面要求人机验证：请在软件侧栏点一下「请验证您是真人」，通过后会自动继续查找
   下载入口」；侧栏小球文案同步为「需要人机验证：请在页面点一下验证框」。
3. **预设指令纠正**：原来的指令写着「verification 表示页面正在自动验证……不要让用户手动
   点击」，这是把"验证会自己过"当成了前提；现在明确要求把「请点一下验证框」告诉用户，
   并继续查询状态等待其完成，不要自行取消或反复重开页面。
4. **顺带修掉 `lab_browser_operation_status` 的 `value is not lossless JSON`**：该工具直接返回
   `{ result, error }`，操作尚未结束时这两个字段是 `undefined`，不是 lossless JSON；
   现在与其他工具一样过 `cleanJson`（`enqueueBrowserOperation` 与取消工具一并加固）。
