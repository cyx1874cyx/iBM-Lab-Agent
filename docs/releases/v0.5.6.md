# v0.5.6 发布说明

发布日期：2026-09-29

> **这是 0.5.4 之后的第一个正式版本**（`betaN` 编号到此结束）。

## 主题：让软件内浏览器变得可读——对人，也对 Agent

**PDF 响应层截取工作已暂停**。这一版不再在"怎么把 PDF 字节抠出来"上继续叠加机制，
而是先把**浏览器本身**做清楚：界面收敛、状态可诊断、页面类型可判定。

### 1. 界面：一个导航栏 + 一个浏览区

| 改动 | 之前 | 现在 |
|---|---|---|
| 页面里的标签栏 | 我们注入的壳里又画了一层标签栏（与宿主重复） | **移除**，只保留导航栏 |
| 导航栏高度 | 76 px | **42 px** |
| 收起后的把手 | 一枚固定在左上角、会占住页面的"展开工具栏" | 小尺寸 **"导航栏 ⌄"**，且**每次重新挂载都会隐藏**，不再无故占位；收起后宿主高度归零，不再挡点击 |
| 归档动作 | 右下角常驻浮层 | 移到**浏览区底部**，且**只在下载任务进行时**出现（`pdf`/`si` 且有 pending 任务，排除 `completed`/`idle`） |

### 2. Agent 侧：只读的浏览器调试快照 `lab_browser_debug`

页面类型不明、跳转结果不确定时（典型如：停在验证页、进了独立查看器、PDF 文档壳），
原本只能靠猜。现在一次调用拿到：

- **主文档状态**：`host` / `documentType` / `httpStatus` / `readyState` / `contentLength` / `pageSeq`；
- **最近 24 条事件**（导航、下载请求/完成、错误……）；
- **WebView2 CDP Target 清单**：每个目标的 `type` / `host` / `pdfViewer` / `attached`。

用途就是**区分"这是 PDF 文档、HTML 验证页，还是独立查看器目标"**。

**边界（有意收窄）**：不返回 Cookie、不返回原始请求 URL、不返回响应体。
Target 清单只给 host；事件里的 URL 与日志走**同一套脱敏**（`redact_for_log`）。
预设已加一句：页面类型或跳转结果不明时先调它；链路规格书也登记了这个工具。

### 3. 明确没做（本版范围之外）

- **PDF 字节截取的遗留问题**：响应层截取（含分段装配）与查看器保存两条路都**暂停**，
  `lab_browser_download_viewer_pdf` 仍可用，但**未在本版做新的实机验证**；
- **iWAN 真机视觉验收未做**：导航栏尺寸、归档按钮位置、收起把手都只经过代码与单测，
  **没有在你的 iWAN 页面上目视确认**；
- 八家出版社的机构会话标定仍全部为 `pending`。

## 安装后建议确认的三件事

1. 打开文献浏览器：应只有**一条 42 px 导航栏**，页面里没有第二层标签栏；
2. 点收起：把手是小小的"导航栏 ⌄"，**不遮挡页面内容**；再点可展开；
3. 发起一次下载任务：**归档按钮出现在浏览区底部**，任务结束后消失；
   期间可调 `lab_browser_debug` 看当前页面类型判定。
