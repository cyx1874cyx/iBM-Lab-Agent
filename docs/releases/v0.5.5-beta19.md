# v0.5.5-beta19 发布说明

发布日期：2026-09-28

## 主题：壳内自动点击彻底移除，出版社知识交给 Skill

这一版把「谁来找下载入口」这件事彻底定了：**只有 Agent**。壳里那套 `PUBLISHER_DOWNLOAD_AUTOMATION`
（入口评分、扫描循环、Wiley 两段流程、验证页信号）连同 `automate` / `pending_automation`
/ 内部 `automation` 命令 / `mode=auto` 的整条接线一起删除，**八项只覆盖它的测试也随之删除**。
历史任务行仍能解析（schema 保留 `mode=auto`），新任务一律记 `ai`。

这不是"少做一件事"，而是消除一条长期存在的**第二套决策路径**：它自己猜入口、自己点、
猜错时把状态说成"正在查找入口"，而 Agent 只能在旁边等。过去几版里最难定位的几个现场
（"自动化识别不了入口""保存支路无元素""验证页被当成普通页"）都出自那条路径。

### 1. 出版社知识变成了 Skill

新增 `skills/publisher-download/`：

- `SKILL.md`：闭环怎么走、`nextAction` 每个取值该做什么、失败怎么记录、什么算成功
  （只有 `completed` 且文件已登记）；
- `references/publishers.md`：逐社的 DOI 前缀、页面入口措辞、预览行为，以及**明确标注
  「待测」**——"表中'待测'是提示，不是已经验证的选择器"，并写明"页面证据与规则冲突时
  以页面观察和任务状态为准"。

装载方式刻意与 Nature 那棵树分开：

```yaml
- id: lab-publisher-skill-filesystem
  name: '@deepseek-ai/dsh-skill-filesystem'
  config:
    providerName: lab-publisher
    includeDefaultRoots: false
    customSkillDirs: [profiles/ibm-lab/node_modules/dsh-lab-agent/skills]
```

第一方指引不再和 pinned 的第三方 skill 树及其版本登记纠缠。`skills` 也加入了
`prepare-runtime.ps1` 的插件拷贝清单与 `package.json` 的 `files`，**确认随安装包一起发**。

### 2. 观察结果更好用

`lab_browser_observe` 不再按 DOM 前 30 条截断，而是**按优先级取 30 条**：
视口内的下载类控件 → 视口外的下载类控件 → 视口内的普通控件；每条带 `inViewport`，
并返回 `candidateCount` / `truncated`。同时开始遍历**同源 iframe**（跨源由 try/catch 挡住）。

### 3. 新状态 `save-from-viewer`

`nextAction` 增加一个取值：**原生 PDF 已经显示、但没有采到完整载荷**时，
提示调用一次 `lab_browser_save_current_pdf` 尝试让查看器保存——**成功判据仍然是
`completed`**（`saveReady` 此时为 false）。这补上了"Science 这类拿不到响应体的站点"
在「没有可验证备用入口」和「直接放弃」之间的中间选项。

### 4. 捕获语义写进了共享 spec

`capture-spec.json`（两份镜像）新增 `_captureSemantics`，把三件事写死：
`documentType=application/pdf` 只说明查看器加载了 PDF 响应、**不代表已捕获**；
捕获开始于 WebView2 下载事件或**完整的非 206 application/pdf 响应体**；
只有**校验通过的上传 + 条目登记**才算完成。

## 出包时的两处审查修正

1. **删脚本同时删掉了一个状态的唯一生产者**：`automationStage=verification` 以前由被删的脚本
   上报（Cloudflare 一类验证页），现在没有任何地方会设置它 → `nextAction=complete-verification`
   不会出现。代码不动（状态留着，将来恢复检测仍可用），但**预设与 Skill 的指引补上了
   "或你自己从 observe 的页面文本看出这是验证页"**——否则 Agent 会在验证页上一直点到耗尽重试。
2. **Skill 里指向 `docs/` 的路径在安装包里不存在**（`docs/` 不随插件发布）：改成说明标定表是
   仓库提交记录、运行时的规则表就是 `references/publishers.md`。

## 真机验收

1. **入口由 Agent 找**：发起一次正文下载，确认**没有**任何自动点击发生，`observe` 返回的候选
   带 `inViewport`/`candidateCount`；`status` 的 `nextAction` 是 `observe-or-click`。
2. **Skill 可见**：新会话里 `publisher-download` 应出现在 skill 目录中（`skill-discovery` 已断言，
   真机确认它在安装包内可加载）。
3. **原生 PDF 中间态**：进原生查看器后若载荷没采到，状态应给 `save-from-viewer`，
   调一次保存后仍以 `completed` 为成功判据。
4. **验证页**：遇到 Cloudflare 一类页面时，Agent 应停止点击并请你去侧栏完成（不再有脚本信号，
   由它从页面文本判断）。

**仍未验证**：Science 的入口/访问模式与 SI 只有用户口述成功（未提供 URL 与访问模式），
其余七家的机构会话、以及所有 SI 通道仍是 `pending`——**不要把"待测"当成已支持**。
