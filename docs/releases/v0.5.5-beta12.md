# v0.5.5-beta12 发布说明

发布日期：2026-09-27

## 主题：把文献浏览器的主动权交给 AI

旧形状是「壳内脚本自己猜着点 + Agent 调状态工具等结果」。现在默认反过来：**页面由 Agent
直接驱动**——自己看页面、自己点、自己等、自己保存；壳内脚本退化为可选快路径。

### 1. `mode`：默认 `ai`，不再抢着点

`lab_publisher_browser_download` 新增 `mode`：

| 值 | 行为 |
|---|---|
| `ai`（**默认**） | 只打开出版社页面并布防捕获；**不注入自动点击脚本**，页面由 Agent 操作 |
| `auto` | 壳内脚本按老规则自动找入口并点击；失败后 Agent 仍可接管（省事的快路径） |

实现上复用了既有开关：`pending_automate=false` 时 `pending_automation()` 本来就不会注入脚本，
所以 `mode=ai` 是"少做一件事"，不是新机制。任务记录里新增 `mode` 字段（schema 同步，否则会被
Zod 静默剥离），客户端领取令牌时按 `claimedTask.mode === "auto"` 决定 `automate`。

**这同时化解了 issue.md 的 B1/O2/B2**：脚本"识别不出版社入口"不再卡住流程——入口由模型自己从
页面里挑，而候选带 `target`/`file`（beta11 加的），Science 那三个同名 `DOWNLOAD` 能靠
`…_sm.pdf` 与 `…tables_s1_to_s6.zip` 区分。

### 2. `lab_browser_observe` 能真正"看到页面"

- 新增 `scope`：`all`（AI 主导推荐）返回**整页可见可交互元素**；`download`（旧行为）只看下载入口。
- 观察结果新增页面摘要：`title` / `url`(去查询串) / `readyState` / **可见文本前 1200 字** /
  滚动位置。模型因此能判断"这是文章页、验证页还是 PDF 预览器"。
- 元素引用仍是短期 + 与页面 URL 绑定（页面一变即失效），不暴露选择器。

### 3. `lab_browser_wait`：等页面变化，不要空转轮询

新工具：等阶段 / 页面 / 已下载字节 / 任务状态发生变化，或超时（默认 8 秒，上限 20 秒），
然后返回最新状态。点击入口后用它等页面响应，不必反复调下载状态。

### 4. 预设指引重写

原来的指引是"下载后持续轮询状态，脚本失败才去观察"；现在是
**observe(scope=all) → click → wait → 再 observe**，并说明 `mode=auto` 只是快路径、
人机验证必须由用户点、正文落到原生 PDF 时调 `lab_browser_save_current_pdf`。

## 本版**未**做（下一步）

**动作延迟**：浏览器的 observe/click/save 仍要等客户端 1.8 秒的轮询节拍去"领取"操作
（`client/src/components-literature.js` 的 `setTimeout(poll, 1800)`）。计划改成
`browser_operation_claim` 长轮询 + 专门的即时动作循环，把每个动作从"最多 1.8 秒"降到毫秒级。
本轮先把"AI 有主动权 + 不盲轮询"落地，延迟单独一轮做，避免同时改两处难以归因。
