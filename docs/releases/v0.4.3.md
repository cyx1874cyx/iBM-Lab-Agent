### 2.1 0.1.5 的服务面变化（本次迁移依据）

在 `0.1.5-rc.1` 安装树中实测到的服务注册者：

| 服务名 | 注册方 | 用途 |
|---|---|---|
| `sessions` | `@deepseek-ai/dsh-session` | 会话数据（仍存在） |
| `workspaces` | `@deepseek-ai/dsh-api-workspace-controller` | 工作区增删改查（仍存在） |
| `uiWorkspace` | `@deepseek-ai/dsh-client-ui-workspace` | **新增**：`connectWorkspace` / `openSession` |
| `uiSession` | `@deepseek-ai/dsh-client-ui-session` | 会话 UI 状态 |

因此客户端把 `ctx.sessions.open(...)` 改为 `ctx.uiWorkspace.openSession(...)`、
`ctx.workspaces.connectWorkspace(...)` 改为 `ctx.uiWorkspace.connectWorkspace(...)`，
并在 `ctx.inject([...])` 中显式加入 `"uiWorkspace"`。`sessions` / `workspaces` 仍在注入面上，
因为它们仍分别承担会话数据与工作区管理。

## 4. 本版本修复

1. **客户端 DSH 0.1.5 服务迁移**：`client/src/apply.js` / `client/index.js` 迁移到 `uiWorkspace`。
2. **注入面断言同步**（`tests/unit/harness-surface.test.mjs`）：此前套件为 356 项 / 354 通过，
   失败的两项均为注入面断言未随客户端改动更新（`:281` 正则、`:356` `deepStrictEqual`）。
   现已同步 `"uiWorkspace"`，套件转全绿。
3. **Windows 上 Harness 定位失败**（`src/harness-root.js`）：原实现只用 `which` 查 PATH，
   而 Windows 无 `which`，因此在未设置 `DSH_HARNESS_NODE_MODULES` 的 Windows 环境里
   `harness-pin` 回归用例与 `scripts/dev-link.mjs` 必然定位失败。现改为：
   - win32 使用 `where`，POSIX 仍用 `which`；
   - 追加 npm 全局 shim 布局（`%APPDATA%\npm\dsh.cmd` → `%APPDATA%\npm\node_modules`）；
   - 追加回退：直接解析本插件自身依赖到的 `@deepseek-ai/dsh`，取其 `node_modules`。
   修复后 `harness-pin` 在未设环境变量的 Windows 上通过（实测 15 packages match）。
4. **`.gitignore`**：`.tmp-*.json` 放宽为 `.tmp-*`，避免升级/排查用的临时日志与探针脚本入库。

## 6. 已知遗留与注意事项

- **子包的 npm `latest` tag 陈旧**（上游问题）：`@deepseek-ai/dsh-base` 的 `latest` 仍指向
  `0.0.1-rc.1`、`@deepseek-ai/dsh-agent-loop` 为 `0.1.0-rc.6`，只有 meta 包
  `@deepseek-ai/dsh` 的 `latest` 指向 `0.1.5-rc.1`。安装子包务必用精确版本或 `next`。
- **上游 git tag 交叉核验受限**：`api.github.com/repos/deepseek-ai/deepseek-harness` 匿名访问
  返回 403，本文"最新版本"的判据是 npm registry 的已发布版本，不含未发布/内部构建。
- **`docs/VERSIONING.md` 第 1 节仍写着 `0.1.1-rc.2`**，属历史文本，未随本次升级更新；
  权威版本以 `harness.lock.json` 与 `runtime/versions.env` 为准。
