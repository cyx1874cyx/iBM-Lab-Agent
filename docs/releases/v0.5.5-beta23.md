# v0.5.5-beta23 发布说明

发布日期：2026-09-28

## 主题：让 Ctrl+S 真的送达，并给人机验证补上生产者

### 1. 焦点：上一版只是"请求"聚焦，并没有真的把窗口拿到前台

β22 的路径是「Tauri `set_focus()` → 只要前台窗口属于本进程就发键」。但 **Windows 有前台锁**：
后台窗口调用 `set_focus` 往往仍是后台状态，于是只判断"本进程有前台窗口"是不够的 ——
按键可能落在没有意义的地方。现在：

- `main.show()` → `main.unminimize()` → **`SetForegroundWindow(hwnd)`** → 再给子 WebView 焦点；
- 判定收紧为「前台窗口**就是主窗口**」（`foreground == hwnd`），10 次 × 50 ms 重试；
- 每个失败信息都**自带人工兜底**："请在侧栏原生 PDF 查看器按 Ctrl+S，下载会自动捕获并归档，无需回传路径"。

### 2. 等待有界：12 秒内没产生下载就早退

Ctrl+S 之后如果既没有 `DownloadEvent`、也没有认领下载、目标文件还是 0 字节，
现在 **12 秒**就返回：

```
原生 PDF 查看器保存指令未触发下载；请在侧栏点击 PDF 页面并按 Ctrl+S，壳会自动捕获归档，无需回传路径
```

不再空等满 100 秒（那个上限只留给**已经开始**的下载/上传）。

### 3. 人机验证重新有了生产者（补上 β19 移除脚本时留下的缺口）

β19 把壳内自动脚本删掉后，`automationStage=verification` **再没有任何地方会设置**，
`complete-verification` 成了永远不会出现的状态（当时我在交接里标了这一点）。现在补上：

- `observe` 会检查页面标题与文本里的挑战特征（`are you a robot` / `verify you are human` /
  `验证您是人类` / Cloudflare 的 `just a moment` + `checking your browser` 等）；
- 命中时设置 `automation_stage=verification`，在观察结果里返回
  **`verificationRequired=true` 并清空 `candidates`**——Agent 不会去点验证控件；
- 验证未通过期间 `click` 会被拒绝，并明确要求由用户在侧栏完成；
- 插件侧据此给出 `complete-verification` + `requiresUserAction` 与问句。

### 4. 顺带：产物卫生与结果语义

- 归档成功后**删掉该任务的响应层缓存**；识别出 HTML 壳时立即删除；
  并做一次**范围收窄**的清扫：只删旧的（≥5 分钟）、小的（≤4 KiB）、
  **明确以 `<!doctype html`/`<html` 开头**的 `*.payload.pdf`——就是一直堆在
  `webvpn-downloads` 里那些 348 字节空壳。清扫**只枚举任务自己的捕获目录**。
- 下载工具返回新增 `code` 与 `taskCreated`（`webvpn-login-required` / `task-created`），
  渲染文案明确写"**尚未创建下载任务**"，避免把"没建任务"误读成"已排队"。

## 真机验收

1. **原生查看器自动保存**：进 PDF → 调保存 → 日志里应出现 `downloadRequested`（目标为任务暂存路径）
   紧跟 `captureCompleted`。若 12 秒内没动静，应看到"保存指令未触发下载"的明确原因，而不是干等。
2. **人工兜底**：自行在侧栏 PDF 上按 Ctrl+S，同样应被捕获归档。
3. **人机验证**（若遇到 Cloudflare 一类页面）：`observe` 应返回 `verificationRequired=true`
   且没有候选元素；状态应给 `complete-verification` 并请你完成验证。
