# v0.5.5-beta16 发布说明

发布日期：2026-09-27

## 主题：一个崩溃 + 一条被信错的"完成"信号

两个现场问题，都来自 beta15。

### bug1｜一进原生 PDF 页就闪退（`ibm-lab-desktop has stopped working`）

根因是**双重释放**。我把 PDF 响应流封送到工作线程时这样写：

```rust
let stream = CoGetInterfaceAndReleaseStream(&marshaled)?;   // ← 这个调用会释放传入的流
// mangled: marshaled 在作用域结束时又被 Rust Drop 一次 → 同一个流 Release 两次
```

微软文档写得很明确（[CoGetInterfaceAndReleaseStream](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-cogetinterfaceandreleasestream)）：

> **Releases the stream pointer. Even if the unmarshaling fails, the stream is still released.**

引用计数下溢 → 堆损坏 → 进程消失，而且**恰好发生在 PDF 响应到达、工作线程启动的那一刻**
（与"进入 PDF 页就崩"的现象一致）。现在用 `ManuallyDrop` 把生命周期完全交给那个 API。

另外：封送失败时的退化路径是"在 UI 线程上读"，原来可以占到 180 秒 —— 现在封顶 20 秒，
宁可少拿字节也不把界面冻住几分钟。

### bug2｜`issue-shell-pdf-payload-judgement.md`：B1 / B2 / B5

**B1【严重】"收满"判据失真。** 完整性曾经有**两个互相打架的定义**：

- 状态上报：读到这一次响应的 `Content-Length` 就算完整；
- 归档校验：要求尾部有 `%%EOF`。

浏览器的 PDF 查看器用 **Range 分段取数**，第一段常常正好 256 KiB —— 于是分段满足了前者，
状态喊 `save-pdf-ready`、`percent: 100`、`totalBytes: 262144`，而归档照规矩拒收，
调用方被自己的信号骗去归档半个文件。现在：

- 完整性**只有一个判据** `payload_is_whole(bytes, declared_total)`：`%PDF-` 头 ∧ `%%EOF` 尾
  ∧（声明总长已知时）收满。状态上报与归档校验共用它。
- **分段响应（206 / `Content-Range`）一律不进入载荷路径**，并留下日志行——宁可不提供保存
  支路，也不给一个假的完成信号。
- `progress` 增加 `declaredTotalBytes`（显式说明"这是声明的文件总长"）与 `idleSeconds`。
- `percent` 恢复真实比例（不再恒为 100）。

**关于报告建议的"且静默 10–15 秒无增长"**：没有采纳。`%%EOF` 是比"静默"更强的**正向证明**
（PDF 规范要求文件以它结束），而静默等待会让每一次保存都白等十几秒。判据已按"正向证明"
原则重写，这一点在交接文档里写明了理由。

**B2【严重】文件完整却报 `failed`。** `fail_pending_download` 现在**先验产物**：盘上文件是
完整 PDF（`%PDF-` 头 + `%%EOF`）→ **归档它**，不报失败；确实不完整 → 失败，但
**保留成 `*-未归档.pdf`**（B5）并把路径写进失败原因。以前失败会把用户的完整文件删掉，
那次没丢件纯属磁盘上恰好还有一份更早的副本。

**B5【中】** 终态任务（`orphaned`/`failed`/`stalled`…）**不再占用队列位次**——它们仍然
出现在 `capture_list` 里作为历史记录，但"队列第 2 位"不再由死任务占着。

## 真机验收

1. **进原生 PDF 页不该再崩**（bug1）。这是本版第一优先，请先确认这一条。
2. 慢速网络上观察 `progress`：`percent` 应逐次逼近 100 而不是一开始就 100；
   `declaredTotalBytes` 应是 2.6 MB 量级而不是 256 KB。
3. 若某个入口只有分段响应，状态里应出现"跳过 PDF 分段响应"的记录，
   并且**不再出现** `save-pdf-ready`（宁可没有保存支路，也不给假信号）。
