# v0.5.5-beta11 发布说明

发布日期：2026-09-27

本版处理 beta10 实测反馈的三处：两处 bug + 应用内 Agent 提交的 issue 里若干项。

## 一、页面上出现多个地址栏 / 前进后退横条

注入的浏览器壳是**初始化脚本，会在每个 frame 里执行**；publisher 页面常有同源 iframe，
每个 iframe 各挂一套，就出现「多个地址栏」。现在只在**最外层文档**挂载：

```js
if (window.top !== window.self) return;   // 见 WEBVPN_CHROME_SCRIPT
```

## 二、侧栏点文件打不开、显示「无法获取应用列表」

**根因（已独立复现）**：那句话来自 DSH 客户端插件 `dsh-client-ui-open-in-app`；它调用会话远程
`session.workspacePathApplications`，宿主侧由 `@deepseek-ai/dsh-native-command` 在 Windows 上跑
PowerShell 调 Shell 的 `SHAssocEnumHandlers` 枚举「打开方式」。该 DllImport 是
`PreserveSig = false`，**Shell 一返回失败 HRESULT 就抛异常**；而这台机器上它对
**所有扩展名、所有位置**（`.md`/`.txt`/`.pdf`、AppData 与用户目录）都返回 `E_FAIL`：

```
使用"1"个参数调用"List"时发生异常: 对 COM 组件的调用返回了错误 HRESULT E_FAIL
+ ConvertTo-Json -InputObject @([DshFileAssociations]::List($path))
```

DSH 没有降级处理 → 远程调用抛错 → 界面显示「无法获取应用列表」，而用户真正要的
「在文件资源管理器里显示」走的 `explorer.exe /select,`（**不含 COM**）本来可用。

**修法**：给**打包进安装包的 DSH** 打一个降级补丁（新增
`scripts/patch-dsh-native-file-associations.mjs`，由 `desktop/scripts/prepare-runtime.ps1`
在 Windows 打包阶段应用）：

1. `SHAssocEnumHandlers` 改为 `PreserveSig = true` 并读返回值；
2. 枚举失败或返回空指针 → 直接返回（等价于"没有可用应用"）；
3. 枚举循环里不再 `Marshal.ThrowExceptionForHR`，失败即 break。

效果：界面不再报错，主按钮就是「在文件资源管理器里显示」，点它能打开资源管理器并选中文件。
补丁脚本可校验、幂等，且**上游一改这段代码就拒绝应用**（单测覆盖）。

## 三、issue.md 里能立刻做的四项

来自应用内 Agent 的测试报告（`projects/test/issue.md`）：

- **O2 / B2：候选不再"同名不可分"**。`lab_browser_observe` 的候选新增 `target` 与 `file`：
  `target` 是**脱敏后**的 host+path+白名单查询参数（只保留 file/filename/name/type/format/
  download/isDTMRedir/doi，其余票据类参数一律丢弃），`file` 是文件名（如
  `science.aeg4791_sm.pdf` vs `…tables_s1_to_s6.zip`）。Science 那三个同名 `DOWNLOAD` 现在
  一眼可分。
- **O3：过滤历史下载气泡**。`Downloads: 981,` 这类与本次无关、却看着像进度的条目不再进候选。
- **B6：观察有效期**。15 秒对"模型一次工具往返"太紧；延长到 2 分钟，并**额外要求页面 URL 未变**
  —— 页面一变，元素引用立即失效（比单看时间更准）。
- **B4 / O5：体积上限前置暴露**。状态里新增 `maxCaptureBytes`；当已收字节/文件大小超过上限时，
  消息里直接说明「已超过 100 MB 捕获上限，上传会被拒（可用 lab_tasks_update_bundle_file
  直接登记该文件）」，不再让人下载 8 分钟后才吃 413。
