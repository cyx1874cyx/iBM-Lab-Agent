# v0.5.3-beta9 发布说明

发布日期：2026-09-24

## 主要更新

**本版的唯一主题：把插件适配到 DeepSeek Harness `0.1.7-rc.1`（上一版锁在 `0.1.5-rc.1`）。**
0.1.7 不是一次「跟随小版本」的升级：它删除了 agent preset 的目录契约，改了浏览器侧
Remote codec 的字段名，还重写了 web 前端的剪贴板压缩代码。这三处里有两处**不会报错，
只会静默丢功能**，因此本版按「先证伪、再改动、最后真机挂载」的顺序完成。

### 1. agent preset：目录 → 声明行（破坏性，静默失效）

- 0.1.5 的 preset 是 `$DSH_HOME/.agent-presets/<id>/`（`preset.yml` + `agent.cordis.yml`），
  0.1.7 改为 bundle patch 里的一条 `@deepseek-ai/dsh-agent-preset` 声明行，
  `config.plugins` 承载原来的行列表；上游文档原文：*"Nothing reads that directory any more."*。
  旧写法**不报错**，只是 roster 里的 `lab-research` 消失、新会话退回 `standard`。
- 本版把 preset 变成 `dsh-lab-agent` bundle 的**第二个 patch 层**：
  `presets/lab-research/preset.patch.yml`，并在根 `package.json` 的
  `dsh.bundle.patch` 里按 `["./cordis.patch.yml", "./presets/lab-research/preset.patch.yml"]`
  排序。原来 319 行的 `agent.cordis.yml` 内容逐行搬进 `config.plugins`，行名全部
  在 0.1.7 上可解析；`preset.yml` 的 `name`/`description` 变成 `config.name`/
  `config.description`，`order: 10` 排在四个内置预设之后。
- 安装器与桌面端**删除**遗留的 `.agent-presets/lab-research/` 目录（`scripts/install.mjs`、
  `desktop/src-tauri/src/runtime/dsh.rs`），避免它看起来还能编辑。
- 新增集成测试 `tests/integration/preset.test.mjs`：用真实
  `presets/lab-research/preset.patch.yml` 经 Loader overlay 路径挂载，断言 registry 接受
  声明、`readDocument()` 返回的 YAML 含 skill 路由与课题工具行。

### 2. 默认预设：`settings.yaml` → profile patch（破坏性，双重静默失效）

- 0.1.7 的 `@deepseek-ai/dsh-settings` 启动时把 `settings.yaml` 改名成
  `settings.yaml.imported`，只分发 `LEGACY_SECTION_ENTRIES`（`ui-developer-tools`、
  `ui-onboarding`、`shell`）里列出的段；`agent-presets:` 段没有映射，只会留一条 warn。
  即使段名写对也写不进去：registry 行 id 是 `agent-preset-registry`。
- `scripts/configure-default-preset.mjs` 重写为：把 `agent-preset-registry` 的
  `config.default: lab-research` 覆盖写进 **profile patch**
  （`$DSH_HOME/profiles/ibm-lab/cordis.patch.yml`）。该层在 `dsh-web-app` 声明 registry、
  `dsh-lab-agent` 声明 preset 之后应用，因此覆盖生效；写入是**逐行小改**，Web 预设编辑器
  写进同一文件的 `preset-*` 覆盖与 `!!js` 表达式都原样保留。
- `--keep-default-preset` 语义不变（不跑该脚本即不覆盖）。

### 3. 浏览器客户端：strict codec 字段 `schema` → `create`（硬阻断）

- 0.1.7 的 `dsh-typert-registry` 校验 `typeof codec.create === "function"`，本项目
  `client/src/descriptors.js` 里 **276 个 strict codec** 全是 `schema: pass`，会让
  `ctx.remote.$mount` 抛错、客户端 `apply()` 整体 reject —— 角标、侧栏 tab、浮层**全部**
  不注册（不是部分降级）。本版改为 `create: () => pass`（`pass` 仍保留 `parse`，语义等价），
  并重建 `client/index.js`；`check:client` 一致性检查通过。

### 4. 剪贴板回退补丁：压缩锚点重新推导（出包成本放大器）

- 0.1.7 重写了 JSON 树复制（改成状态变量赋值 `G="copied"`）并重命名了 helper
  （`Fn`→`tr`、参数 `t`→`e`），旧的两个锚点**一个都匹配不到**：
  `desktop/scripts/prepare-runtime.ps1` 会直接 `throw`；它的
  `Test-DshWebFrontendPatch` 也会恒假，导致 DSH 暂存指纹永远不匹配、**每次出包重拷整棵
  DSH 树**（约 3 万条目）。
- `src/dsh-web-frontend-patch.js` 改成**多布局表**：0.1.5-rc.1 与 0.1.7-rc.1 各一条，
  未知布局以「找不到受支持的 shared clipboard anchor」明确失败，而不是误改。
  0.1.5 的无分号历史补丁仍可迁移。
- PowerShell 侧的锚点探测改为调用同一支 node CLI
  （`scripts/patch-dsh-web-frontend.mjs verify --root …`），不再复制第二份字符串——
  0.1.5 线内 rc.1→rc.2 的漂移已经证明「两处锚点必然分叉」。

### 5. 依赖安装：0.1.7 把内部依赖改成了 peerDependencies

- 0.1.7 的 `@deepseek-ai/dsh-app-boot`、`dsh-tools` 等把 `cordis-plugin-group`、
  `dsh-sandbox` 等改为 peer；旧的
  `npm ci --omit=peer --legacy-peer-deps` 会把它们全部跳过，插件在 bootLite 阶段直接
  `ERR_MODULE_NOT_FOUND`。`install.sh` 与两条 CI 工作流改为 `npm ci`（装 peer）。

### 6. 版本与哈希钉子

- `harness.lock.json` → `cli: 0.1.7-rc.1`；`dsh-agent-presets` 由
  `dsh-agent-preset` + `dsh-agent-preset-registry` 取代；cordis `4.0.2`→`4.0.4`、
  zod `4.5.4`→`4.6.5`。
- `runtime/versions.env`：`DSH_VERSION=0.1.7-rc.1`，
  `DSH_AGENT_LOOP_SHA256=257eb83c…` → `c831f709b4ff86d855fdba0d60b32d32c7cbd0803ca058bea924e4e03639ff4f`
  （0.1.7 实测哈希）。宿主补丁锚点本身在 0.1.7 上仍然命中，只换哈希。
- `runtime/launcher/{package.json,pnpm-lock.yaml}`、`package.json`（devDependencies +
  12 项 peerDependencies）、`package-lock.json`、`pnpm-workspace.yaml`
  （231 → 267 条 `minimumReleaseAgeExclude`）全部重新生成。
- `desktop/` 的 DSH 版本字面量、`desktop/docs/architecture.md`、`desktop/README.md`、
  `README.md` 同步。

## 已知限制

- 预设声明只在**新建会话**上生效；已运行会话保持启动时的组合，这与 0.1.5 的行为一致。
- 0.1.7 的 `agent-preset-registry.default` **不是 volatile**，因此默认预设只能由组合层
  （bundle patch 或 profile patch）决定，UI 里改的是运行期 `selectedDefault`；安装器的
  `--keep-default-preset` 仍然通过「不写 profile patch」实现。
- **安装包从 172 MB 涨到 259 MB（+87 MB，+50%）。** 原因已定位并确认不是配置失误：
  0.1.7 的 `dsh-web-app` 直接依赖 `dsh-office-to-pdf`，后者依赖 `libreoffice-kit`，
  其 Windows x64 平台包 `@deepseek-ai/libreoffice-kit-win32-x64` 解包后 **325 MB**，
  让暂存的 DSH 树从 318 MB 涨到 648 MB。该 `office-to-pdf` 行在我们组合出的 profile 里
  **是启用状态**（`--dump-config` 第 508 行，无 `disabled`），删掉这个平台包会让该行在
  运行期缺依赖，因此本次按原样出货。顺带的好处是：上游现在自带 LibreOffice 转换能力，
  本项目的 Office 预览/转换不再只依赖用户机器上装的 LibreOffice。
- 首次在 Windows 侧安装根依赖需要能访问 npm registry 或镜像；本机实测
  `registry.npmjs.org` 从 Windows 侧不可达，出包脚本会自动回退
  `registry.npmmirror.com`（见下）。

## 出包链路（本次打通，四个只在真出包时才暴露的缺陷）

Windows 安装包由 `scripts/windows-release-from-wsl.sh` 在 WSL 里驱动 Windows 原生
工具链产出（完整 11 阶段流水线）。本次升级把它从「能用」推到「干净副本也能用」，
期间修掉四个缺陷：

1. **根依赖不会自动更新** → 驱动脚本只补 `desktop/` 依赖，根 workspace 依赖要人工准备；
   升级 DSH 后 Windows 副本仍是旧树，出包不报错、只是把旧 Harness 打包进去。现在每次都
   与冻结锁对齐，并遍历 `@deepseek-ai/dsh*` 校验版本。
2. **半装树被放行** → 一次被 TLS 错误打断的 `pnpm install` 留下
   `dsh=0.1.7` 而 `dsh-client-ui-session=0.1.5` 的混合树，只探入口包的写法会放行。
   现在的后置校验覆盖全部 267 个 `@deepseek-ai/dsh*` 包。
3. **npmjs 从 Windows 侧不可达** → 依赖安装第一步就超时。现在先探测
   `registry.npmjs.org/-/ping`，不可达则回退 `registry.npmmirror.com`
   （项目安装器本来就用它下 pnpm），可用 `IBM_LAB_WSL_REGISTRY` 强制指定。
4. **剪贴板补丁缺分号** → 0.1.7 里被替换的 `try{}catch{}` 后面直接跟 `const`，
   块语句不需要分隔符，换成表达式语句后必须自带分号，否则补丁后的前端是
   `failed"const`——`prepare-runtime` 的 `node --check` 会在第 8 阶段拦下。
   已修锚点，并把「对真实钉住前端跑补丁 + `node --check`」加进集成测试。
5. **token 交换断言写死了 Location** → 0.1.7 把重定向从 `/` 改成 `./`，
   `verify-package.ps1` 因此误报「没有下发会话 cookie」。现在按 URI 解析后比较路径。

## 升级须知

- Linux：重新运行安装命令即可幂等升级；升级后安装器会删除
  `$DSH_HOME/.agent-presets/lab-research/`（0.1.7 不再读它），并把默认预设写进
  `$DSH_HOME/profiles/ibm-lab/cordis.patch.yml`。安装器在新 release 通过验证前不会切换
  `current`。
- 手工部署：`npm ci`（不要加 `--omit=peer`）→ `node scripts/dev-link.mjs` →
  `node scripts/install.mjs --strict` → `node scripts/configure-default-preset.mjs` →
  `dsh plugin --profile ibm-lab add "$PWD"`。
- 回滚到 beta8 时不会有数据迁移问题：preset 目录与 `settings.yaml` 段都是旧版读法，
  重装旧 release 即可。
