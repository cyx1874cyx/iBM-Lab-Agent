# v0.5.5-beta17 发布说明

发布日期：2026-09-27

## 主题：文件还没写完就上传了

`issue-0.5.5-beta16.md` 的现象是：同一个 DOI、同一串点击，**3 次 400 失败、第 5 次成功**；
而三次失败留在盘上的 `-未归档.pdf` 都是**完整的** 2,716,663 B PDF，sha256 与那次成功归档的
上传体**完全一致**。

### 真因：读得比写完早（报告的 §3 推断被代码推翻）

报告推断"壳上传的是响应层载荷而不是落盘文件"。不是：

- 失败时被改名保留的 `-未归档.pdf` **就是 `upload.path` 本身**（`preserve_failed_download`
  是重命名，不是拷贝）——如果上传的是别的缓冲区，保留下来就不会是那份完整文件；
- 而 `read_captured_file` 的旧实现是**第一次 `fs::read` 成功就返回**。

`DownloadEvent::Finished { success: true }` 表示**网络传输结束**，不表示写文件的句柄已经
flush 完。于是我们读到的是**前缀**，把它当整份上传，捕获服务的校验按规矩回 400；等事后去
看，文件已经长到完整大小。之所以 3 失败 1 成功，就是因为它是一个竞态（缓存命中、1 秒内
完成的那几次更容易输）。

### 修法（R1）

`read_captured_file(path, kind)` 现在**等到内容被证明完整才交出去**：

- `captured_body_defect(kind, &body)`：`%PDF-` 头 + 尾部 `%%EOF`（SI 另认 zip/docx 的 `PK` 头），
  **与捕获服务的校验同一组判据**——本地就不会把一份注定被 400 拒绝的 body 发出去；
- 还要求**连续两次读到的长度一致**（证明真的写完了）；
- 30 秒上限（`CAPTURE_READ_TIMEOUT`），超时带着"读到了多少字节、差哪一项"报错。

这条把"3 失败 1 成功"的摇摆变成确定性：要么成功，要么以明确理由失败。

### 原因可见（R2/R3/R4/R5）

| 编号 | 改动 |
|---|---|
| R2 | 捕获服务拒绝时读**响应体**并写进错误（以前只有 `HTTP {}`）——现场三条失败的具体文案就是这么丢的 |
| R3 | 校验失败带稳定 `code`（`payload-too-small` / `missing-pdf-header` / `missing-eof` / `kind-mismatch`）与 `receivedBytes`，返回体里都有 |
| R4 | `WebVpnStatus` 新增 `lastFailure {message, salvagedPath, salvagedBytes, salvagedSha256}`；客户端**以前根本没上报 `lastError`**，现在两个都上报；状态消息会明说"本地已保住完整文件 …，可用 `lab_tasks_update_bundle_file` 直接登记，不必重新抓取"。`sha256` 只在文件确实是完整 PDF 时才给，避免误导调用方去救半截文件 |
| R5 | 失败原因不再在终态被抑制（旧条件**恰恰在失败时**把它藏起来）；`cancelTask` 不再覆盖已有 `error`——原因进 `errorHistory`，取消原因另存 `cancelReason` |
| R7 | 预设把处置顺序写成固定的：**先读原因 → 再看有没有保住的文件 → 连环失败 2 次就停 → 才谈重建**；明确"不要先 cancel" |

## 本版**未**做

- **R6**（完成判据三合一 + `completed` 带 sha256）：三合一的判据在 beta16 已经落到载荷与归档
  两处，本版的 R1 又把**下载路径**补上了（上传前必须先证明完整）；`sha256` 已随
  `lastFailure` 提供，但成功事件本身仍不带——留给"事件载荷"那一轮。
- 报告 §8 的第 1 条（读 `lab_captures.json` 拿校验原话）现在**不需要**了：状态消息直接给原因，
  不必去读存储文件。
- 其余排队项不变：B3/B4/B6/B7/B8、A1/A2、动作延迟、八家出版社 iWAN 标定（全 `pending`）。

## 真机验收（最短路径）

按报告 §7 复现：`PDF` → `/doi/epdf` → 点 `Download PDF • 2.6 MB`，**连做 5 次**。

- 期望：5 次全部 `captureCompleted`；**不允许再出现"3 失败 1 成功"的摇摆**。
- 若失败：日志里必须出现捕获服务的**响应体原文**（R2），状态消息里必须出现原因与
  `code`（R3），且若本地文件完整，消息里要给出 `salvagedPath` 与 sha256（R4）。
