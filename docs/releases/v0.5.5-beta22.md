# v0.5.5-beta22 发布说明

发布日期：2026-09-28

## 主题：修复让 Ctrl+S 变成空操作的一个查询

beta21 加了"聚焦主窗口 → 确认前台窗口是本进程 → 给原生 PDF 查看器发 Ctrl+S"，但取主窗口用的是：

```rust
app.get_webview_window("main")   // ← 这个查询只接受 WebviewWindow
```

本应用的主窗口是**普通 Window + 子 WebView**，所以这个查询**实机永远返回 None**：
每一次查看器保存都在第一行就失败成"主窗口不可用"，快捷键**一次都没发出去过**。
现在改成 `app.get_window(...)`；并且这条路上的每个失败信息都**自带人工兜底**：

> 请在侧栏原生 PDF 查看器按 **Ctrl+S**，下载会自动捕获并归档，无需回传路径

## 状态侧：失败有界，而不是无声重试

- **`pdf.verdict`**（`html-viewer` / `non-pdf` / `complete-pdf` / `unverified` / `none`）：
  真正的 HTML 壳或非 PDF 载荷**永远不能让 `ready`/`complete` 为真**——不管它的字节数显示成什么；
- **查看器保存失败计数**（`viewerDownloadFailure {count, error, terminal}`）：累计到终态后，
  状态切到 `manual-handoff` + `requiresUserAction=true`，并给出**让用户自己按 Ctrl+S** 的
  `question`；此后继续调查看器下载会被**拒绝**而不是无限重试；
- **`progress.source`** 增加 `archived-file`：已完成的任务报**归档后的体积**，
  而不是最后那条传输通道的中间数字。

技能、预设与标定记录都写上了人工 Ctrl+S 兜底。

## 真机验收

1. **原生查看器**：进 PDF → 调一次保存（或点右下角浮层）→ 期望这次**真的**发生保存：
   日志里应出现 `downloadRequested`（目标为任务暂存路径）紧跟 `downloadFinished`/`captureCompleted`。
   上一版这里会失败成"主窗口不可用"——**这次不允许再出现这条**。
2. **人工兜底**：若自动仍不成功，状态会明确让你**在侧栏按 Ctrl+S**；按下后应同样被捕获归档。
3. **失败有界**：连续失败后状态应转 `manual-handoff` 并停止重试，而不是一直重来。
