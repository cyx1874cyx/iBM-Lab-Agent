# v0.5.5-beta27 发布说明

发布日期：2026-09-29

## 原生 PDF 查看器保存热修复

beta26 在 ScienceDirect 查看器内以 CDP 寻找 `#viewer`，现场返回 `viewer-unavailable`。新版本不再依赖查看器内部 DOM：壳调用 WebView2 `ShowSaveAsUI`，在 `SaveAsUIShowing` 事件中把系统保存对话框替换为当前任务的暂存路径。仅接受 `application/pdf`，并检查落盘文件的 PDF 头与结尾标记后归档。

任务状态按暂存文件实际写入字节报告保存进度。原生另存为与普通 `DownloadStarting` 下载事件都可能产生结果；先完成的一路认领任务，避免重复归档。保存失败时保留非 PDF 或不完整文件供诊断，并继续提供人工 Ctrl+S 兜底。插件现在只对确定性的错误首轮转人工；一般超时允许再次尝试。

项目原有 `WebResourceResponseReceived` 取流能力在该现场只得到 348 B HTML 查看器外壳，不能把它当作已加载 PDF。此版本没有重发签名 URL。

## 验证

- Node 单元与集成测试：759 通过、2 跳过、0 失败。
- Windows Rust 测试：119 通过、1 跳过、0 失败。
- ScienceDirect 机构会话及其他出版社的真机下载仍待安装后复测。通过源码测试不能证明 WebView2 在目标机器上已完成保存。

## 真机验收

使用 issue beta26 的 DOI `10.1016/j.bios.2013.11.059` 重复文章页 `View PDF` 路线。`lab_browser_download_viewer_pdf` 后应出现 `viewerNativeSave`，状态的 `progress.source` 为 `native-save` 且字节数随任务文件增长；完成后出现 `captureCompleted`。若失败，请保留原始 `viewerNativeSave` 日志、保存动作返回值、任务状态与诊断文件路径。
