# v0.5.5-beta18 发布说明

发布日期：2026-09-28

## 主题：Science 正文热修——两条字节通路分开算，备用入口变为可验证的一条

针对 2026-09-27 深夜的 Science 正文现场（348 B 查看器空壳被判 completed、双通路互相干扰、
`saveReady` 与消息自相矛盾、备用入口与已失败入口等价）。**一次交付，插件与壳必须同版本。**

### 1. 响应层载荷：HTML 空壳当场拒绝

`write_stream_to_file` 在读到前几个字节时就判断是不是 PDF：以 `<!doctype html` / `<html` 开头的
body 直接以 **`wrong-object-html`** 结束（不再白等 5 秒），其他缺 `%PDF-` 头的报 `wrong-object`。
`GetContent` 启动失败与"没有响应体"也分开成 `get-content-failed` / `no-body`——以前都显示成
`0x00000000`，看不出是哪种。

现场那份 348 B 的空壳正是
`<!doctype html>…<embed src='about:blank' type='application/pdf'>`：**响应头说是 PDF，body 是查看器外壳**。

### 2. 两条通路分开度量

| 改动 | 效果 |
|---|---|
| 新增 `downloadEventBytes` | 下载事件目标文件的字节数单独上报，不再与响应层载荷用 `max()` 混算 |
| 下载事件运行期间（`state=downloading/uploading`） | 状态只报这条通路的进度，**不会**给 `save-pdf-ready`，也不为它编造总长（下载事件没有 Content-Length）→ 不再出现假百分比 |
| `saveReady` | 现在**字面等于** `nextAction === "save-pdf-ready"`（以前是第二次推导，可能与 `nextAction` 打架——348 B 那条假阳性就是这么来的） |

### 3. 备用入口：模型不再给 URL

旧实现让调用方拿 `alternateEntry`（一个 URL 字符串）去重新进入，既可能等于刚失败的入口，
也游走在"模型不能直接给地址"的边界上。现在：

- 插件只在**确实是那篇 Science 论文**时才给备用入口（精确 host、https、无端口、DOI 必须与任务一致、
  且当前不是该下载地址），并给出 `alternateRouteId` + 它派生时所依据的 `page.pageSeq`；
- 新工具 **`lab_browser_navigate(taskId, routeId, expectedPageSeq)`** 不携带任何 URL：
  **目标 URL 由壳自己从当前页面构造**（`science_pdf_download_route`），并且要求
  「当前任务 ∧ kind=pdf ∧ 出版社=Science ∧ 页面序号与上报一致 ∧ 尚未开始下载 ∧ 每任务只一次」；
- 没有可用备用入口时，状态给 **`manual-handoff`**（让用户在侧栏处理），**不再**指向一个已知点不通的入口。

已加 Rust 测试：`www.nature.com`、`evilscience.org`、多余路径段、以及"已经是该下载地址"全部拒绝。

### 4. 另外两处状态修正

- `stalled` 与 `verification` 现在**强制**各自的 `nextAction`（`recreate-or-cancel` /
  `complete-verification`）。此前它们保留 `wait-and-poll`，调用方会一直等下去；
- 页面观察脚本现在会遍历**同源 iframe**（跨源由 try/catch 挡住），嵌在 iframe 里的下载入口可见了。

### 5. 出错原因有码

`reasonCode` 字段：`wrong-object-html` / `wrong-object` / `no-body` / `get-content-failed` /
`transfer-incomplete`，配合 beta17 的 `salvagedPath`/`salvagedSha256`，失败不必再靠读日志反推。

## 真机验收

1. **Science 正文**：文章页点 `PDF` → `/doi/epdf` → 页内 `Download PDF • 2.6 MB`；
   期望 `completed` 且归档字节 ≈2.7 MB；`progress.totalBytes` 在下载事件通路下应为**空**
   （不再拿载荷的 348 B 冒充总量）。
2. **空壳场景**：若再次遇到 348 B 的查看器外壳，状态必须给
   `reasonCode=wrong-object-html` + `nextAction` 为 `retry-download-entry`（有备用入口时）
   或 `manual-handoff`（没有时），**不允许**出现 `save-pdf-ready`。
3. **备用入口**：出现 `retry-download-entry` 时调
   `lab_browser_navigate(taskId, alternateRouteId, page.pageSeq)`，随后 `lab_browser_wait`；
   同一任务第二次调用必须被拒绝。
4. **双通路**：`downloadEventBytes` 与 `progress.receivedBytes` 不再互相冒充。

**仍未验证**：Science 校园网（iWAN）下的下载入口需要装包后真机回归；
八家出版社的 iWAN 标定仍全部 `pending`（`docs/PUBLISHER_DOWNLOAD_CALIBRATION.json`）——
**本轮不声称任何一家已标定完成**。
