# v0.5.5-beta6 发布说明

发布日期：2026-09-25

## 修掉的问题：文献侧栏白屏

beta5 的实测反馈是「能正常打开侧边栏，但浏览器是白屏；开始下载文献时变白，手动打开
WebVPN 又能正常显示」。定位过程与结论如下。

### 实测到的现场

在用户报告的瞬间，对应用窗口做了三类只读测量（主 WebView 作为对照）：

| 观测量 | 文献侧栏 | 主 WebView |
| --- | --- | --- |
| 子窗口 z 序 | 最上层（索引 0） | 其下 |
| `WS_VISIBLE` | true | true |
| 窗口矩形 | 1409,115 1151×1277（正确） | 0,23 2560×1369 |
| 表面颜色数 | **1 种（纯白 100%）** | 124 种 |
| 页面 JS 是否执行 | 执行（12 秒后上报 `pdf-manual`） | — |
| 注入的工具栏 | **不存在** | — |

也就是说：webview 没有被隐藏、没有销毁、位置正确、页面脚本在跑，但画面上是一片纯白，
连我们自己的地址栏都不在。这不是布局或 z 序问题，也不是窗口被遮住。

### 根因

1. 注入的浏览器壳只在 `DOMContentLoaded` 挂载。验证页/被反爬拦下的文档不触发（或很晚才触发）
   这个事件，于是侧栏里既没有页面内容也没有工具栏 —— 用户连手动绕过都做不到。
2. `challengePresent()` 只匹配正文关键词。Cloudflare 插页在挑战脚本注入前正文是空的，
   标题已经是「请稍候…」（英文 `Just a moment...`），全都不在正则里。
3. 于是扫描器把这张空白挑战页当成「已确认的出版社文章页」（只按 host 匹配），
   16 次尝试全打在它上面，最后上报 `pdf-manual`。
4. Rust 侧把 `pdf-manual` 当成「已进入 PDF 预览器」，**对普通文章页**执行了
   `html{transform:translateY(76px)…}` 位移。这段位移本就是为整屏 fixed 预览器设计的，
   对普通页面只会把布局搞坏 —— 与 2026-09-23 ScienceDirect 那次白屏同源。

Science 在本机环境返回的正是 Cloudflare「正在进行安全验证／请验证您是真人」插页
（用真实 Edge 独立复现）。

### 本版改动

1. **工具栏立即挂载并重试**：`mountNow()` 在文档创建时先挂一次，再于 250/1200/4000 ms
   重试，同时保留 `DOMContentLoaded` 钩子。页面卡住时用户至少还有地址栏和关闭按钮。
2. **真正识别验证页**：标题（`请稍候` / `Just a moment` / `Attention Required` …）
   与挑战脚本/组件标记（`challenge-platform`、`challenges.cloudflare.com`、
   `cf-turnstile-response`、`#challenge-form`、`cf-chl*`）都算验证中，按既有
   `ibm-webvpn://automation/challenge` 上报，不再消耗尝试次数。
3. **文档没加载完就不算文章页**：`readyState === 'loading'` 或正文没有任何可交互内容时
   只等待；超过约 30 秒才退回人工，免得任务永远停在"正在查找入口"。
4. **位移只认正向证据**：只有顶层文档确实是 PDF 时才开页面位移；`pdf-manual` 不再
   单独触发位移，也不再谎报「已进入 PDF 预览器」，改为
   「未能自动识别正文下载入口；捕获仍有效，请在页面中手动打开并保存」。
