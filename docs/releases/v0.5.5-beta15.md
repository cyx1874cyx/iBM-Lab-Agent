# v0.5.5-beta15 发布说明

发布日期：2026-09-27

## 主题：给"保存"一个点得到的地方

beta13 报告的 R1：用户要在预览页上点保存，但原生 PDF 查看器的 UI 不在文档 DOM 里，
`observe` 返回 `candidates: []`，没有任何可点元素。

**先更正 beta14 发布说明里我写的一句话**：我说"原生 PDF 查看器里注入脚本不执行"。
这是错的，而且证据就在那份报告自己的记录里：

```json
observe(原生 PDF) → {"candidates":[], "documentType":"application/pdf", "readyState":"complete", ...}
```

这串 JSON **是我们的脚本在那个文档里跑完返回的**。真正的限制是"查看器 UI 不在 DOM 里，
所以没有可点元素"，而不是"脚本进不去"。这个区别决定了方案可不可行。

### 动手前先实测（Edge 内建查看器 = WebView2 同引擎同查看器）

| 检查 | 结果 |
|---|---|
| 往文档里注入 `position:fixed` 元素 | **画在 PDF 之上**（截图为证） |
| `document.elementFromPoint(按钮中心)` | 返回我们的宿主元素 |
| `{有无 html transform} × {popover / 普通 fixed} × {左/右}` 五格矩阵 | **五格全部**收到 trusted 的 `pointerdown/mousedown/pointerup/mouseup/click` |
| 施加页面位移后滚动文档 | 按钮仍在视口右下角（y 与底部间距不变）→ top layer 逃逸有效 |

### A｜页内右下角「保存到课题」浮层（壳注入）

- 与小球同一套机制：壳注入、壳推送状态、`ibm-webvpn://save-pdf/` 内部命令回壳。
  绝不用 `location.href`（那是一次真实导航，是白屏的根因）。
- **载荷没被证明收全之前它是禁用的**，并显示「PDF 正在接收 1.0 MB / 2.6 MB…」——
  它不可能引诱人去归档半个文件（beta14 的那条事故在新入口上被结构性挡住）。
- 点过之后锁定，不会重复触发第二次归档；归档中拒绝第二次保存。
- 用户触发与 Agent 触发**同一条实现**：等终态 + 归档前三道校验（头/尾/大小）。
- 用 popover 跳进 top layer：PDF 页会被施加 `html{transform:…}`，否则按钮会跟着页面
  滚走（小球当初就是为这个改成 popover 的）。
- 状态与小球同源（同一次 `push_capture_ball` 推送），所以两者不可能互相矛盾。

### B｜侧栏兜底按钮

右侧栏「文献浏览器」tab 顶部多了一条工具行，里面是同一件事的按钮。它**故意不在**上报给
壳的矩形内——原生子 WebView 会盖住那个矩形，放进去就看不见了。它读同一份 `webvpn_status`、
调同一条 shell 动作，所以当页内注入因为任何原因缺席时（时序、CSP、特殊文档），
用户仍然有一个地方可以点。

## 真机验收

1. 打开一篇正文 → 点 `PDF` 进原生查看器：**右下角应出现「保存到课题」**，
   载荷没收全时显示"正在接收"且不可点。
2. 收满后点它 → 应直接归档成功（`completed` + 字节数与页面标称一致）。
3. 侧栏「文献浏览器」tab 顶部应有一条工具行，同样的按钮在那里也可点（兜底）。
4. 若第 1 条没出现：说明注入在这个文档上缺席，第 3 条仍然可用——两处一起看能直接判断
   是"注入缺席"还是"按钮逻辑不对"。
