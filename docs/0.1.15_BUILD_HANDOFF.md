## 3. 需求的确定性解释

### 3.1 文件夹与文件名

为每个 bundle 生成稳定的文献条目标识 `entryStem`：

```text
<短引用> <10字以内短介绍>
```

建议规则：

- 短引用优先使用 report 的 `shortCitation`；不存在时使用 `第一作者 et al. 年份`；再回退 DOI 或 bundle id。
- 短介绍优先使用 `titleZh`，其次论文标题；去除标点和 Windows 非法字符后截取不超过 10 个 Unicode 字符。
- 清理 Windows 非法字符 `<>:"/\\|?*`、控制字符、尾部空格和句点；文件夹名总长设置合理上限。
- 同一 bundle 的 `entryStem` 必须稳定，正文和 SI 分批存档时不能产生两个文件夹。
- 建议目录：

```text
<工程文件夹>\literature\<entryStem>\
  <entryStem> 正文.pdf
  <entryStem> SI.pdf
  <entryStem> 精读报告.md
  <entryStem> 精读报告.docx
  <entryStem> 文献汇报.pptx
  ...审计与来源文件
```

如果元数据后补导致更好的 `entryStem`，必须设计一次受控迁移，同时更新数据库中的所有路径；不能只重命名磁盘文件而留下失效路径。最稳妥方案是在文献占位创建时固化 `entryStem`/`entryDir` 到 bundle schema，旧数据按需迁移。

### 3.2 PDF/SI 类型

- 本需求中的正文和 SI 都是 PDF。
- 捕获上传时 `kind=pdf` 和 `kind=si` 都必须执行 PDF 签名、EOF、大小和 SHA-256 校验。
- 两者保存扩展名都强制为 `.pdf`，不能依据原始响应文件名把 SI 保存成 ZIP/TXT。
- UI 对已登记的 SI 不再通过路径后缀猜测是否为 PDF；已登记 SI 按 PDF 阅读按钮处理。

## 4. 必须修改的代码链路

### 4.1 存档与目录归一化

重点文件：

- `lib/manual-capture.js`
  - 当前 `saveCapturedFile()` 保存到 `captured-literature/<bundleId>/<原文件名>`。
  - 改为调用统一的文献条目路径生成器；不要接受浏览器提供的文件名作为最终文件名。
  - 正文与 SI 都验证为 PDF，写临时文件后原子替换目标文件。
- `lib/tasks.js`
  - 新增统一 helper，例如 `literatureEntryLayout(bundle, report?)`、`sanitizeEntryStem()`、`stageArtifactIntoEntry()`。
  - `preparePaper()`：外部传入 PDF/SI 时复制或移动到工程的条目目录，再登记归一化后的路径；不要继续登记工程外部临时路径。
  - `registerCapturedFile()`：登记最终条目目录中的正文/SI 路径。
  - `completeReadingReport()` / `materializeReadingDocx()`：把 Markdown 和 DOCX 固化到同一条目目录，数据库保存新路径。
  - `completePresentation()`：把 PPTX 复制到同一条目目录，数据库保存新路径；相关 outline、notes、figure sources、QA 文件也尽量同目录。
  - `bundleFile()`：正文和 SI 都用 `validatePdfBuffer()`，MIME 都返回 `application/pdf`。
- `src/task-models.js`
  - 如采用固化布局，给 bundle 增加可选 `entryStem`、`entryDir` 字段，保持旧数据兼容。
- `lib/remote.js`
  - `siIsPdf` 不再依据扩展名猜测；已登记 SI 即为 PDF。
- `lib/artifact-download.js`
  - `kind=pdf|si&preview=1` 都必须返回 `application/pdf` 和 `Content-Disposition: inline`。

路径迁移必须使用复制到临时文件、校验、原子替换、更新数据库的顺序。不要在数据库更新前删除旧文件；旧数据迁移失败时应保留原文件并报告错误。

### 4.2 Edge 打开链路

重点文件：

- `client/index.js`
- `desktop/src/index.html`
- `desktop/src-tauri/src/main.rs`
- `lib/artifact-download.js`

推荐保留专用消息 `OPEN_ARTIFACT_IN_BROWSER`，但必须做真实端到端诊断：

1. 前端点击后显示短暂“正在打开”状态；失败必须 toast 明确错误，不得静默。
2. shell 收到消息后调用 Tauri 命令并回传结果。
3. Rust 命令只接收 `kind + bundleId`，按当前 runtime port 生成受限地址，防止任意 URL 注入。
4. Edge 启动后，Rust 不能仅以 `spawn()` 成功作为最终成功。至少在启动前对本地 PDF 端点执行一次受限 HTTP 预检，验证响应为 200、`content-type=application/pdf`；预检失败时把具体错误回传 UI。
5. Edge 地址必须使用新的、不可与旧缓存混淆的阅读 URL，可加入 `v=<sha256/updatedAt>`。必要时增加专门的 `/lab/read/<bundleId>/<kind>` 阅读路由，再由该页面嵌入同源 PDF。
6. 检查 `denyCrossSite()` 是否误拦 Edge 顶层导航。顶层浏览器打开本地阅读地址必须允许，但跨站脚本 fetch 仍应拒绝。
7. 安装后确认运行的确是 0.1.15。上一轮继续使用 0.1.14 版本号，极易导致 Windows 保留/启动旧安装内容，这是本次必须消除的风险。

若直接 HTTP URL 在 Edge 上仍不稳定，可采用更可靠的备选方案：桌面端通过受限 loopback URL获取并校验 PDF，保存到应用缓存目录，再执行 `msedge.exe --new-window <file:///...pdf>`。该方案仍是在 Edge 阅读，但必须保证缓存文件名和哈希可追溯，并且正文/SI 指向正确文件。

### 7.8 安装包静态校验

```powershell
Set-Location $repoRoot
if (-not (Test-Path -LiteralPath $installer)) { throw "未生成安装包: $installer" }

& powershell -ExecutionPolicy Bypass -File desktop\scripts\verify-package.ps1 -InstallerPath $installer

$installerItem = Get-Item -LiteralPath $installer

"PATH=$($installerItem.FullName)"
"SIZE=$($installerItem.Length)"
"LAST_WRITE=$($installerItem.LastWriteTime.ToString('yyyy-MM-dd HH:mm:ss'))"
"SHA256=$($installerHash.Hash)"

git diff --check
```

安装包不应小于 1 MB；以当前完整运行环境为参考，通常约 150 MB。体积异常小往往表示资源未打入。

### 7.9 安装与真实桌面验收

静态校验不能证明点击 PDF/SI 有效。最终必须安装新包：

1. 保存当前工作，完全退出正在运行的 iBM Lab Agent。必要时在任务管理器确认旧 `ibm-lab-desktop.exe` 已退出。
2. 运行 `iBM Lab Agent_0.1.15_x64-setup.exe`。当前 NSIS 配置为 `perMachine`，可能触发管理员/UAC。
3. 安装完成后从开始菜单启动，确认日志或安装信息显示 0.1.15，不能继续测试旧 0.1.14。
4. 等待界面显示本地服务就绪。运行日志位于 `%LOCALAPPDATA%\iBM-Lab-Agent\logs\`。
5. 使用同一文献条目分别点击正文和 SI，确认 Edge 各自打开正确 PDF。
6. 检查工程目录中文献条目文件夹和重命名后的 PDF、DOCX、PPTX。
7. 重启应用后重复点击，验证数据库路径和文件布局可持久恢复。

若需要保留旧安装作对照，先记录旧版本和安装位置；不要同时运行两个版本，因为单实例机制可能把新启动请求转给旧进程，造成“新包仍是旧行为”的误判。

### 7.10 常见故障定位

| 现象 | 优先检查 | 处理方式 |
|---|---|---|
| `node` 不是命令 | 系统 PATH 无 Node | 全程使用 `$nodeSource`/`$bundledNode` 绝对路径 |
| `prepare-runtime` 删除 Node 后失败 | `-NodeExe` 指向了 `resources/node/node.exe` | 改用旧 target 或系统 Node 24；不要指向会被脚本删除的目录 |
| 找不到 DSH `lib/bin.js` | `runtime/launcher/node_modules` 未物化 | 在 `runtime/launcher` 执行锁定的 pnpm production install |
| 捆绑 Python缺失或不能 import markitdown | `resources/python/dist` 不完整 | 运行 `build-bundled-python.ps1`，再执行独立 import 检查 |
| Rust 提示 linker/SDK 错误 | MSVC Build Tools 或 Windows SDK 缺失 | 安装 Desktop development with C++ 与对应 Windows SDK 后重开终端 |
| build 长时间停在资源扫描 | 资源文件数量巨大 | 先等待；必要时使用 `TAURI_CONFIG` 优化并强制做安装后资源验证 |
| makensis 下载或构建卡住 | GitHub 不可达或 NSIS 未缓存 | 配置可用代理/镜像，确认 Tauri binary releases 可访问 |
| 生成的文件仍叫 0.1.14 | `tauri.conf.json` 未升级 | 统一版本后重新 prepare、build，不要手工改安装包文件名 |
| 安装 0.1.15 后行为仍像旧版 | 旧进程仍运行、同版本缓存、打包副本旧 | 退出旧进程；确认版本；比较 source/packaged client 哈希；重跑 prepare/build |
| 点击 PDF/SI 无响应 | UI 消息、shell invoke、Rust 预检或 Edge 启动某段失败 | 查看 UI toast 和 `%LOCALAPPDATA%\iBM-Lab-Agent\logs`; 分段记录 requestId/错误，不能只检查代码存在 |
| Edge 打开 404/403 | runtime port、bundleId、跨站导航策略或数据库路径错误 | 直接请求生成的 loopback URL，核对 HTTP 状态、content-type 和 `denyCrossSite()` |
| 安装包体积异常小 | bundle resources 未包含 | 禁用可疑 override，重跑 prepare/verify/build；安装后确认运行目录含 Node/DSH/plugin/Python |
