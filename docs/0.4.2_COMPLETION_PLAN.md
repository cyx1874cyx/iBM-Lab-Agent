# iBM Lab Agent 0.4.2 完成书：登记追溯、性能与发布加固

> 执行对象：接手实现的 Agent
> 前置条件：0.4.0、0.4.1 全部发布门禁通过

## 1. 版本目标

完成 NMR 与绘图登记的数据闭环，处理旧数据迁移，并把 Windows 打包从“长时间无输出、容易重复启动、安装包与源码不一致”改造成可观察、可中止、可复现的单命令发布过程。本版只完成可视化结构编辑器的技术设计和接口预留，不实现完整编辑器。

## 2. 必须交付

### WP1 NMR 登记闭环

- 创建、更新和读取接口实际持久化 `projectId/entityId/compound{name,casNumber,smiles}/nucleus/deuteratedSolvent/fidPath/structurePath`，不能只扩展 schema/UI。
- 登记页以 Ketcher 图为主，显示名称、CAS、谱核和氘代试剂；旧记录仅有 `structurePath/solvent` 时可读并提示补充关联。
- 化合物关联改变时保留原快照和修改 provenance；原始 FID 与已审核结构继续受不可变规则保护。
- 提供旧记录惰性迁移或显式迁移命令，迁移可重复执行且不丢数据。

### WP2 绘图登记完善

- 持久化课题、绘图主题、日期、产物引用、创建者/来源、创建与更新时间。
- Agent 登记时生成可修改的默认主题；人工可编辑主题和日期。
- 默认日期按 Windows 本地时区计算，不使用可能跨日的 UTC 日期截断。
- 删除需要确认；产物路径变化或文件不存在时给出可恢复提示。

### WP3 Windows 发布性能与可观察性

- 使用 `desktop/scripts/build-windows-release.ps1` 作为唯一推荐入口。
- `prepare-runtime` 自动识别根 pnpm `node_modules`，以资源指纹跳过未变化快照；`-Force` 才强制全量刷新。
- 单实例锁阻止两次 `prepare-runtime` 或两次发布并发删除同一资源树。
- 每个长阶段独立 stdout/stderr 日志；默认每 20 秒输出心跳、耗时、PID、CPU 和日志大小。
- prepare、测试和 Tauri/NSIS 分别设置超时；超时只终止本次脚本启动的进程树，并保留日志。
- 禁止通过清空 `TAURI_CONFIG.bundle.resources` 制作正式包；增量性能依赖“不触碰未变化资源”和 Cargo target 缓存。
- 发布前校验 Ketcher 动态哈希引用、五处版本一致、干净工作树；发布后只接受本轮新生成、精确版本文件名的安装包。
- 输出安装包大小、SHA256、阶段耗时和日志位置；`-AllowDirty` 产物必须标记为不可发布。

### WP4 结构编辑器后续设计

- 输出 0.5.x 技术设计：抽屉/内嵌模式、Ketcher 工具栏裁剪、载入/保存、撤销重做、自适应尺寸、快捷键、错误恢复、人工覆盖 provenance、路线锁联动和离线测试。
- 保留接口但不向用户暴露未完成入口。当前估算维持 7–12 个工作日，路线自由拖拽另行估算。

## 3. 自动化与人工验收

- NMR 新字段创建/更新/重启持久化、旧数据兼容和不可变字段测试。
- 绘图主题/日期/产物引用测试，覆盖 UTC 日期与本地日期不同的边界时刻。
- PowerShell AST 解析测试；重复启动锁测试；资源未变时 prepare 必须跳过；源 Ketcher 引用损坏时必须在删除资源前失败。
- 模拟超时测试确认子进程树被终止且日志保留。
- 连续执行两次发布：第二次在无源码变化时 prepare 明显缩短，Cargo 使用增量缓存；两次均通过 Web smoke。
- Windows 10/11 干净用户安装、升级、卸载、中文路径和带空格路径验收。

## 4. 发布性能目标

- 无源码/依赖变化时，资源准备阶段目标小于 2 分钟。
- 有插件源码变化但 DSH/Python 未变化时，优先只刷新插件快照；若暂未实现分区指纹，允许全量一次，但必须有心跳和上限。
- Tauri/NSIS 首次全量构建允许 120 分钟，增量目标小于 30 分钟；超限视为失败而不是无限等待。
- 日志必须足以区分 Rust 编译、资源扫描、NSIS 下载和 makensis 压缩。

## 5. 完成定义

NMR/绘图新字段能够真正登记并跨重启读取；旧数据无损；Windows 单命令发布具备锁、心跳、日志、超时、增量跳过和精确产物验证；干净 Windows 验收完成。完整结构编辑器只提交经过评审的设计，不计入 0.4.2 功能验收。
