# iBM Lab：母插件与六个可选子插件拆分计划

日期：2026-11-03。状态：敏捷实施方案，尚未实施功能迁移。

## 开发原则：先交付可运行功能

采用小步迁移、即时验证、逐插件交付。以“母插件 + 当前子插件”的可运行版本作为每轮成果，优先复用现有实现，不以完整平台建设、全量审计或全部自动化测试作为开始开发的前置条件。

开发期不新增插件签名、包来源审计、逐插件权限审批、跨插件安全沙箱、全量文件哈希校验、64 种组合全测及完整故障演练。这些不进入本轮拆分验收。沿用项目现有访问控制，不额外建设权限系统或增加用户确认步骤。

每次变更只检查当前功能和直接受影响的接口。与变更无关的已有问题记录待办，不阻塞交付；由本次修改造成的功能损坏、插件互相强依赖和数据损坏当轮修复。

## 1. 目标与范围

按最新要求，最终为 **1 个必选母插件 + 6 个可选子插件，共 7 个插件**。每个子插件拥有自己的实现、界面、工具、数据迁移、环境依赖、测试与发布产物。子插件可分别开发、构建、测试、升级和装配；生产运行依赖母插件公开接口，开发测试可使用 SDK 测试宿主。

“完全解耦”的验收含义：母插件不导入子插件业务代码；子插件之间没有强制依赖、私有代码导入或跨插件数据写入；任何一个子插件缺失或停用，不妨碍其余插件的基础功能。复用 Mnova、Origin、RAG 现有执行方式，本轮不额外建设进程隔离平台。

取消项目申报功能：移除入口、路由、专属提示词、工具及新任务创建；已有申报草稿和文件保留为历史数据。

品牌统一为 iBM Lab，身份与默认模板保持通用科研定位。既有内部包名、服务 ID、应用 ID、数据路径及登录信息按兼容需求保留；新增公开名称不使用 Agent。

以下新包名均为建议名，实施阶段需映射宿主登记规则并维护旧标识兼容。

| 插件 | 建议包名 | 业务职责 | 自有数据/资产 |
| --- | --- | --- | --- |
| 母插件 | `@ibm-lab/core` | 助手预设、项目空间、项目记忆、会话绑定、项目文件索引、任务公共状态、插件装配、环境与能力管理、公共工作台 | 项目/记忆版本/会话引用、装配配置、能力快照、公共文件与任务引用 |
| 1 文献阅读 | `@ibm-lab/literature` | 检索、导入、正文/SI 管理、精读、翻译、阅读器、PPT、相关模板与引用导出 | 搜索记录、文献条目、阅读报告、翻译、PPT 任务、模板与业务产物 |
| 2 RAG 知识库 | `@ibm-lab/knowledge` | 文档接入、分块、索引、检索、知识问答、来源定位；预留 Obsidian 接入 | 知识源配置、分块/向量索引、检索配置、来源锚点、同步状态 |
| 3 试剂管理 | `@ibm-lab/reagents` | 复用现有清单接入、工作簿解析、搜索与来源打开等已实现功能 | 试剂数据源、字段映射、缓存与该业务配置；不额外承诺尚未实现的库存流程 |
| 4 核磁解析 | `@ibm-lab/nmr` | 核磁文件/结构接入、解析、现有模拟、归属、Mnova 联动、报告 | 数据集、解析/模拟任务、归属结果、Mnova 适配器与相关脚本 |
| 5 科研绘图 | `@ibm-lab/plotting` | 数据表绘图、Origin 联动、图像处理、版式编辑、现有检查与导出 | 绘图任务、图形规格、编辑/排版记录、Origin 适配器与脚本 |
| 6 论文润色 | `@ibm-lab/polishing` | 本轮只实现可安装的占位插件、页面与配置接口 | 可选草稿；标注“尚未实现”，不注册虚假的润色执行工具 |

母插件中的“项目记忆”保存用户确认的项目事实、目标、偏好、约束与决策，支持版本管理；RAG 保存知识资料的检索索引与来源。关闭 RAG 后，项目记忆继续完整工作。RAG 回答不自动写入项目记忆，子插件通过公开接口提交记忆更新。

母插件只管理产物引用、通用元数据与文件访问，不理解核磁峰、图形布局、精读模板等业务结构。各业务提供自己的元数据扩展和历史数据查看器。未安装业务插件时，母插件仍可列出文件与基本元数据。

六插件清单之外，现有合成路线等旧设计领域功能不自动并入母插件，也不新增第七个子插件。本轮只迁移六项功能确实使用的通用结构解析等组件；其余实现和历史数据先保留，其活动入口去向记为待办，不阻塞六插件拆分。

## 4. 依赖规则与公共接口

采用单仓库多包管理，便于一次性迁移与统一约束；每个插件独立版本、构建、测试与发布，后续可迁出仓库。不要把“同仓库”作为读取其他插件源码的理由。

- 依赖方向：子插件 → SDK/公共契约；母插件实现宿主服务。子插件的运行时要求声明母插件 API 兼容范围，不导入母插件内部实现。
- 母插件通过发现和注册加载业务插件，公共入口不静态导入六个子插件。
- 子插件之间无必装关系。业务协作经能力查询与公开协议完成，协作适配器只在双方能力就绪时启动。
- SDK 与契约包只提供类型、Schema、注册协议、客户端和测试替身，不聚合业务实现。
- 通用库只包含实际共享的文件转换、结构解析等纯逻辑或通用执行客户端；采用按需依赖，不产生额外用户可装配插件。
- Electron、浏览器、原生文件选择及系统钥匙串等保留宿主适配层；业务插件只使用公开宿主能力。

建议公共接口面：

| 接口 | 负责事项 |
| --- | --- |
| `projects` / `workspaces` | 项目查询、空间定位、会话绑定及当前项目变化 |
| `memory` | 读取版本、提交更新、处理版本冲突 |
| `artifacts` / `files` | 文件引用、归档、受控读写、预览与来源元数据 |
| `tasks` | 公共任务 ID、进度、取消、恢复与业务结果引用；业务状态机留在子插件 |
| `capabilities` | 查询提供者、版本、就绪状态；调用公开能力与订阅变化 |
| `tools` / `presets` | 工具注册注销、权限、按项目/会话生成有效工具与指令 |
| `ui` | 菜单、页面、配置、任务展示和历史查看器注册/销毁 |
| `runtime` | 声明与检查依赖、请求执行器、凭据引用、超时/取消与日志 |
| `storage` | 获取当前插件命名空间的存储与迁移上下文 |

接口先覆盖当前迁移需要的项目、记忆、文件、工具注册和界面注册能力，保留最小请求/响应结构。其余接口随使用补齐，不提前建立完整抽象层。优先复用已有 Schema、版本和错误处理，公共协议自动生成作为后续优化。

## 5. 插件装配与工具更新

每个插件先提供最小 manifest：`id`、`version`、宿主 API 版本、前后端入口、能力/工具/Skills 注册信息及必要环境依赖。只检查启动需要的字段和 API 兼容性，不新增签名校验、来源审查和权限审批流程。

第一版区分“已安装、已启用、可用、环境缺失/错误”，并支持项目装配配置。预设复用当前选择方式，不新增多级授权或装配审批。

有效工具集合由“插件已安装、已启用、当前项目选用、对应能力可用”共同决定，并沿用宿主已有工具权限机制。同一个插件内部按能力判断就绪状态，例如缺少 Origin 时不应禁用其不依赖 Origin 的图像功能。

装配流程：读取配置 → 加载插件 → 注册可用能力、工具与页面。环境检查仅针对实际使用的执行器，环境缺失就提示原因，不执行全环境扫描。加载失败时清理该次注册并保留其他插件运行，不建设通用事务与回滚框架。

每次变化同时更新菜单、Remote、工具 Schema、预设指令、Skills 与模型可见描述。禁用文献插件后，不能仍由通用 Skills 目录向助手暗示存在文献工具。

第一版允许装配修改在重开会话或重启应用后生效，并在界面说明。已有动态注册机制容易复用的部分可即时更新；不为全量热加载、运行中升级或环境快照版本化阻塞开发。退出时复用既有资源清理机制。

旧 Remote 委托接口按提供者是否启用决定能否调用，缺失时返回功能不可用。插件停用、卸载默认保留数据与配置。

## 6. 环境与可选协作

- 母插件管理环境目录、依赖状态与生命周期；子插件声明并携带自己的业务适配器和锁文件。
- NMR 的 Mnova 与绘图的 Origin 不作为母插件必备依赖。文献转换/渲染及 RAG 向量库也不随母插件默认安装。
- Python 环境先复用当前可工作的环境，各插件单独声明依赖；出现实际版本冲突时再拆分虚拟环境，不提前重建全部执行环境。
- 外部调用沿用现有适配器、超时、取消及日志，不另建安全代理或审计系统。
- RAG → 文献精读：传递公开的资料/文件引用，由文献插件接收；无文献插件时，RAG 检索问答照常工作。
- 文献 → RAG：作为可选导入动作，不把向量索引作为文献阅读的前置条件。
- 核磁 → 绘图、文献 PPT → 绘图：仅使用标准数据/文件引用与可选能力调用；各自原有基础功能可单独执行。
- Obsidian 本轮只预留知识源适配接口；增量同步、删除/重命名和冲突处理留到正式接入时实现。

## 7. 数据迁移与兼容

按“先划清所有权，再迁移物理存储”推进：

1. 只记录当前迁移插件涉及的表、文件目录与关联，修改数据前备份受影响数据；不执行全仓扫描、全量哈希或凭据审计。
2. 初期由母插件唯一打开历史 `lab_tasks`，通过归属明确的兼容仓储供迁移使用；子插件不重复打开同名 domain，不直接访问其他插件数据。逻辑归属明确即可先交付，物理迁移按需进行。
3. 新数据进入插件自有域与项目下的插件命名空间；核磁与绘图共享的 characterization 数据按业务类型迁移并保留旧 ID 映射。
4. 实际需要改存储格式时提供可重复执行的迁移，检查记录数量和代表性记录能否打开、关联能否找到；无需校验全部文件哈希。迁移完成后确定唯一写入位置。
5. 迁移失败时保留原始数据并修复重试，不要求先开发完整反向迁移或故障演练平台。已经产生的新数据保留，不用旧备份直接覆盖。
6. 保留已用的配置、登录态、项目路径、历史任务快照及模板快照。旧 `lab/*` 和包导出按需要做限期兼容，新实现不反向依赖兼容层。
7. 项目申报历史归档可读；移除执行能力和新建入口，不删除原始文件。停用或卸载插件不触发自动业务数据清除。

## 8. 敏捷迭代与交付

| 阶段 | 工作 | 交付物与完成条件 |
| --- | --- | --- |
| P0 最小盘点 | 确认七个插件归属和当前要迁移的入口、数据；记录相关已有改动 | 一份简短迁移清单即可开工，不等待全仓审计或设计冻结 |
| P1 最小 SDK 与首个业务纵切 | 定义首个插件需要的 manifest、宿主接口和测试替身；边使用边补齐 | 首个插件能单独构建、测试，不引用旧主包；不等待完整 SDK |
| P2 母插件最小可用 | 分离项目/记忆/预设/公共布局及装配配置；复用当前环境执行能力 | 母插件独立可启动并管理项目、记忆和预设；允许重启后应用装配变化 |
| P3 试剂插件及润色占位 | 先迁移耦合相对较少的试剂；创建润色插件骨架；完成独立入口与环境声明 | 试剂真实功能保持；润色占位无执行工具；两者分别在仅母插件环境运行 |
| P4 拆开核磁和绘图 | 分离 analysis/characterization 聚合、数据状态机、远程 API、界面、脚本、Mnova/Origin 适配器 | 母插件+核磁不加载绘图；母插件+绘图不加载核磁；各自真实外部应用流程通过 |
| P5 文献阅读插件 | 迁移检索/下载/导入、精读、翻译、阅读器、PPT、模板及文档依赖 | 母插件+文献独立完成既有主流程；保留正文/SI、归档、对话绑定与模板历史 |
| P6 RAG 插件 | 迁移知识源、检索/问答、权限、索引和工具；拆除强制精读连接；预留 Obsidian 适配接口 | 母插件+RAG 独立接入/检索/定位来源；文献协作有无均通过 |
| P7 迁移收尾与交付 | 清理必要兼容入口、移除申报、整理插件产物和简短使用说明 | 六子插件均有独立产物；母插件单独、每个单插件、全部启用三类场景可用 |

采用“每迁移一个插件，就把它的源码、资产、依赖、测试和构建真正迁出旧实现”的方式。每轮完成一个能启动、能操作、能独立测试的成果即可交付；随迁移更新清单，不要求每阶段额外出具评审或安全报告。

P0 仅做必要定位；P1、P2 与首个子插件共同迭代，先打通“母插件 + 试剂插件”完整路径，再迁移其余插件。文献优先级更高时可直接调整顺序，不等待完整平台或全部公共接口完成。

## 9. 独立开发、构建与测试

建议目录：`packages/core`、`packages/sdk`、`packages/contracts`、`packages/testing`、`plugins/literature`、`plugins/knowledge`、`plugins/reagents`、`plugins/nmr`、`plugins/plotting`、`plugins/polishing`、`adapters/desktop`、`tests/compositions`。共享代码按真实职责另设内部库。SDK、契约、测试包和宿主适配器不计入七个产品插件。

每个业务插件目录自带：`package.json`、manifest、后端源码、前端入口/样式、资产与脚本、迁移、测试、锁定环境说明、开发说明。命令目标为各包内 `dev`、`build`、`test`、`test:integration`、`test:ui`、`pack`，发布流水线可单独选定一个包。命令在实施后提供，当前文档不代表这些脚本已经存在。

| 测试层 | 必须证明的事项 |
| --- | --- |
| 依赖边界 | 检查当前改动涉及的依赖，确认没有回接旧主包或强制安装其他子插件；先用简单检查，不先造全仓审计工具 |
| 业务与接口 | 复用相关已有测试，只补关键接口/状态或本次修复需要的用例；普通界面迁移可做人工操作验证 |
| 单插件运行 | 母插件 + 当前子插件完成一条代表性主流程，工具与入口符合装配配置 |
| 外部应用 | 未改适配器时复用既有验证；改变 Mnova/Origin 调用协议时验证对应流程，其余先用替身开发并记录实机未验证项 |
| 数据变更 | 仅在改动存储时备份和检查受影响记录，确认旧项目仍能打开；不跑全量哈希与灾难恢复演练 |
| 独立产物 | 每个插件完成迁移时做一次仓库外安装与启动，确认没有依赖本仓库源码；不在每次界面修改后重复执行 |
| 组合冒烟 | 交付前覆盖母插件单独、6 个单插件以及全部启用，共 8 类配置；有协作修改时补相关双插件场景，不测全部 64 种组合 |

日常只运行修改插件的相关测试或操作冒烟；公共接口变更只补测实际调用者。完整全仓测试、所有浏览器场景、全平台安装包和性能压力测试都不作为每轮迭代要求。不为低影响、可逆的界面迁移新增大量镜像实现的测试。

明确延期：安全审计、供应链检查、新的细粒度权限系统、插件签名/沙箱、64 组合全量矩阵、完整异常注入、全量热卸载、事务化环境发布、全文件哈希和通用回滚平台。仅遇到实际阻碍时针对性处理，不预建这些系统。

## 10. 最终验收清单

- 只装母插件时，预设、项目、文件、记忆与插件环境管理完整可用。
- 六子插件分别有独立源码边界、测试、构建和发布产物；不依赖旧主包托底，也不依赖其他业务插件。
- 已交付装配配置中的工具、Skills、提示词、API 和页面与实际可用能力一致；任意组合可自由选择，通过注册机制保证一致性，不要求逐一枚举验证。
- 核磁和绘图能分别装配；RAG 与文献能分别装配；可选协作缺失有明确降级路径。
- 子插件业务存储只有一个所有者，跨插件协作使用公开协议，不共享可写私有表。
- 子插件缺失或停用不影响母插件与其他插件启动；出现实际环境冲突再隔离对应执行环境。
- 已有项目、研究文件、登录数据、对话绑定和历史任务快照保留且可验证。
- 项目申报不再可新建或执行，历史资料可读取；论文润色明确为占位状态。
- 所有公开应用名、窗口标题、安装包、快捷方式和网站可见应用标识均维持 iBM Lab 品牌规则。
