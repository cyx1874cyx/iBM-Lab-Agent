# 现有文献检索方法评估

> 评估对象：本插件当前的文献检索链路（`src/literature/search-engine.js`、
> `src/literature/data-sources.js`、`lib/tasks/literature.js`、`lib/literature-sources.js`）。
> 结论来自对现有代码与端点的逐项核对；带「未实测」标注的是静态判断。

## 1. 现状：检索链路做了什么

### 1.1 数据源

| 源 | 协议 | 覆盖 | 在链路里的角色 |
|---|---|---|---|
| OpenAlex | REST JSON | 全学科、含引用数/许可/OA 位置 | 主力源；`doi` 精确命中走它的单作品端点 |
| Crossref | REST JSON | 全学科元数据（出版社登记） | 补全期刊/卷期页；DOI 命中第二条路 |
| PubMed | E-utilities XML | 生物医学 | 生物医学覆盖；给 PMC 链接 |
| arXiv | Atom XML | 预印本（物理/CS/材料） | 预印本与绿色 OA 全文 |

另有**订阅/校内资源**目录（`data-sources.js`）：Scopus、Engineering Village、
SciFinder-n、Reaxys、IEEE Xplore、Nature 等，它们只做探测与「用你自己登录的浏览器
会话打开」，**不参与检索式检索**——本插件不代抓这些站的检索结果。

### 1.2 流程

```
query 解析（DOI / PMID / arXiv ID / 普通检索式）
  → 多源并行检索（每源 15s 超时）
  → canonicalizePaper 统一字段
  → deduplicatePapers 去重 + 打分排序
  → oaOnly 过滤（精确标识符查询不受 OA 过滤）
  → 落库 literature_search_runs（同一会话多轮合并成一条）
  → RIS 导出 / 摘要中文概括（Agent）/ 面板展示
```

### 1.3 去重与排序（实测代码）

- 去重键：DOI 归一化后优先；否则题名归一化（去标点、小写、压空白）＋年份/卷期页。
- 打分：`标识符精确命中 1000 + 题名完全等于检索式 500 + 题名覆盖率×200 +
  摘要覆盖率×60 + 源优先级分(0–20)`；`sort=cited_by_count` 或 `publication_date`
  时改用对应字段优先，再用 score 兜底。
- 源优先级固定写在各 adapter 里，不是自适应权重。

## 2. 评估

### 2.1 强项

1. **四源互补、无单点**：一个源失败只记 `sourceFailures` 并降级（全部失败才报错），
   面板会显示「N 个源降级」。这对校内不稳定网络是必要的。
2. **精确标识符分支**：给出 DOI/PMID/arXiv ID 时走单作品端点并置顶，**不受 OA 过滤**，
   避免了「用题名关键词搜出一堆噪声再人工挑」。
3. **同会话多轮合并**：同一会话反复检索累加进同一条目、同一个 RIS，
   符合「一次调研 = 一个条目」的直觉。
4. **OA 优先且可解释**：默认只回可获取全文的条目，并给出 `oaStatus`/`license`/`pdfUrl`，
   后续下载规则（`literature-sources`）据此分流。
5. **来源可追溯**：每条结果保留 `sources[]`、`provider`、`score`，登记产物带 provenance。

### 2.2 短板（按影响排序）

| # | 问题 | 影响 | 证据 |
|---|---|---|---|
| 1 | **没有中文库**（CNKI/万方/维普）与**引文索引库**（Web of Science/Scopus 的检索 API） | 中文文献、以及需要「被引/学科规范化」的选题调研覆盖不到；本组方向（聚前药/高分子）中文综述常有关键信息 | `DEFAULT_SOURCES` 只有 4 个开放源；订阅源只做打开，不检索 |
| 2 | **仅标题+摘要参与相关度**，不做全文检索 | 「某材料在某条件下怎么做」这类问题检索不到；摘要缺失的记录会被大幅降权 | `search-engine.js` 的 coverage 只算 title/abstract |
| 3 | **无查询扩展/同义词/词形归一** | `prodrug`/`pro-drug`、`聚前药`/`polymeric prodrug` 不能自动互搜；用户得自己写多个检索式 | 检索式原样拼进各源 URL；`normalizeTitle` 只用于比较，不用于扩展 |
| 4 | **无字段限定语法**（`AU=`、`TI=`、`PY>`、`SRC=`） | 无法表达「周绍兵 2020 年以后的 AFM 文章」这类精确需求；只能靠精确题名/DOI | 参数只有 `query/limit/sort/yearFrom/oaOnly` |
| 5 | **OA 过滤默认开**，且不做「有全文 vs 只有摘要」的分级 | 综述调研时会把大量非 OA 关键文献直接过滤掉（工具描述要求 Agent 提示，但默认值就偏窄） | `oaOnly = true` 默认；`searchLiterature` 直传 |
| 6 | **超时 15s、无重试/退避** | 校内网络抖动时整源失败（面板显示降级），但不自动重试 | `response()` 的 AbortController 15s；无 retry |
| 7 | **无速率限制与配额管理** | OpenAlex/Crossref 的 polite pool 需要 `mailto`，当前只有可选参数；高频批量检索有被封风险 | `options.mailto` 仅在传入时拼接 |
| 8 | **去重对预印本/正式版、勘误、会议扩展版无判别** | 同一工作可能出现两条（arXiv + 期刊），综述引用会重复 | 去重键只看 DOI/题名+年份 |
| 9 | **摘要概括依赖 Agent 逐条提炼**（`shortDescriptionZh` ≤9 字） | 条目多时是一轮不小的模型开销；未提炼时显示「摘要待提炼」 | `lab_tasks_update_search_summaries` + `get_search_summary_inputs` |
| 10 | **无引用网络**（谁引用了它 / 它引用了谁） | 无法做「从一篇种子文献向前向后滚雪球」，而这恰是综述调研的主力手法 | 结果里只有 `citations` 计数（OpenAlex），无 references/cited_by 列表 |
| 11 | **PDF 获取仍受出版社反爬与授权限制** | 检索能命中，但正文常需 WebVPN/iWAN 与人工确认（这是产品边界，不是缺陷） | `literature-sources` 的 WebVPN/iWAN 分流与用户确认门禁 |

### 2.3 与「综述写作」需求的匹配度

新上线的综述流程（`lab_tasks_get_review_inputs` 只允许引用本次检索到的条目）把
检索质量直接变成了综述质量的天花板：

- 短板 1/2/4/10 会让某些主题的**召回**明显不足；
- 短板 8/9 会让**引用列表**里出现重复条目或泛泛的「摘要待提炼」；
- 短板 6/7 让**大批量检索**（综述动辄 50–200 篇）在校园网下不稳定。

## 3. 改造建议（按性价比排序）

| 优先级 | 改造 | 预估 | 收益 |
|---|---|---|---|
| P0 | **批量检索的稳健性**：每源 2 次指数退避重试、把 `mailto` 设为课题级配置默认值、失败原因结构化回显 | 1–2 人日 | 综述级检索（100+ 篇）成功率显著提升 |
| P0 | **引用滚雪球**：OpenAlex 结果里取 `referenced_works` / `cited_by_api_url`，新增「以某篇为种子向前/向后扩」的检索模式 | 3–4 人日 | 综述调研的主力手法，直接补上短板 10 |
| P1 | **字段限定与查询构造器**：把 `yearFrom/author/journal/doiPrefix` 变成各源的字段化 URL，而不是拼接裸 query | 2–3 人日 | 精确调研不再依赖精确题名 |
| P1 | **预印本/正式版归并**：同题名+同作者集合的 arXiv 与期刊条目合并为一条，保留 `versions[]` | 2 人日 | 综述引用不重复 |
| P1 | **摘要概括批量化**：允许一次提交多条（当前已是批量），并把「未提炼」在导出 RIS 时降级标注 | 0.5 人日 | 减少综述里的空泛引用 |
| P2 | **OA 分级**：把 `oaOnly` 换成 `fullText: any\|oa\|pdf`，默认保留「有 DOI 但非 OA」的条目并标注 | 1 人日 | 综述召回不再被默认值砍掉 |
| P2 | **中文源接入**：CNKI/万方无公开 API，只能用用户浏览器会话做「人工检索 + 页面提取」，属受限能力 | 3–5 人日（且依赖授权） | 中文文献覆盖 |
| P3 | **全文检索**：见 `PROJECT_RAG_DATABASE_ASSESSMENT.md`——本课题已归档 PDF 的全文检索属于 RAG 的一部分，不要重复造 | — | — |

## 4. 结论

当前检索链路在**开放英文文献的选题调研**上是可用且稳健的（四源互补、标识符精确、
同会话合并、OA 可解释）；主要缺口集中在**中文/引文索引库、字段化查询、引用滚雪球**
三处，而这三处恰好是「写一篇能用的综述」最需要的。建议先做 P0 两项（稳健性 +
引用滚雪球），它们投入小、直接抬高综述质量上限。
