# iBM Lab 三栏工作台开发验证

双击仓库中的 `Start-iBM-Lab-Dev.cmd`，或运行 `npm run dev:workbench`。
这两种方式只编译客户端并启动已有 Electron 运行时，不创建压缩包或安装程序。

- 左侧：文献阅读、RAG 知识库、试剂管理/采购、项目申报、核磁解析、合成路线、论文润色。
- 中央：复用真实课题业务组件；宿主的资源标签、文件预览和浏览器也显示在中央。
- 右侧：复用宿主的真实会话组件、输入框、模型选择与任务执行。
- 顶部：课题入口、会话历史及设置；对话可收起，分隔条支持鼠标拖动与方向键调宽。
- 项目申报、论文润色提供本地自动保存草稿及向真实对话输入框传递任务。
- RAG、试剂管理入口标注“待接入”，没有模拟检索、库存或采购结果。

开发运行时与数据默认位于 `work/workbench-dev-20261021/`，不使用正式版数据目录。
第一次启动复制已有的已验证桌面运行时。只在开发副本的 ui-layout 加入 `lab.workbench` 布局插槽，原始布局作为回退；不重复声明宿主的子插槽。
此接入点由 `scripts/workbench-layout-adapter.mjs` 管理，宿主版本不匹配时停止并报错。
以后正式发布时也需要把此接入点应用到暂存运行时；仅替换客户端文件不足以启用新布局。

保存 `client/src/` 下的源码会触发客户端重新编译并刷新开发窗口。写作草稿自动保存到项目目录的 `草稿/`，浏览器保留本机恢复副本；模块选择仍保存在开发版的浏览器存储中。开发窗口刷新前仍需提交尚未保存的其他业务表单。项目文件格式和迁移方式见 [PROJECT_FILES.md](PROJECT_FILES.md)。
更改宿主、预设或后端代码后应重新启动开发版。当前自动刷新仅针对前端源码。

窗口大小验证使用 `node scripts/dev-workbench.mjs --verify-window-resize`，直接测试原生窗口的还原、最大化和全屏。不要在留给用户使用的窗口中用 Puppeteer `setViewport` 模拟尺寸；模拟尺寸可能在断开连接后仍然保留，导致窗口最大化而页面仍固定大小。

验证命令：

```powershell
node scripts/migration/verify-workbench.mjs --browser-url http://127.0.0.1:端口
node --test tests/browser/literature-view-state.test.mjs
node --test tests/unit/ui-redesign.test.mjs
```

Electron 调试端口记录在开发目录的 `electron.stderr.log` 中。验证只操作独立开发数据，创建“前端验证课题”，不提交模型请求、不使用真实科研或机构账号。
`verification/` 中保留界面截图与检查结果。模型生成质量、机构登录、真实实验数据分析仍需用户后续验收。

“精读文献”的“上传文献”和拖拽入口支持一次导入多份 PDF、DOCX（单文件最多 25 MB）。文件首先归档到当前工程，并创建灰色加载条目；最多两个独立后台阅读会话同时识别 MarkItDown 转换文本，完成后通过项目变更通知自动更新面板。模型沿用应用配置的默认模型，不切换右侧对话。面板仍显示期刊短引用和中文标题；五段命名规则仅用于归档目录及 PDF、后续精读报告/PPT 文件。失败保留原始文件和错误原因，可点击“重新识别”；重复内容复用原条目，切换到全部列表、滚动定位并短暂闪烁提示。扫描件未提取到文本时明确提示先 OCR。

`tests/integration/pdf-intake.test.mjs` 固定模型与转换边界，验证登记、去重、归档路径、失败重试以及面板标题和文件名分离；`tests/browser/literature-view-state.test.mjs` 覆盖按钮选择、拖拽和加载状态。2026-10-22 另在独立开发课题用实际 PDF 完成了 MarkItDown → 已配置模型 → 书目信息回填与文件归档的手工验证。

文献阅读两列的拖拽范围包含条目下方直到窗口底部的空白：检索记录列批量导入 RIS，精读文献列导入 PDF、DOCX。拖入科研助手整栏则通过宿主附件服务加入当前输入框，保留草稿，不发送消息。工作台在事件边界隔离三种接收方式，避免宿主的全局拖拽监听重复接收文献文件。

正文与 SI 统一通过“上传文献”或精读文献整列拖拽进入同一个后台阅读流程，不提供单独的 SI 上传入口。助手读取 MarkItDown 文本后判断材料类型，文件名和拖到哪条文献上均不决定归属；按 DOI 或足够长的完整题名唯一匹配已有论文。PDF 正文和 PDF/DOCX SI 均保留原始格式。先上传 SI 时保留已有书目信息和原始文件，不显示常驻归档提示；标题缺失不阻断 SI 归档，后补正文会合并；自动归档新版本 SI 时保留旧文件备份。旧版可能错存的附件重新进入内容识别流程后校正，保留原始字节。

缺少 DOI/完整题名的 SI 会对照本课题正文内容识别归属。模型需给出至少两组独立的 SI/正文原文引文，具有相同的具体统计数值；服务端校验引文确实存在、数值对应且候选唯一，候选书目信息不能冒充 SI 自带标识。正文候选变化时重新核对尚未关联的 SI；候选未变则不重复调用模型。

发表来源缺失的正文会先核对项目已有题录，再按准确题名/DOI 查询 Crossref 和 PubMed；题名、已有作者、年份、页码以及 DOI 约束通过且候选 DOI 唯一时补齐来源并保存核验来源记录。无法核验则保留未知，不把页码与年份作为条目标题。会议论文允许没有卷号，界面显示会议简称、页码与年份；旧的残缺引用从结构化元数据或实际论文标题回退。

上传内容先区分论文正文、论文补充材料和明确的非论文文件。非论文须有内容依据和简短说明，不因缺少期刊/DOI 或检索无结果而拒绝；预印本、会议论文、学位论文与 SI 仍可登记。非论文的临时精读条目移除，前端闪烁提示持续 3 秒后自动消失；重复上传再次提示。原始文件及拒绝原因保留在工程中以便恢复，重启不会重建精读条目，也不作为 SI 关联候选。已有精读产物或正文/SI 的条目不因重判而删除。

精读条目支持拖动上下排序；普通点击选择一条，Shift 点击按当前列表连续多选，Ctrl/Cmd 点击可增减选择。选中条目使用与主体一致的主题绿色底与边框，与白灰交替底色区分，不显示额外的选择提示栏。条目内不显示分类下拉框，删除操作移入右键菜单：右键选中组可批量删除，右键未选中条目仅操作该条，保留删除确认；Escape 可清除选择；可拖动整组选中条目排序或移入顶部分类文件夹，拖到未分类则移出分类。顶部文件夹栏随列表滚动保持可见；拖动靠近滚动区域边缘会滚动。排序保存在工程 readingOrder 字段中，重开工程后保留，新上传条目显示在已有顺序前。拖动不移动原始文件或精读产物路径。内部条目拖放与外部 PDF/DOCX 文件上传分别处理，识别中的条目暂不允许移动。

精读条目中的正文、SI、简介、翻译、精读和 PPT 均使用 32×30 的图标按钮，优先排列在一行，窄容器下可换行。悬停说明与无障碍名称保留原操作含义，已完成产物沿用主题绿填充，加载时显示转圈并保留禁用逻辑。
