# Electron NEXT 迁移：P2 执行报告

执行日期：2026-10-03。状态：**P2 core、契约、仓储与兼容入口 PASS**。

## 结果

core 已成为历史 `lab_tasks` 的唯一所有者。课题、核心记忆、工作区/会话绑定可以在没有文献、设计、分析、模板和科研运行时的情况下独立运行。历史 `labTasks` 导出/方法集合、157 个 Remote 标记和原单 request 调用约定保留，完整科研组合继续工作。

固定输入仍为 iBM Lab Agent **0.5.8-rc.1**、DSH NEXT **v2.0.17-next** 与内核 **0.2.0-rc.2**。NEXT 和内核源码未改动，原工作区未改动。实施位于 `codex/electron-next-migration` 分支的独立迁移工作区，承接 P1 检查点 `52d1684`。

## 实施内容

- 增加 `lib/core`、`src/contracts`、`lib/repositories` 及包子入口。契约保持纯数据逻辑；core 仅必需注入存储域。
- 把课题 CRUD、记忆版本、绑定迁移与公共溯源/审核凭据校验交给 core；旧 tasks 通过仓储和方法委派保持原调用面。
- 沿用历史域名、8 张表、schema version 0、ID、路径和快照；core 课题的目标/模板引用改为可选，旧创建模型仍严格必填。不执行物理数据库迁移。
- Remote 必需依赖收敛到 core；基础课题接口直接路由 core，缺失领域服务返回 `feature-unavailable`。科研目标/模板的旧创建路径继续走兼容入口。
- 仓储包装按域提供视图，历史视图只有读操作；core 卸载使旧包装失效。删除课题继续校验配置根目录，拒绝越界路径。
- 修复旧单会话绑定在 schema 默认补空数组后无法显式迁移的情况，合并绑定并保留已有信息。
- 扩展真实 NEXT 原型脚本的 `--exercise-core` 模式：完整组合 → 仅 core + Remote → 恢复完整组合，全部使用独立 home。

详细配置归属、仓储表、兼容委派及后续边界见 [P2_CONTRACTS.md](P2_CONTRACTS.md)。

## 本阶段边界

P2 建立了代码/数据所有权和可选业务路由，仍以一个根包安装；尚未完成五个领域/运行时的独立插件拆分。组合课题页面仍需要相应业务服务，可选 UI 属于 P5。core-only 的基础 API 验收不代表科研预设在业务缺席时可用。

新增无目标/模板引用的基础课题仅由新 core 模型读取；原 0.5.8 的严格模型不能直接读取这种新行。正式迁移/回滚必须隔离新旧数据目录，保留原副本；本次试验数据已使用独立目录。

正式 Electron 窗口、机构授权捕获、Origin/Mnova 自动化、离线安装/更新和真实 0.5.8 用户数据对账，仍在 P4–P6 验收。本次只使用新 home 和临时数据，没有导入、修改或删除用户历史业务数据。

**下一阶段：P3**，拆出 documents、literature、design、analysis 和 runtime，落实领域仓储与跨域通知。
