# P4 运行时与桌面边界

`ibmRuntime` 持有受管 Python、执行器、任务取消信号、异步工作和资源关闭回调。停用先拒绝新任务、取消执行和关闭桌面资源，再清理受管子进程并等待已登记工作。Windows Job Object 只管理自身启动的进程树，不能关闭用户已有软件。

`ibmScientificDesktop` 是 core/runtime 上的独立 provider。未配置固定 Electron 时报告不可用，不在 Host 启动时打开窗口。课题租约绑定科研窗口及其弹窗、隔离持久分区和捕获任务。页面没有 preload、Node、Host 凭据或桌面通用调用入口。

桌面与 Host 通过带随机认证值的本机命名管道通信，认证值只由私有启动配置传递。科研网页仅使用普通 HTTPS 和下载能力。目的地校验拒绝 Host、本机/私网地址和文件协议；本机测试来源必须显式列入夹具白名单。

PDF/SI 捕获复用 `labCapture` 的一次性令牌及 `core` 的归档/哈希契约。明文令牌只存在于 Host 端；Electron 仅收到任务 ID 和类型。下载以不透明文件 ID 暂存，Host 消费后删除临时文件，验证内容后交给 core 归档。窗口释放取消待捕获任务，切换任务作废该窗口上一任务。原始资料替换继续遵守已有批准和哈希边界。

页面链接检查使用固定脚本，仅提取公共锚点文字与 URL，不读取表单值、Cookie 或存储。每个页面检查限时 2 秒，优先列出 PDF/SI 链接；对外 URL 不包含查询参数和片段。此检查还不能操作 WebVPN 动态资源按钮，不能据此声称完整浏览器自动化已实现。

下载完成后只自动关闭属于当前租约、URL 仍为空或 `about:blank` 的下载弹窗。正常机构和文章弹窗保留。已加载的 PDF 预览不能靠这一条件推导为可关闭，预览能力另行验收。

原生软件 MCP 配置只能从固定应用注册表选择 Origin/MestReNova。解释器和工作目录必须为绝对路径，模块及启动参数由 Host 决定；不接收客户端任意命令。官方 rc.2 MCP client 管理 stdio，会话取消/退出由受管守护进程负责。工具注册不等于 GUI 软件执行成功。

MestReNova 原生调用限时 90 秒，早于 Host 工具调用的 120 秒期限。运行期桥接文件和输出根从工作区派生，不把验收请求写到猜测的全局目录。Origin 的用户 GUI 属于借用资源；创建样例使用唯一工作簿名，只删除自己创建的工作簿。

原生 PDF 预览和系统打开仅接收 Host 暂存的不透明文件 ID，并校验 PDF 签名；不接收网页指定的本机路径。预览采用独立非持久分区和沙箱，拒绝网络请求与新窗口。系统打开在本插件 root 内导出 PDF 副本后调用默认 PDF 应用；副本是持久输出，不属于退出时删除的临时下载。保存对话框的选择由用户决定，回传读回后的大小和哈希，不回传用户选中的完整路径。

旧 DPAPI 导入是安装配置路径，未暴露为 Remote 或 Agent 工具。合成凭据测试只证明同一 Windows 用户下保护/解保护及 Electron 系统加密重新封装；真实用户 Key 和机构认证不因该测试被读取或迁移。机构会话重启后可能需要用户重新登录。

本轮 provider 仍从 iBM 根包子入口加载；独立发布包、预设和 UI 能力组合属于 P5。运行时资源、GUI 软件和插件包版本分别报告；不能用一个 Python 环境可用状态代替桌面能力判断。
