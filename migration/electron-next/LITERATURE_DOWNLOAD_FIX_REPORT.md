# 文献下载浏览器修复（2026-10-05）

## 根因与结果

1. 课题资料页的 Electron「获取正文/SI」仅创建捕获任务，没有导航到该任务的论文。现在先布防，再打开对应出版社页面；同课题复用已有科研窗口与机构会话。
2. Agent 下载仍依赖 Tauri iframe 的课题标识轮询。Electron 页面不会启动该轮询，旧 WebVPN 心跳预检也阻止任务创建。现在科研桌面服务直接接管 Agent 队列，短期令牌保留在 Host，不经过模型或页面。
3. 打包后的 Electron 忽略作为参数传入的脚本文件，会再次启动主程序。新增 `--ibm-scientific-desktop` 专用入口，在初始化主 Profile 之前加载固定的科研浏览器模块。
4. Chromium 将附件下载作为失败的页面加载报告。只在本窗口实际收到下载事件时接受 ERR_ABORTED / ERR_FAILED，避免把已启动的正常 PDF 下载取消。

## 下载与归档

科研浏览器提供真实页面观察、短期元素引用点击、PDF 查看器下载与调试状态。旧观察在导航后失效，不能用来点击新页面。同课题多个 Agent 请求排队，取消排队任务不覆盖当前任务；归档完成后推进下一任务。

下载仍沿用文件种类、大小、PDF 头尾、SHA-256 与课题归属检查。未经过完整性验证的响应不会作为成功文件登记。机构登录和验证码仍由用户完成，打开论文页面不表示获得访问权限。

原有 Web/Tauri 路径保留，Electron 不再需要旧侧栏桥或人工启动 Edge 才能接管已登记文献下载。

## 验证与范围

完整自动检查：807 项，799 通过、8 跳过、0 失败。

实际 Electron 本地出版社样例验证：手动获取自动导航；Agent 请求不依赖 iframe/旧登录心跳；同课题排队和取消；观察/点击新窗口下载；文件校验和课题归档；直接 PDF 下载；旧观察引用拒绝。安装版另外验证专用科研浏览器入口不初始化主 Profile。

只对合成页面和合成 PDF 做下载验收，不能据此声称某篇真实付费文献、机构登录或人机验证已经成功。本次没有读取真实机构 Cookie 或模型密钥。

首次安装版验证旧错误入口时曾误启动主程序，触发安装器管理的插件文件刷新。课题、数据库与认证文件未被覆盖，旧插件已由刷新流程备份。后续安装版测试显式指定独立数据目录，并检查主 Profile 初始化标记不存在。
